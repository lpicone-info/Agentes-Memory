### [16/09/2026 20:14:53] Agente

Diego, lo más probable es que el problema esté en el destino, no en `lds_aux`.

En `uo_nv_factu_v3`, `lds_aux` es un `ds_clase`/DataStore con 1 fila, pero `adw_impre` es un parámetro `DATAWINDOW` que viene creado dinámicamente desde la ventana. Aunque tenga `DataObject` asignado, ese `DATAWINDOW` no es un control visual real agregado a una ventana. Para copiar buffers e imprimir, puede comportarse distinto o quedar sin buffer efectivo. Por eso el `RowsCopy` puede no copiar aunque `lds_aux.RowCount()` dé 1.

El indicio fuerte es que en el mismo archivo la copia a `lds_pdf_compro` sí es más confiable:

```powerscript
lds_pdf_compro = CREATE ds_clase
lds_pdf_compro.DataObject = ds_impre.DataObject
lds_pdf_compro.SetTransObject(SQLCA)
ds_impre.RowsCopy(ll_row, ll_row, Primary!, lds_pdf_compro, 1, Primary!)
```

Ahí el destino es otro DataStore, no un `DATAWINDOW` visual creado al vuelo.

Para este caso conviene reemplazar el uso de `adw_impre` en esa rama por un `ds_clase` local, por ejemplo:

```powerscript
lds_pdf_compro = CREATE ds_clase
lds_pdf_compro.DataObject = lds_aux.DataObject
lds_pdf_compro.SetTransObject(SQLCA)

lds_aux.RowsCopy(ll_row, ll_row, Primary!, lds_pdf_compro, 1, Primary!)

lds_pdf_compro.Modify("Datawindow.Printer='Bullzip PDF Printer'")
lds_pdf_compro.Modify("DataWindow.Print.DocumentName='" + ls_file + "'")
lds_pdf_compro.Print()

DESTROY lds_pdf_compro
```

Además agregaría control del retorno:

```powerscript
ll_cop = lds_aux.RowsCopy(...)
IF ll_cop <= 0 OR lds_pdf_compro.RowCount() = 0 THEN
   MessageBox(ls_Title, "No se pudo copiar el registro para generar el PDF")
   RETURN FALSE
END IF
```

Resumen: `RowsCopy` no falla porque `lds_aux` no tenga registros; falla porque el destino `adw_impre` no es buen candidato para operar como buffer temporal. Usaría `ds_clase` local para generar el PDF.
