### [05/11/2026 14:31:33] Agente

Emanuel, el cambio de `TINYINT` a `INT` es una **ampliación de tipo**: los valores actuales se conservan sin conversión destructiva. El riesgo sobre los datos es bajo, pero existen riesgos operativos y de compatibilidad.

## Riesgos principales

1. **Reconstrucción de la clave primaria**
   - `codigo` forma parte de `pk_aporte_indices3 (codigo, cuenta)`.
   - Para alterar la columna hay que retirar y recrear la PK.
   - Esto puede bloquear temporalmente la tabla.

2. **Despliegue incompleto**
   - Si se cambia solamente la tabla, los SP con parámetros `TINYINT` seguirán rechazando códigos mayores a 255.
   - Tabla, SP y catálogo deben desplegarse coordinadamente.

3. **Consumidores externos**
   - En `prevencion_entrega` no encontramos claves foráneas hacia `aporte_indices`, pero pueden existir procesos externos que supongan un código de un byte.
   - También existen `aporte_indices_emp` y `tmp_aporte_indices` con `codigo TINYINT`. No deben modificarse automáticamente, pero hay que comprobar que no intercambien este código con `aporte_indices`.

4. **Rollback limitado**
   - Mientras todos los códigos sean menores o iguales a 255, se puede volver a `TINYINT`.
   - Después de guardar el código 256 o superior, el rollback requeriría eliminar o transformar esos registros.

5. **Concurrencia**
   - El algoritmo `MAX(codigo) + 1` puede generar el mismo código ante dos altas simultáneas.
   - Cambiar a `INT` no agrega este problema, pero tampoco lo resuelve.

6. **Bloqueos y log**
   - `ALTER COLUMN` y la reconstrucción de la PK pueden generar bloqueo y uso del log.
   - Actualmente la tabla es pequeña, por lo que en `prevencion_entrega` el impacto debería ser reducido.

## Cambio controlado de la tabla

Para la estructura actualmente verificada, la migración sería conceptualmente:

```sql
SET XACT_ABORT ON
GO

BEGIN TRY
    BEGIN TRANSACTION

    ALTER TABLE dbo.aporte_indices
    DROP CONSTRAINT pk_aporte_indices3

    ALTER TABLE dbo.aporte_indices
    ALTER COLUMN codigo INT NOT NULL

    ALTER TABLE dbo.aporte_indices
    ADD CONSTRAINT pk_aporte_indices3
        PRIMARY KEY CLUSTERED (codigo, cuenta)

    COMMIT TRANSACTION
END TRY
BEGIN CATCH
    IF XACT_STATE() <> 0
        ROLLBACK TRANSACTION

    DECLARE @mensaje NVARCHAR(4000)

    SET @mensaje = ERROR_MESSAGE()

    RAISERROR(@mensaje, 16, 1)
END CATCH
GO
```

Antes de aplicarlo se debe confirmar en el ambiente destino que la PK instalada sea efectivamente `pk_aporte_indices3` y conservar sus propiedades reales —por ejemplo, si es `CLUSTERED`—.
