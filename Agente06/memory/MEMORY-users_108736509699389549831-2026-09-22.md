## 2. Significado funcional de cada valor

### `apo_ni_fac = 'N'`

Significa:

> El aporte no fue marcado durante la importación para el circuito especial de generación de NI por condiciones de baja, cambio de plan u origen.

No significa:

- que el aporte nunca pueda generar una NI;
- que obligatoriamente deba quedar dentro de una FC;
- que el aporte no pueda generar un AP;
- que el aporte deba quedar consumible.

Los circuitos normales utilizan:

```sql
ISNULL(apo_ni_fac, 'N') = 'N'
```

Esto permite que el aporte:

1. sea tomado durante la generación de la FC;
2. quede facturable si no se consume en esa etapa;
3. sea tomado posteriormente por `afi_aju_inter_aporte_real`;
4. genere un AP y luego una NI separada.

Esto es exactamente lo ocurrido en R30417.

### `apo_ni_fac = 'S'`

Significa:

> El aporte fue marcado durante la importación para ser procesado por el circuito especial de NI.

Las condiciones que pueden producir `S` son:

- afiliado dado de baja;
- plan vigente configurado con `verif_impor_apo = 'S'`;
- origen vigente configurado con `verif_impor_apo = 'S'`.

El código asigna además un motivo:

| `motivo_ni` | Condición |
|---:|---|
| `1` | Afiliado dado de baja |
| `2` | Cambio de plan |
| `3` | Cambio de origen |

### 1. Desde dónde parte la facturación individual

La facturación individual no toma directamente todos los subsidios o descuentos históricos.

La cadena es:

```text

    → afi_generar_prefacturas
        → cálculo de períodos a prefacturar
            → afi_generar_prefactura_xafi
                → cálculo de subsidios/descuentos
                    → generación de FC o NC
```

`afi_generar_compro_individual` invoca `afi_generar_prefacturas` con el período que está facturando:

[afi_generar_compro_individual.sql:349](/home/desarrollo-ia-06/.openclaw/workspace/svn/ogomez-Prevencion-trunk/backend/procedures/afi_generar_compro_individual.sql:349)

La cantidad de meses hacia atrás se obtiene del modo de emisión:

```sql

@apli_max     = @factu_perio2
```

[afi_generar_prefacturas.sql:361](/home/desarrollo-ia-06/.openclaw/workspace/svn/ogomez-Prevencion-trunk/backend/procedures/afi_generar_prefacturas.sql:361)

Para los tres contratos analizados, el modo de emisión tiene `emi_meses = 1`. Por lo tanto, si la facturación se ejecuta para septiembre de 2026, el período máximo de aplicación es agosto de 2026.

La facturación individual **sí puede recorrer períodos anteriores**, pero no porque siempre lo haga ni porque exista cualquier descuento.
