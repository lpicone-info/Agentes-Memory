## Diagnóstico

El error se produce **durante el handshake TLS**, después de que Gmail respondió correctamente a `STARTTLS` con `220`. Por lo tanto:

- No es un problema de usuario, contraseña ni `AUTH LOGIN`.
- No es un bloqueo general del puerto 587.
- `-41` en cryptlib significa `CRYPT_ERROR_READ`; `WSAECONNABORTED` es el error Winsock subyacente: el servidor cerró la conexión durante el handshake.
- Las constantes informadas son **correctas para cryptlib 3.4.5**.
- En cryptlib 3.4.5, `CRYPT_SESSINFO_SERVER_NAME` y `CRYPT_SESSINFO_NETWORKSOCKET` son mutuamente excluyentes. No se debe intentar agregar `SERVER_NAME` al flujo STARTTLS.
- Gmail actualmente acepta STARTTLS aun sin SNI; lo verifiqué contra `smtp.gmail.com:587`. Por eso SNI no explica por sí solo el fallo.

La diferencia determinante es:

- Puerto 465: cryptlib crea y administra la conexión.
- Puerto 587: PowerBuilder crea el socket, negocia SMTP y luego entrega ese socket abierto a cryptlib.

El problema está concentrado en esa transferencia del socket o en la compatibilidad del handshake generado por cryptlib 3.4.5 usando un socket externo.

                CRYPT_OPTION_NET_READTIMEOUT, 60)

                CRYPT_OPTION_NET_WRITETIMEOUT, 60)
If ll_RetVal <> CRYPT_OK Then Return False

// Entregar el socket conectado
ll_RetVal = cryptSetAttribute(il_Session, &
                CRYPT_SESSINFO_NETWORKSOCKET, iul_socket)
If ll_RetVal <> CRYPT_OK Then Return False

Después de activar, debe eliminarse este bloque:

```powerscript

```

Gmail no envía una nueva bienvenida SMTP después del handshake. El cliente debe enviar directamente un nuevo `EHLO` cifrado.

## Corrección obligatoria adicional

La declaración actual de `cryptGetAttributeString` tiene un error:

```powerscript
Ref integer StrLen
```

Debe ser:

```powerscript
Ref long StrLen
```

Y la variable correspondiente:

```powerscript
Long ll_StrLen
```

La API de cryptlib espera un puntero a entero de 32 bits. El `Integer` de PowerBuilder es de 16 bits y puede corromper memoria precisamente cuando se intenta recuperar el detalle del error.

## Conclusión

Primero aplicaría, en este orden:

1. Corregir `StrLen` a `Long`.
2. Forzar el socket a modo bloqueante.
3. Configurar timeouts antes de `ACTIVE`.
4. Forzar TLS 1.2 con `CRYPT_SESSINFO_VERSION = 3`.
5. Eliminar el `cryptPopData` posterior al handshake.
6. Registrar inmediatamente `CRYPT_ATTRIBUTE_ERRORMESSAGE` si falla `ACTIVE`.

Si todavía devuelve `CRYPT_ERROR_READ / WSAECONNABORTED`, quedaría confirmada una incompatibilidad de **cryptlib 3.4.5 con Gmail en su modalidad STARTTLS sobre socket externo**. En ese escenario, la solución segura es mantener temporalmente el puerto 465 o actualizar cryptlib a una versión posterior con sus bindings correspondientes; no recomiendo volver a 3.3.3.
