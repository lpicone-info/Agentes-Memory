Pablo, el RM30162 amplía la integración entre Presmed y Alephoo para informar la baja de autorizaciones con copago pagado por adelantado.

Resumen funcional

* Actualmente Presmed informa a Alephoo las autorizaciones cerradas, aceptadas y con copago adelantado.
* El problema es que, si posteriormente se da de baja una autorización ya informada, Alephoo no recibe esa cancelación.
* El requerimiento incorpora el envío de la baja mediante una API HTTPS con método POST.
* La comunicación debe ejecutarse después de completar correctamente la baja local.
* Un error de Alephoo nunca debe revertir la baja realizada en Presmed.

Condición principal

* Solo debe intentarse informar la baja cuando `autorizaciones.alephoo_expor_fecha` tenga valor, indicando que la autorización fue enviada previamente.
* La URL se obtiene del parámetro `alephoo_cemap_url_envio_autorizacion_baja`.
* Si la URL está vacía, se conserva la baja local y se informa al usuario que falta configurar el parámetro.

Información enviada

* Identificador: `autorizacion`.
* Número: número de autorización.
* Estado: `5`, correspondiente a anulada.
* Autenticación: Basic Auth.
* Comunicación: HTTPS POST.

Resultado de la comunicación

* HTTP 200: se considera exitoso y se completa `autorizaciones.alephoo_baja_informada`.
* Error HTTP o timeout: la baja local permanece aplicada, `alephoo_baja_informada` queda nulo y se muestra el detalle del error.

Trazabilidad

* Cada intento debe registrarse en `auto_alephoo_log`.
* Se guarda autorización, sucursal, usuario, evento, fecha, URL, método, request, respuesta y mensaje.
* Evento de baja: `Autorización dada de baja`.
* Evento del envío preexistente: `Autorización cerrada con copago adelantado`.

Reintentos

* Se reutiliza el botón existente de reenvío.
* Para una autorización activa, conserva el circuito de reenvío del cierre.
* Para una autorización dada de baja, permite reintentar la notificación de cancelación.
* Cancelar la confirmación no debe ejecutar la API ni modificar datos.

Alcance

* Prestaciones.
* Materiales.
* Traslados.
* Cirugías.
* Odontología.
* Autorizaciones vinculadas con CEMAP y copagos pagados por adelantado.

En síntesis: el requerimiento asegura que Alephoo refleje la cancelación de una autorización previamente enviada, con trazabilidad completa, manejo de errores y posibilidad de reintento, sin comprometer la baja local en Presmed.

### [20/11/2026 16:47:07] Agente

Pablo, el RM29025 incorpora una integración entre Presmed y Alephoo para informar automáticamente las autorizaciones cerradas que tienen copagos de pago adelantado.

## De qué se trata

Alephoo se utiliza en los CEMAP de Ospecon como sistema de caja. Cuando un afiliado recibe una autorización para atenderse con un prestador externo, Alephoo necesita conocer:

* La autorización cerrada.
* El afiliado relacionado.
* La institución o sucursal de origen.
* El importe exacto que debe cobrarle al afiliado.
* Las prestaciones comprendidas mediante un código genérico.

Antes de esta funcionalidad, Presmed no tenía comunicación con Alephoo para este circuito.

## Qué permite hacer la nueva funcionalidad

* Detectar automáticamente cuándo una autorización cerrada corresponde al circuito de cobro de Alephoo.
* Enviar mediante HTTPS la autorización a la API REST de Alephoo.
* Informar el importe exacto del copago que debe cobrarse.
* Crear en Alephoo un bono asociado al número de autorización de Presmed.
* Mostrar al usuario el resultado del envío.
* Registrar en Presmed que la autorización ya fue informada.
* Evitar que una misma autorización sea enviada nuevamente.
* Habilitar a Alephoo para realizar el cobro en caja del CEMAP.

## Autorizaciones alcanzadas

El circuito contempla:

* Prestaciones.
* Cirugías.
* Odontología.
* Materiales.
* Traslados.

La autorización debe:

* Haber sido creada en Presmed.
* Estar aceptada.
* Tener fecha de cierre.
* No haber sido informada anteriormente.
* Tener al menos un copago de modalidad `Paga por adelantado`.
* Tener como efector un prestador externo al círculo CEMAP correspondiente.

## Funcionamiento

Cuando el usuario cierra una autorización aceptada:

1. Presmed evalúa todas las condiciones.
2. Calcula la suma de los copagos adelantados de la orden y de sus prestaciones.
3. Construye el JSON con:
   * Fecha de cierre.
   * Número de autorización.
   * Código de la sucursal.
   * Documento del afiliado.
   * Código genérico de prestación.
   * Cantidad.
   * Importe total.
4. Ejecuta un `POST` al endpoint de Alephoo.
5. Alephoo crea el bono y devuelve su número e identificador.
6. Si responde HTTP `201`, Presmed considera exitoso el envío.
7. Presmed completa `AUTORIZACIONES.alephoo_expor_fecha`.
8. Se muestra al usuario el resultado del proceso.

## Control de duplicados

* El envío se realiza una sola vez, durante el cierre.
* `alephoo_expor_fecha` identifica que la autorización ya fue exportada.
* Si posteriormente se habilita la edición de autorizaciones cerradas y se cambia su estado, Presmed no vuelve a informar automáticamente esa modificación a Alephoo.

## Manejo de errores

La funcionalidad distingue respuestas como:

* `201`: autorización enviada correctamente.
* `400`: datos o JSON inválidos.
* `401`: credenciales incorrectas.
* `403`: usuario sin permisos.
* `404`: servicio no encontrado.
* Otros errores: falla general de comunicación.

Cada resultado genera un mensaje específico en Presmed.

## Resultado funcional

La incorporación del RM29025 permite que el proceso de autorización médica y el cobro en los CEMAP queden integrados: Presmed determina qué debe cobrarse y Alephoo recibe automáticamente la información necesaria para generar el bono y efectuar el cobro al afiliado.
