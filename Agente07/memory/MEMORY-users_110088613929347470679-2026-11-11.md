## Liquidación de órdenes

`prs_orden_a_liquidar` envía a la validación:

- Oficina.
- Expediente.
- Ítem.
- Orden.
- Cantidad que se está liquidando.

`prs_topes_acumulados` contabiliza una orden cuando:

```sql
EXPE_ORDEN_ITEMS.ok = 'S'
```

o cuando tiene un error validado que no debitó completamente la prestación:

```sql
EXPE_ERRORES.vali = 'S'
```

También exige:

```sql
EXPE_ORDENES.auto IS NULL
EXPE_ORDENES.baja_fecha IS NULL
EXPE_ORDEN_ITEMS.baja_fecha IS NULL
EXPE_ERRORES.baja_fecha IS NULL
```

La fecha evaluada es:

```sql
EXPE_ORDENES.rea_fecha
```

y debe encontrarse dentro del período correspondiente al tope.

Se consideran:

- Órdenes de otros expedientes que ya estén liquidados: `EXPEDIENTES.liqui_fecha IS NOT NULL`.
- Otras órdenes del mismo expediente que se está cargando, aunque todavía no esté liquidado.
- Se excluye exactamente la orden que se está validando para no duplicar su cantidad.

## Liquidación de honorarios

`pru_expe_honorarios_cober` valida cada registro de `EXPE_HONORARIOS` y envía una cantidad fija de **1** a `prs_valida_of_cobertura`.

Los consumos históricos se recuperan cuando:

```sql
EXPE_HONORARIOS.auto IS NULL
EXPE_HONORARIOS.baja_fecha IS NULL
EXPEDIENTES.liqui_fecha IS NOT NULL
```

Además:

- `EXPE_HONORARIOS.fecha` debe estar dentro del período.
- Deben coincidir prepaga y contrato.
- Para sumar el consumo deben coincidir `EXPE_HONORARIOS.nomen` y `EXPE_HONORARIOS.prestac` con la prestación evaluada.

El expediente actual todavía no se encuentra liquidado, por lo que no ingresa en el consumo histórico.

## Prevención de duplicados

Las órdenes y honorarios no vuelven a contabilizarse como consumo normal cuando existe un registro vigente por toda la cantidad en:

```sql
EXPE_COPAGOS_TOPES
```

La relación se realiza por oficina, expediente e ítem; para órdenes también por número de orden.

## Resultado del control

El proceso acumula:

- Autorizaciones.
- Reintegros.
- Transacciones remotas.
- Órdenes liquidadas.
- Honorarios liquidados.
- Ítems anteriores de la carga actual.

Luego valida:

```text
consumo acumulado + cantidad solicitada > cantidad permitida
```
