## Descripción funcional actual — Facturación Masiva

El proceso de **Facturación Masiva**, disponible en **Facturación → Procesos Masivos → Facturación**, genera los comprobantes correspondientes a una entidad, grupo de emisión y período de facturación previamente prefacturado.

Al ingresar a la pantalla, el sistema determina automáticamente el próximo período a facturar a partir de la información registrada en `PERIODOS`. El período se presenta protegido y no puede ser modificado manualmente. El usuario selecciona el punto de venta, el punto de venta electrónico cuando corresponde y, opcionalmente, un grupo de emisión específico.

Antes de generar los comprobantes, el sistema valida, entre otras condiciones, que el período corresponda a la entidad y al grupo seleccionado, y que exista una prefacturación para dicho período. Confirmada la ejecución, procesa las prefacturas y los ajustes pendientes, determina el tipo y numeración de cada comprobante y registra el resultado en `COMPROBANTES`.

## Determinación de la fecha de emisión

Actualmente, la fecha de emisión inicial de los comprobantes generados por Facturación Masiva se determina de la siguiente manera:

1. El sistema obtiene la fecha corriente del servidor de base de datos mediante `GETDATE()`.
2. Elimina el componente horario, conservando únicamente la fecha calendario.
3. Esa fecha se transmite al circuito de facturación y se asigna inicialmente a todos los comprobantes del proceso.
4. Una vez determinados el tipo, letra y punto de venta de cada comprobante, el sistema controla la fecha máxima ya utilizada para la misma combinación de:
   - Ente.
   - Tipo de comprobante.

## ¿Qué significa “misma combinación”?

El sistema separa las secuencias considerando:

- **Ente:** organización que emite el comprobante.
- **Tipo:** por ejemplo `FC`, `NC` o `ND`.
- **Letra:** por ejemplo `A`, `B` o `C`.
- **Punto de venta:** por ejemplo `0011`.

Por lo tanto, estas son secuencias diferentes:

- FC A, punto `0011`.
- FC B, punto `0011`.
- NC A, punto `0011`.
- FC A, punto `0001`.

La fecha de una secuencia no modifica la de otra.

## ¿Qué hace concretamente el sistema?

Supongamos que la Facturación Masiva se ejecuta el **26/11/2026**.

La fecha inicialmente calculada es:

```text
26/11/2026
```

El sistema va a generar una factura con esta identificación:

```text
Ente 1
Tipo FC
Letra A
Punto de venta 0011
Número 00000025
```

Antes de grabarla, busca en `COMPROBANTES` todos los registros existentes que pertenezcan a:

```text
Ente 1 + FC + A + punto 0011
```

Luego obtiene la fecha máxima de esos comprobantes.

### Caso 1: no existe una fecha posterior

El último comprobante existente es:

```text
FC A 0011-00000024
Fecha: 25/11/2026
```

Como `25/11/2026` no es posterior a la fecha inicialmente calculada, el nuevo comprobante conserva:

```text
FC A 0011-00000025
Fecha: 26/11/2026
```

### Caso 2: existe un comprobante con fecha posterior

El último comprobante existente es:

```text
FC A 0011-00000024
Fecha: 30/11/2026
```

Aunque la facturación se ejecute el `26/11/2026`, el nuevo número `00000025` no queda con una fecha menor que el número anterior. El sistema reemplaza la fecha inicial y genera:

```text
FC A 0011-00000025
Fecha: 30/11/2026
```

## Regla aplicada

En términos simples:

```text
Fecha final =
la mayor entre:

- la fecha actual del servidor;
- la máxima fecha existente para el mismo ente, tipo, letra y punto.
```

El control **no compara el período facturado**. Compara exclusivamente la fecha de emisión registrada en `COMPROBANTES`.

Además, la búsqueda implementada no filtra por estado ni por baja: considera los registros existentes en `COMPROBANTES` que coincidan con esa combinación.

## Redacción funcional sugerida

> Antes de registrar cada comprobante, el sistema consulta la máxima fecha de emisión utilizada para el mismo ente, tipo de comprobante, letra y punto de venta. Si dicha fecha es posterior a la fecha corriente del servidor, asigna al nuevo comprobante esa máxima fecha existente. En caso contrario, conserva la fecha corriente. De esta manera, los números nuevos de una misma secuencia no se registran con una fecha anterior a la ya utilizada en esa secuencia.
