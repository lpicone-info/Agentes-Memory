### 1. NC o ND generada desde un ajuste manual

La estructura esperada es:

```xml
<ar:FECAEDetRequest>

    <!-- Datos generales del comprobante -->

    <ar:CbteDesde>NUMERO_COMPROBANTE</ar:CbteDesde>
    <ar:CbteHasta>NUMERO_COMPROBANTE</ar:CbteHasta>
    <ar:CbteFch>AAAAMMDD</ar:CbteFch>

    <!-- Otros datos del comprobante -->

    <ar:PeriodoAsoc>
        <ar:FchDesde>AAAAMMDD</ar:FchDesde>
        <ar:FchHasta>AAAAMMDD</ar:FchHasta>
    </ar:PeriodoAsoc>

</ar:FECAEDetRequest>
```

Debés comprobar que:

- `FchDesde` sea igual a `COMPROBANTES.fecha`.
- `FchHasta` sea igual a `COMPROBANTES.fecha`.
- Las fechas tengan formato `AAAAMMDD`.
- No se utilice `AJUSTES.apli_perio`.
- Dentro del mismo `FECAEDetRequest` **no aparezca** el bloque `<ar:CbtesAsoc>`.
- La NC o ND no figure asociada consigo misma.

Ejemplo para un comprobante del 13/11/2026:

```xml
<ar:CbteFch>20261113</ar:CbteFch>

<ar:PeriodoAsoc>
    <ar:FchDesde>20261113</ar:FchDesde>
    <ar:FchHasta>20261113</ar:FchHasta>
</ar:PeriodoAsoc>
```

### 2. NC o ND con un comprobante relacionado real

Para los comprobantes no originados en ajustes manuales que posean una relación válida, debe aparecer:

```xml
<ar:CbtesAsoc>
    <ar:CbteAsoc>
        <ar:Tipo>CODIGO_TIPO_ARCA</ar:Tipo>
        <ar:PtoVta>PUNTO_DE_VENTA</ar:PtoVta>
        <ar:Nro>NUMERO_RELACIONADO</ar:Nro>
        <ar:Cuit>CUIT_EMISOR</ar:Cuit>
        <ar:CbteFch>AAAAMMDD</ar:CbteFch>
    </ar:CbteAsoc>
</ar:CbtesAsoc>
```

En este caso:

- Los datos deben corresponder al comprobante relacionado registrado en `COMPRO_AFIP_REFERENCIA`.
- El bloque no debe identificar a la propia NC o ND.
- **No debe aparecer** `<ar:PeriodoAsoc>`.

### Regla principal

Dentro de cada `<ar:FECAEDetRequest>` debe existir solamente una de estas estructuras:

- `PeriodoAsoc`, para NC/ND de ajustes manuales.
- `CbtesAsoc`, cuando corresponda informar un comprobante relacionado real.

Nunca deben aparecer las dos simultáneamente.
