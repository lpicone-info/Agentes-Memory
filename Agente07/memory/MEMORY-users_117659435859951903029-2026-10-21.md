
## Comportamiento propuesto

Al presionar **Alta**, el sistema deberá buscar la combinación `prepaga + plan_codi`:

1. **No existe:** insertar una nueva configuración.
2. **Existe con `baja_fecha IS NULL`:** impedir el alta porque ya tiene una configuración activa.
3. **Existe con `baja_fecha` informada:** reactivar esa misma fila.

Para reactivarla deberá:

```text
emi_grupo  = grupo seleccionado
alta_fecha = fecha y hora actual
baja_fecha = NULL
```

Además, deberá registrar en la auditoría:

- Acción: Reactivación.
- Grupo anterior y grupo nuevo.
- Fecha de baja anterior.
- Nueva fecha de alta.
- Usuario que realizó la operación.

El historial anterior se conservará en `AUDIT_ABM_CAB` y `AUDIT_ABM_DET`.

## Ejemplo

Estado anterior:

```text
Prepaga:    1
Plan:       200
Grupo:      DIRECTOS
Alta:       01/10/2026
Baja:       15/10/2026
```

Nueva asignación:

```text
Grupo seleccionado: DÉBITO AUTOMÁTICO
```

La misma fila quedará:

```text
Prepaga:    1
Plan:       200
Grupo:      DÉBITO AUTOMÁTICO
Alta:       fecha y hora de la reactivación
Baja:       NULL
```

El historial permitirá visualizar:

```text
Alta → Baja → Reactivación
```

## Redacción para incorporar en la EF

### Reactivación de una configuración

> Cuando se intente dar de alta una relación entre entidad y plan, el sistema deberá verificar si ya existe una fila en `EMI_GRUPO_PLAN`.
>
> - Si no existe una fila para la entidad y el plan, se insertará una nueva configuración.
> - Si existe una configuración con `baja_fecha` nula, no se permitirá el alta porque el plan ya posee una asignación activa.
> - Si existe una configuración con `baja_fecha` informada, el sistema deberá reactivar la misma fila, actualizando el grupo de emisión con el seleccionado, informando `alta_fecha` con la fecha y hora actual y dejando `baja_fecha` en nulo.
>
> La reactivación deberá registrarse en `AUDIT_ABM_CAB` y `AUDIT_ABM_DET`, conservando el grupo anterior, el grupo nuevo, la fecha de baja anterior, la nueva fecha de alta y el usuario responsable.
>
> El Historial deberá mostrar de forma cronológica las operaciones de Alta, Baja y Reactivación.

## Opción alternativa

Si se necesita conservar **una fila física por cada ciclo de alta y baja**, habría que cambiar el diseño:

- Agregar un identificador propio como clave primaria.
- Permitir varias filas históricas para el mismo plan.
