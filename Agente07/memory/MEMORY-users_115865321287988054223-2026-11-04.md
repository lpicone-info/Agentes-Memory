Pato, hoy **no existe una única regla de duplicados para todas las importaciones**. Cada proceso define su propia clave.

### Importación de mails

La clave utilizada es:

`Entidad + Contrato + Integrante + Vigencia desde`

Si dos filas coinciden en esos campos:

- **Ambas filas** quedan marcadas con error.
- Se muestran en “Rechazos” con el mensaje **“Regristro duplicado”** —así está escrito actualmente—.
- **Ninguna de las dos se incorpora a `AFI_MAILS`**.
- Esto ocurre aunque cada fila tenga un mail diferente, porque el correo no forma parte de la clave utilizada para detectar duplicados.

Si solamente coinciden Entidad + Contrato + Vigencia, pero tienen distinto integrante, no se consideran duplicadas.

Evidencia: [afs_valida_importacion_mails.sql](/home/desarrollo-ia-07/.openclaw/workspace/svn/mpariso-Infomedical-trunk/backend/procedures/afs_valida_importacion_mails.sql:47).

### Derivación de aportes

La clave utilizada es [SECRETO REDACTADO]

`Entidad + Contrato + Integrante + Vigencia desde + CUIT + Obra social`

Cuando las dos filas coinciden en esa combinación:

- Ambas reciben el rechazo **1452 – “Registro duplicado.”**
- Ambas aparecen como rechazadas.
- Ninguna se incorpora a `AFI_DERIV_APORTES`.

El código y la descripción del rechazo 1452 están vigentes en `Premedic_Prox_Ver`.

Evidencia: [afs_valida_importacion_deriv_apo.sql](/home/desarrollo-ia-07/.openclaw/workspace/svn/mpariso-Infomedical-trunk/backend/procedures/afs_valida_importacion_deriv_apo.sql:35).

### Otros ejemplos

- **Afiliados morosos:** usa `Entidad + Contrato + Vigencia`; ambas filas quedan con error **“Registro duplicado”**.
- **Prestador externo:** usa `Entidad + Contrato + Vigencia`; ambas filas reciben el rechazo **1452**.
- **Certificados:** usa `Entidad + Contrato + Integrante + Vigencia`; ambas filas quedan rechazadas.
- **Notas:** no tiene un control equivalente de duplicidad. Cada fila válida recibe un número de nota diferente y ambas pueden importarse.

### Conclusión funcional

Cuando el proceso posee control de duplicidad, SubeDatos **no conserva una fila y descarta la otra**: rechaza todas las filas que forman el grupo duplicado. El usuario debe corregir o eliminar la repetición del archivo y volver a verificarlo. En cambio, no puede afirmarse que Entidad + Contrato + Vigencia sea siempre la clave, porque depende del tipo de importación.
