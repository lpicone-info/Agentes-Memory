## 2. Filtro Clase del afiliado

La clase se encuentra en `AFI_CLASE` y pertenece al **contrato**, no al integrante:

```text
PEDIDOS.prepaga + contra
          ↓
AFI_CLASE.prepaga + contra
```

Como puede existir más de un registro histórico, no debe hacerse un `JOIN` directo sin controlar vigencia: podría duplicar pedidos.

La forma segura es seleccionar una sola clase vigente a la fecha de ejecución:

```sql
OUTER APPLY
(
    SELECT TOP 1
           AC.clase_afi,
           AC.cuenta,
           AC.subcta
    FROM AFI_CLASE AC
    WHERE AC.prepaga = P.prepaga
      AND AC.contra  = P.contra
      AND AC.vigen_desde <= @var_hoy
      AND
      (
          AC.baja_fecha IS NULL
          OR AC.baja_fecha = '19000101'
          OR AC.baja_fecha > @var_hoy
      )
    ORDER BY AC.vigen_desde DESC
) CLASE
```

En `SMC_Prox_Ver`, `19000101` se utiliza como fecha testigo de registro activo; no debe interpretarse como una baja histórica real.

Parámetro:

```sql
@prm_clase_afi CHAR(1) = 'T'
```

Filtro:

```sql
AND
(
    @prm_clase_afi = 'T'
    OR CLASE.clase_afi = @prm_clase_afi
)
```

Valores:

```text

D = Directos
```
