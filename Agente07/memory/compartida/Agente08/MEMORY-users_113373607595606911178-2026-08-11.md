Sí, Andre. Ese es el riesgo funcional.

Si hacemos que `expedientes.debito` incluya automáticamente el copago por orden, el usuario podría cargar un débito global menor y en la práctica compensar o anular el copago que debería descontarse. Ejemplo: copago por orden `1200` + débito global esperado `1200`; si el sistema guarda todo junto en `expedientes.debito = 2400`, el usuario podría informar `1200` y no quedaría claro si ese importe representa solo el copago, solo el débito global, o una decisión de no aplicar parte del descuento.

Por eso no conviene mezclar ambos conceptos en un único campo editable. La alternativa más controlada es:

- Mantener el copago por orden en `expe_copagos.valor`, con `pago_copa = 'P'`.
- Mantener el débito global manual en `expedientes.debito`.
- Calcular el total a descontar como suma funcional: `expedientes.debito + copago por orden vigente`.
- Mostrarlo en el resumen como total compuesto, pero sin permitir que el usuario lo reduzca indirectamente editando el débito global.

Si funcionalmente se quiere permitir “no aplicar el copago por orden”, debería ser una decisión explícita y trazable, no una consecuencia de cargar un débito global menor.
