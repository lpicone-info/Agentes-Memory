**Qué hace Buscar**
1. Valida lote, prepaga, referencia y `Periodo Hasta`.
2. Para el lote seleccionado, si el origen es `N` = Novedades, ejecuta:
   `afi_isss_afiliados_busca_compara(@prepaga, @fecha_hasta, @lote)`.
3. Ese procedure arma una foto “actual” de afiliados activos desde:
   `afiliados`, `afi_deriv_aportes`, `afi_domicilios`, `afi_opcion`, `localidades`.
4. Compara esa foto contra el último lote de novedades enviado a SSS.
5. Inserta el resultado en `ISSS_NOVEDADES_RNAS_EXPORT` con movimientos:
   `A` alta, `B` baja, `M` modificación, `X` sin cambios.

**Fechas que determinan activo**
Con `nov_sss_fecha_fin = N`, el sistema toma el primer día del mes del `Periodo Hasta`. Para el lote 109, usa `01/08/2026`.

Un afiliado entra como activo si cumple, entre otras:

- `afiliados.ingre_fecha < 01/08/2026`
- `afiliados.baja_fecha IS NULL OR afiliados.baja_fecha >= 01/08/2026`
- `afi_deriv_aportes.vigen_desde < 01/08/2026`
- `afi_deriv_aportes.vigen_hasta IS NULL OR vigen_hasta >= 31/07/2026`

- domicilio vigente con `afi_domicilios.vigen_desde < 01/08/2026` y sin baja antes del corte
- opción vigente con `afi_opcion.vigen_desde < 01/08/2026` y sin baja antes del corte

**Cómo decide baja**
No decide la baja solo mirando `afiliados.baja_fecha`. Primero arma la foto actual de afiliados activos al corte. Después compara contra el lote anterior enviado.

Marca `B` cuando un CUIL que estaba en el lote anterior enviado ya no aparece en la foto actual activa. También puede generar baja + alta cuando cambia información estructural sensible, por ejemplo CUIT empleador, tipo beneficiario, parentesco o datos identificatorios según el caso.
