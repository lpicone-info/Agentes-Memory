## 2026-07-13 21:24 UTC - Presmed expediente ordenes / autorizacion sin efector

- User Mariela/Maru asked whether Presmed ever allowed associating an authorization without loaded efector to an order expediente for a non-circle provider, because trunk now shows "El prestador de la orden no se corresponde con el expediente".
- Conclusion: evidence indicates the system previously could advance, or at least did not have this blocking validation at authorization load. In SVN trunk, revision `r83206` added the blocking validation under Redmine `#28808`.
- Current trunk evidence: `wp_expe_orde.srw` lines around the `R28808` block call `wf_valida_prestador(is_tipo_pre, exp.ofi, exp.expe, exp.prestad, lds_auto.object.efe_prestad[1], lds_auto.object.efe_lugar[1], Ref li_existe)` and show the message if the function fails or `li_existe = 0`.
- SVN evidence: `svn annotate` attributes the new validation lines to `r83206` by `s.altamiranda`; `svn log -r 83206` says `Defecto #28808 - Liquidar Aut Webpos - Mensaje "El efector tiene mas de un lugar de atencion"`.
- Diff evidence: before `r83206`, the auto-load path retrieved places with `ids_lugar.retrieve(...)` but did not call `wf_valida_prestador` at that point. Revision `r83206` added the validation and passed `efe_lugar` into `wf_valida_prestador`.
- Root cause of current rejection for a non-circle provider with missing efector: `wf_valida_prestador` executes `dbo.prs_valida_lugares_x_prestador_circulo`; for non-circle cases the SP validates `expedientes.ofi = @ofi`, `expedientes.expe = @expe`, and `expedientes.prestad = @prm_prestad`. If authorization `efe_prestad` is null/empty, no expediente row matches and the SP returns `0`, causing the message.
- Redmine `#28808` description/journals show the change was meant to fix WebPos authorization liquidation/place-of-attention behavior, especially efector place selection and circle/non-circle place discrimination. The rejection of authorizations without efector appears to be a consequence of that new validation, not a separately identified explicit requirement to block missing effectors.
