## Prestador común

Cuando `es_centro = 'N'`:

- El usuario representa un único prestador.
- La autorización madre debe pertenecer a ese prestador.
- La sección **Prestador** de la `05P` puede mostrar directamente el prestador del usuario.
- El lugar debe respetar la restricción del usuario o el lugar de la autorización madre.

## Centro de atención

Cuando `es_centro = 'S'`:

- El usuario representa un **punto de atención**, no un único prestador.
- El centro puede tener varios prestadores y lugares asociados mediante `prestad_lugares.cod_punto_atencion`.
- Por lo tanto, no debe grabarse el código del centro como si fuera el efector de la prórroga.

La regla funcional más consistente sería:

1. Buscar la autorización madre por número.
2. Obtener de ella su sucursal, prestador efector y lugar.
3. Verificar que ese prestador y lugar estén asociados y vigentes para el centro autenticado.
4. Mostrar en la sección **Prestador** el prestador real de la autorización madre.
5. Generar la `05P` para ese mismo prestador y lugar.
6. Registrar además que la operación fue realizada por un usuario centro (`es_centro = 'S'`).

### Ejemplo

```text
Centro autenticado: 132

Prestadores asociados:
- Prestador 500 / Lugar 1
- Prestador 700 / Lugar 3

Autorización madre:
- Prestador 700
- Lugar 3
```

La `05P` debería generarse con:

```text
Prestador: 700
Lugar:     3
Centro:    132
Es centro: S
```

No debería generarse con el prestador `132` ni permitir elegir arbitrariamente el prestador `500`.

Si la autorización madre fuera del prestador `900`, no asociado al centro `132`, debería rechazarse con un mensaje equivalente a:


## Relación con RM30265

RM30265 ya establece esta diferenciación:

- Usuario común: la autorización debe pertenecer al prestador autenticado.
- Usuario centro: el efector de la autorización debe corresponder a alguno de los prestadores asociados al centro.
- La sucursal se obtiene automáticamente de la autorización y se muestra deshabilitada.

La `05P` debería reutilizar el mismo criterio.

## Definición faltante en R29396

La frase de V5:

> “La sección del Prestador corresponde al prestador logueado en el portal”

es suficiente para un usuario común, pero **no para un centro de atención**. Debería aclararse así:

## ¿Qué función cumple el centro?

El centro de atención agrupa lugares de distintos prestadores mediante:

```text

```

Un usuario del Portal puede estar configurado como:

```text

es_centro = S → representa a un centro de atención
```

Cuando el usuario es centro, el sistema verifica que el prestador y lugar de la autorización pertenezcan a alguno de los prestadores asociados al centro.

```text
Prestador: 334 / Lugar 1
```


## Entonces, ¿puede ser de cualquiera?

La autorización puede ser operada:

- directamente por el usuario del prestador efector;
- por un usuario centro, siempre que el efector y su lugar estén asociados al centro.

Pero **la autorización siempre conserva como efectores a los prestadores reales**. El centro es el ámbito desde el cual se opera, no el efector asistencial.

## Consulta de validación

```sql
DECLARE @sucur SMALLINT = 40
DECLARE @auto INTEGER = 868386

SELECT
       a.sucur,
       a.auto,
       a.tipo,
       ar.transac,
       ar.tipo_transac,
       ar.aufree,
       origen =
       CASE
           WHEN ar.transac IS NULL THEN 'PRESMED'
           WHEN ar.aufree IS NULL THEN 'PRESMED'
           WHEN ar.aufree = '-1' THEN 'WEBPOS'
           ELSE 'ACTIVIA'
       END
FROM autorizaciones a
OUTER APPLY
(
    SELECT TOP 1
           r.transac,
           r.tipo_transac,
           r.aufree,
           r.alta_fecha
    FROM auto_remotas r
    WHERE r.sucur = a.sucur
      AND r.auto = a.auto
      AND r.baja_fecha IS NULL
    ORDER BY r.alta_fecha, r.transac
) ar
WHERE a.sucur = @sucur
  AND a.auto = @auto
  AND a.baja_fecha IS NULL
```

Se toma la primera transacción vinculada directamente porque representa el registro original de generación.
