## Qué controla si el lote está cerrado

La ventana **Generación de archivos para la SSS** determina el estado del lote solamente mediante:

```powerscript
IF ISNULL(dw_lotes.object.cierre_fecha[1]) THEN
    // Lote abierto
ELSE
    // Lote cerrado
END IF
```

Cuando `cierre_fecha` está informada, deshabilita:

- Buscar
- Exportar
- Modificar
- Cerrar

`fecha_envio` no determina si el lote está abierto o cerrado.

## Importante sobre el stored procedure

`pru_isss_integracion_lotes` actualiza el cierre así:

```sql
cierre_fecha = ISNULL(@prm_fecha_cierre, cierre_fecha)
```

Por lo tanto, si se ejecuta el procedimiento pasando:

```sql
@prm_fecha_cierre = NULL
```

**no se borra el cierre existente**; conserva el valor anterior.

## ¿Se puede reutilizar?

### Técnicamente

Sí, un lote cerrado podría reabrirse mediante una actualización directa:

```sql
UPDATE isss_integracion_lotes
SET cierre_fecha = NULL,
    fecha_envio = NULL,
    fecha_proceso = NULL
WHERE lote = @lote
```

Luego la ventana lo trataría como abierto y permitiría volver a seleccionar/exportar sus ítems.

Al exportar, el circuito:

1. Elimina los ítems actuales del lote.
2. Inserta nuevamente los ítems seleccionados.
3. Actualiza las fechas de proceso/envío.
4. Permite cerrar nuevamente el lote.

### Riesgos

No recomiendo hacerlo sin un script controlado porque puede:

- Reenviar un lote ya enviado a la SSS.
- Generar duplicidad de información externa.
- Perder la trazabilidad de los ítems originales.
- Dejar inconsistencias con `ISSS_LOTES_RENDICION` o respuestas recibidas.
- Alterar la auditoría funcional del lote.

## Conclusión

- `fecha_envio = NULL` no reabre el lote.
- `cierre_fecha = NULL` sí lo haría visible como abierto.
- El procedimiento estándar no permite limpiar `cierre_fecha` pasando `NULL`.
- Para una prueba controlada puede reutilizarse, pero requiere un `UPDATE` explícito y revisar previamente si el lote fue enviado o rendido.

Sí, se puede. Para pruebas internas, la alternativa más segura es:

1. Eliminar los ítems seleccionados de `ISSS_INTEGRACION_LOTES_ITEMS` del lote origen.
2. Registrar la operación en auditoría.
3. Abrir o crear el lote destino.
4. Buscar nuevamente los expedientes desde la pantalla.
5. Incorporarlos al lote destino mediante el circuito normal.

Al eliminarse del lote origen, dejan de cumplir el `NOT EXISTS` que los excluye y vuelven a quedar disponibles, siempre que:

- El expediente tenga `integracion = 'S'`.
- Tenga `cierre_admin_fecha`.
- Cumpla el rango de fechas del lote destino.
- No exista otro registro activo del mismo expediente/ítem en otro lote.

No recomiendo copiar directamente las filas al lote nuevo, porque conservaría datos calculados del lote anterior —CUD, homologaciones, importes y estados— sin recalcularlos.

Para preparar el script controlado necesito:

- **Lote origen:** entiendo que es `86`.
