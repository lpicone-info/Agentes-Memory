La ventana **Solicitudes**, a la cual se accede desde **Afiliados / Solicitudes / Solicitudes**, permite registrar las novedades que modifican los datos del padrón. Según el motivo seleccionado, el sistema habilita los campos y solapas correspondientes.

Actualmente, el sistema propone el Grupo de Emisión según la clase del afiliado:

- Para afiliados de clase **Directo**, toma el Grupo de Emisión predeterminado configurado en `PARAM_AFI.emi_grupo_default`. - Para afiliados de clase **Empresa**, toma la configuración vigente correspondiente a la Cuenta y Subcuenta seleccionadas. Para ello, recupera de `SUBCTA_CONTRATOS` el registro cuya combinación de `cuenta` y `subcta` coincida, que tenga `baja_fecha IS NULL` y la mayor `vigen_desde`. Si existe una configuración, el sistema asigna el Grupo de Emisión, el Modo de Emisión y el Grupo de Vencimiento definidos en dicho registro y protege estos campos para impedir su modificación manual.

El comportamiento según el motivo de solicitud es el siguiente:

**Afiliaciones**

Durante la carga de una afiliación, el sistema propone el Grupo de Emisión cuando se completan los datos utilizados para determinar la configuración: Clase y, para afiliados de Empresa, Cuenta y Subcuenta. La selección posterior del Plan o de la Tarifa no modifica el Grupo de Emisión propuesto.

**Cambio de plan y tarifa**

Actualmente, al seleccionar o modificar el nuevo Plan, el sistema no busca una configuración de Grupo de Emisión asociada a la combinación Entidad y Plan. **Cambio de datos personales**

> “El contrato se encuentra facturado a la fecha de aplicación ingresada. ¿Desea continuar?”

`plan_codi` no identifica por sí solo un Plan de manera única, porque un mismo código puede existir en entidades diferentes.

Por ejemplo:

- Entidad 1 — Plan `200`.
- Entidad 2 — Plan `200`.

Si la relación se realiza solamente por `plan_codi = '200'`, la grilla podría recuperar el Plan de ambas entidades o mostrar información duplicada.

La identificación correcta del Plan requiere siempre la combinación:

> **Entidad (`prepaga`) + Plan (`plan_codi`)**

Esto además mantiene consistencia con la clave foránea compuesta definida para `EMI_GRUPO_PLAN`.
