Pablo, la **notación científica** es una forma abreviada de representar números grandes o pequeños mediante una potencia de 10.

Por ejemplo, este número entero:

```text
10860541
```

podría representarse en notación científica como:

```text
1.0860541E7
```

La expresión significa:

```text
1.0860541 × 10⁷ = 10860541
```

## Aplicación al caso de prueba 14

El servicio debe devolver:

```xml
<NroTransaccion>10860541</NroTransaccion>
```

No debe devolver:

```xml
<NroTransaccion>1.0860541E7</NroTransaccion>
```

Ni tampoco:

```xml
<NroTransaccion>10860541.0</NroTransaccion>
```

## ¿Por qué es importante?

`NroTransaccion` es un **identificador**, no un valor matemático. Debe conservarse como una secuencia exacta de dígitos.

La notación científica podría:

- impedir que otro sistema encuentre la transacción;
- generar errores al convertir el contenido a entero;
- alterar comparaciones con `[SECRETO REDACTADO].transac`;
- producir diferencias en logs, auditorías o integraciones.

## Qué valida el CP14

La operación debe terminar rechazada por una causa funcional controlada, pero el número debe mantener este formato:

```text
Solamente dígitos: Sí
Letra E/e:         No
Punto decimal:     No
Signos + o -:      No
```

Además, debe coincidir exactamente con la base:

```text
Respuesta XML:           10860541
[SECRETO REDACTADO].transac:10860541
```

El ajuste de formato no debe modificar el rechazo:

```text
Código:  272
Mensaje: Terminal inexistente
```

En resumen: el CP14 comprueba que una transacción rechazada devuelva su identificador completo como entero literal, sin convertirlo a una expresión como `1.0860541E7`.
