## Cómo determina el prestador

El proceso distingue tres roles:

- `exp.prestad`: prestador titular del expediente. No se obtiene por matrícula.
- `ori_prestad`: prestador demandante/ordenante.
- `efe_prestad`: prestador efector, utilizado cuando el titular es un círculo (`prestadores.tipo = 'C'`).

La búsqueda se realiza directamente desde PowerBuilder sobre `prestadores`; no utiliza un stored procedure.

### Matrícula nacional

```sql
SELECT MAX(prestad)
FROM prestadores
WHERE matri_naci = matrícula
  AND baja_fecha IS NULL
```

### Matrícula provincial

```sql
SELECT MAX(prestad)
FROM prestadores
WHERE matri_prov = matrícula
  AND matri_prov_provin = provincia
  AND baja_fecha IS NULL
```

Después, `of_prestador` carga los datos completos y vuelve a controlar que el prestador exista y no esté dado de baja.

## Precedencia para `ori_prestad`

1. Parte del `ori_prestad` informado en el archivo.
2. Una matrícula nacional válida lo reemplaza.
3. Una matrícula provincial válida lo vuelve a reemplazar; por ejecutarse después, tiene prioridad.
4. Si no se informó prestador, matrícula ni nombre, genera el aviso **“Sin demandante (el sistema fuerza el valor)”** y asigna `exp.prestad`.

El nombre `ori_nombre` **no se cruza con la matrícula** para verificar identidad.

## Normalizaciones

- Provincia `1` —Capital Federal en QA—: la matrícula provincial se transforma en nacional.
- Si falta la provincia, se utiliza la provincia del lugar de atención.
- `999999` se considera matrícula no informada para el demandante.
- Las matrículas numéricas se convierten a número y nuevamente a texto, eliminando ceros iniciales.

## Prestador efector

Cuando el expediente pertenece a un círculo:

1. Busca `efe_prestad` por matrícula nacional.
2. Después busca por matrícula provincial y provincia.
3. La coincidencia provincial prevalece.
4. Si no existe prestador ni matrícula, genera el error **“Sin efector (para círculo es oblig)”** y la fila no se importa.

Para expedientes que no pertenecen a círculos, el efector y sus matrículas se persisten como `NULL`.

## Casos especiales

- Expediente `S` procesado como internación: fuerza `ori_prestad = exp.prestad` y elimina los datos de matrícula.
- Expediente `H`: no ejecuta la resolución de `ori_prestad` mediante `of_prestador_row` en esta etapa.
- Una matrícula informada pero inexistente no genera aquí un mensaje específico de “matrícula inválida”; la búsqueda devuelve `False`.

## Hallazgo relevante en QA

La consulta utiliza `MAX(prestad)`, no valida unicidad. En `SwissQAP10_prestaci` confirmé matrículas activas duplicadas, nacionales y provinciales.

Por lo tanto, ante duplicados, el sistema selecciona el código `prestad` numéricamente mayor, que puede no ser el prestador esperado funcionalmente.

### Consecuencia funcional

Aunque un prestador tenga varias matrículas provinciales vigentes en `prestad_matriculas`, Importación Inteligente solamente puede encontrar directamente la matrícula copiada en:

Las restantes matrículas registradas en `prestad_matriculas` **no participan en la búsqueda del importador**.
