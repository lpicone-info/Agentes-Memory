## 1. Validaciones previas a leer el archivo

1. **Acción obligatoria**
   - Se debe seleccionar una acción en `ddlb_accion`.

   - Referencia: `wf_is_not_null_accion`.

2. **Prestador**
   - Se ejecuta `prs_prestad_imp_inv_prestac`.
   - Determina si el prestador permite validar normalmente la prestación.
   - Si devuelve `S`, los errores de prestación se clasifican como aviso en lugar de error.

3. **Cierre del período**
   - Se ejecuta `Val.Of_cierre_perio_liq`.
   - Se valida el período del expediente y la oficina.
   - Si el período está cerrado, se bloquea toda la importación.
   - Mensaje: `Sobrepasa fecha de cierre para Liquidación de Período mm/yyyy`.
   - Referencias:
     - `wp_import_exp.srw:1733`
     - `wp_import_exp_new.srw:1763`

4. **Selección y apertura del archivo**
   - Se permite seleccionar archivo TXT.
   - También se procesa DBF.
   - Se valida:
     - archivo seleccionado;
     - error al obtener el archivo;
     - error al abrirlo;
     - error durante la lectura de una fila.
   - Mensajes posibles:
     - `No se seleccionó archivo ...`
     - `Ocurrió un error al intentar leer ...`
     - `Ocurrió un error al abrir el archivo ...`
     - `Ocurrió un error de lectura (fila N)`.

5. **Tipo de importación**
   - Ambulatoria o internación.
   - No se permite importar internación para círculos.
   - Mensaje: `No está contemplado la importación de círculos para internación`.

6. **Datos existentes**
   - Se informa si el expediente ya posee datos.
   - Según la opción elegida:
     - se reemplazan los datos anteriores;
     - o se agregan los nuevos registros.

## 2. Validaciones por cada fila

### Lugar de atención

- Si el expediente tiene un solo lugar, se asigna automáticamente.
- Si hay varios lugares:
  - se verifica que el lugar exista;
  - si está vacío o no es válido, se utiliza el lugar predeterminado.
- No necesariamente genera error: en algunos casos corrige automáticamente el valor.

### Fecha de realización

- Es obligatoria.
- Mensaje: `Sin fecha de realización`.
- Se valida que el mes de realización no sea posterior al período del expediente.
- Excepción: prestador `73572`.
- Mensaje: `Fecha mayor al periodo de este expediente`.

### Afiliado

Se puede buscar por credencial, DNI o contrato/integrante.

#### Por credencial

Se ejecutan:

- `prs_busca_credencial_afi_cred`
- `val.of_afiliado`

Para Docthos se normalizan distintos formatos de credencial:

- 13 dígitos;
- 15 dígitos;
- 11 dígitos;
- 9 dígitos;
- credenciales con prefijo `800006`.

Se eliminan espacios, barras, guiones y prefijos configurados.

Validaciones y mensajes:

- Credencial vacía:
  - `Sin credencial`
- Credencial Docthos inválida:
  - `Formato Credencial Docthos Erronea: ...`
- Afiliado inexistente:
  - `Sin prepaga (contrato) o inexistente`

#### Por DNI

Se ejecuta:

```text

    ...,
    dni,
    fecha_realizacion,
    prepaga,
    contrato,
    integrante,
    fecha_baja

```

Se valida el afiliado vigente a la fecha de realización.

Casos:

- Un afiliado encontrado: se completan prepaga, contrato e integrante.
- Más de un afiliado:
  - `Mas de 1 afiliado encontrado (contrato)`
- Ningún afiliado:
  - `Sin afiliado (contrato) - valid 1`
  - o `Sin afiliado (contrato) o inexistente`, según el modo de importación.
- Si existe fecha de baja, se evalúa contra la fecha de realización.

#### Por contrato e integrante

Se ejecuta:

- `val.of_prepaga_creden_contra_inte`

Se valida:

- que exista el contrato;
- que exista el integrante;
- que pueda determinarse la prepaga.

Mensajes:

- `Sin afiliado (contrato) o inexistente`
- `Sin prepaga (contrato) o inexistente`
