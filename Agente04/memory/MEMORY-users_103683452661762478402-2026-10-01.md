## Algoritmo aplicado

La función central es `of_dif_valores` ([uo_nv_liquida_farma.sru](/home/luispicone/.openclaw/workspace/git/smg-code-presmed-main/ws_objects/liqui14.pbl.src/uo_nv_liquida_farma.sru:475)):

```text
diferencia = abs(valor_informado - valor_auditado)

Si valor_auditado no es nulo ni cero:
    porcentaje = diferencia * 100 / valor_auditado
    Si porcentaje > desvi_porce:
        devuelve diferencia

Si ambos valores no son nulos:
    Si diferencia > desvi_monto:
        devuelve diferencia

En caso contrario:
    devuelve 0
```

Resultados:

- `1`: el valor informado es mayor.
- `-1`: el valor auditado/calculado es mayor.
- `0`: diferencia tolerada.

**Los controles porcentual y monetario son independientes.** La diferencia se rechaza cuando supera **cualquiera** de los dos límites. Para considerarla tolerada debe cumplir ambos.

Además:

- El porcentaje se calcula tomando como denominador el segundo valor, normalmente el auditado o calculado.
- Si el segundo valor es cero, se omite el porcentaje y solamente se controla el monto.
- Una diferencia exactamente igual al límite se tolera porque se utiliza `>` y no `>=`.

## Uso por ítem

`desvi_monto_item` y `desvi_porce` se utilizan para comparar:

1. **Importe de venta del ítem**

```text
informado = rece_vta_precio × cantidad
auditado  = audi_vta_precio × cantidad
```

2. **Importe cubierto por la entidad**

```text
informado = (rece_vta_precio - rece_afi_precio) × cantidad
auditado  = (audi_vta_precio - audi_afi_precio) × cantidad
```

3. En la auditoría interactiva también se comparan:

```text
rece_total_precio contra audi_total_precio
```

Las diferencias generan:

- Error `155`: sobre facturado.
- Error `154`: subfacturado.
- Estados de ítem `F` o `A`, según quién absorba el débito.
