## Multi-Evolucionador / Contrato de Evolucion
- Daniel definio junto con La 99 el concepto de Multi-Evolucionador multi-archivo/multi-lenguaje: la IA analiza en sandbox/carpeta de trabajo, no modifica fuentes originales ni aplica cambios; entrega propuestas auditables en texto plano.
- Se creo el contrato persistente en `/mnt/Agentes/d.acosta/Recetas/CONTRATO_EVOLUCIONADOR.md`, version 1.0. El contrato evita JSON para transportar codigo y usa texto literal con etiquetas como `[CAMBIO 0001]`, `ARCHIVO`, `OBJETO`, `LINEAS`, `ACCION`, `MOTIVO`, y bloques `<buscar>`, `<reemplazo>`, `<insertar>`, etc.
- Destinos definidos: `PROGRAMADOR`, `EVOLUCIONADOR`, y `PROGRAMADOR|EVOLUCIONADOR`. Default: `PROGRAMADOR|EVOLUCIONADOR`.
- Salidas definidas: `propuesta_evolucion_DEV.txt` para programador y `propuesta_evolucion_EVO.txt` para la herramienta.
- Regla clave: todos los rangos pertenecen al archivo original copiado a la carpeta de trabajo al inicio de la evolucion. El Evolucionador reconstruye bloques por lineas y aplica cambios aprobados, nunca reemplazos globales.
- Acciones formalizadas: `REEMPLAZAR`, `ELIMINAR`, `INSERTAR`, `MOVER`. Para `INSERTAR` se usa `REFERENCIA_LINEAS` + `POSICION: ANTES|DESPUES` + `<insertar>`. Para `MOVER` se usa `LINEAS`, `DESTINO_LINEAS`, `POSICION`.
- Regla PowerBuilder: conservar encoding y BOM originales, pero todo archivo PB debe guardarse con `FIN_LINEA: CRLF`; LF puro puede romper import/compilacion/IDE PB 2022.
- Duplicados en carpeta plana: si hay archivos con el mismo nombre desde rutas distintas, La 99 no debe elegir automaticamente; debe copiarlos a `DUPLICADOS/...`, informar y bloquear esos archivos hasta aclaracion del programador.
- La unidad minima del contrato es un `CAMBIO`, no una coincidencia textual. Si el mismo bloque debe modificarse en tres ubicaciones, deben existir tres `[CAMBIO XXXX]` independientes.
