Fernanda, el proceso actualmente instalado en `SwissDeVP10_prestaci` espera el campo `MATRICULA` de **10 posiciones** con esta estructura:

```text
Posición 1: tipo de matrícula
Posiciones 2–10: número, 9 dígitos con ceros a la izquierda
```

## Formato actualmente reconocido

| Tipo | Posición 1 | Posiciones 2–10 | Ejemplo para matrícula 12345 |
|---|:---:|---|---|
| Nacional | `N` | Número con 9 dígitos | `N000012345` |
| Nacional alternativo | `0` | Número con 9 dígitos | `0000012345` |
| Provincial | `P` | Número con 9 dígitos | `P000012345` |
| No informada | `0` | Nueve ceros | `0000000000` |

El SP toma el número mediante:

```sql
RIGHT(MATRICULA, 9)
```

y determina el tipo mediante:

```sql
LEFT(MATRICULA, 1)
```

### Validación nacional

Para prefijo `N` o `0` busca:

```sql
prestadores.matri_naci = número
AND prestadores.baja_fecha IS NULL
```

### Validación provincial

Para prefijo `P` busca:

```sql
prestadores.matri_prov = número
AND prestadores.baja_fecha IS NULL
```

Si no encuentra coincidencia genera:

```text
Rechazo 6052: Matrícula inexistente
```

## Problema: la provincia no viene informada

El formato actual **no reserva ninguna posición para la provincia**.

Por ejemplo:

```text
P000003019
```

solamente informa:

```text
Tipo       = Provincial
Matrícula  = 3019
Provincia  = no informada
```

La validación no utiliza:

```sql
prestadores.matri_prov_provin
```

ni la tabla:

```sql
prestad_matriculas
```

Por lo tanto, una matrícula provincial repetida en distintas provincias no identifica unívocamente al prestador.

En desarrollo confirmé **16.848 números de matrícula provincial activos que aparecen en más de una provincia**. Ejemplos:

| 3354 | 15 | 15 |
| 1035 | 14 | 14 |
| 1120 | 14 | 14 |

Es decir, `P000003019` puede validar como existente, pero no permite determinar cuál de los 17 prestadores corresponde.

## Formato que debería utilizarse

La solución robusta sería ampliar el layout con campos separados:

```text
TIPO_MATRICULA  1 posición
MATRICULA      10 posiciones
PROVINCIA       2 posiciones
```

Ejemplos:

```text
N | 0000012345 | 00
P | 0000012345 | 02
```

La resolución debería ser:

```sql
-- Nacional
matri_naci = @matricula

-- Provincial
matri_prov = @matricula
AND matri_prov_provin = @provincia
```

Preferentemente consultando `prestad_matriculas`, que soporta múltiples matrículas provinciales por prestador, y exigiendo exactamente una coincidencia vigente.

### Alternativa manteniendo exactamente 10 posiciones

Podría definirse:

```text
N + matrícula de 9 dígitos
P + provincia de 2 dígitos + matrícula de 7 dígitos
```

Ejemplo:

```text

```

Para resolverlo correctamente deben incorporarse `tipo + matrícula + provincia`, buscar por la combinación matrícula/provincia y guardar el prestador encontrado en `expe_farma_recetas`.
