### [11/09/2026 09:47:29] Agente

Marcelo, sí: está mal el orden de ejecución.

El problema principal es que esto quedó **después** de los `RETURN` del cierre de período:

```powerscript
//GRUPO DE PAGO
manda = dw_cab.object.manda[1]
idwc_pg.retrieve(manda)

//idwc_ofi.InsertRow(0)
idwc_ofi.retrieve(dw_cab.object.prepaga[1])

exp.status = False
```

Ese bloque queda prácticamente **inalcanzable**, porque antes ya salís del `open` con `RETURN 0` o `RETURN 1`. Por eso `idwc_ofi` nunca se carga y el campo `ofi` queda mostrando solo el código.

La corrección es mover el `retrieve` del child `idwc_ofi` inmediatamente después del `dw_cab.retrieve(...)`, cuando ya tenés cargada la cabecera y ya existe `prepaga`:

```powerscript
dw_cab.getChild("oficina", idwc_ofi)
idwc_ofi.setTransObject(SQLCA)

dw_cab.retrieve(exp.ofi, exp.expe)

idwc_ofi.retrieve(dw_cab.object.prepaga[1])
```

Y lo mismo te conviene hacer con el grupo de pago antes del bloque que puede retornar:

```powerscript
manda = dw_cab.object.manda[1]
idwc_pg.retrieve(manda)
```

En resumen: `idwc_ofi.retrieve(dw_cab.object.prepaga[1])` no debe quedar al final del evento. Debe ejecutarse después de recuperar `dw_cab` y antes de cualquier validación que pueda hacer `RETURN`.
