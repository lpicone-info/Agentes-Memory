### [14/08/2026 00:58:21] Agente

Walter, el error está en que estás intentando hacer `INSERT` sobre una clave que ya existe:

```sql
cod_zona, vigen_desde, provin, partido
```

Aunque el registro esté dado de baja, **sigue existiendo físicamente en la tabla**, entonces la PK `pk_aume_zona_det` no permite insertarlo otra vez.

El control correcto tiene que estar **antes del INSERT**, no después. La lógica debería ser:

```sql
IF EXISTS (
    SELECT 1
    FROM dbo.AUMENTOS_ZONA_DETALLE
    WHERE cod_zona = @cod_zona
      AND vigen_desde = @vigen_desde
      AND provin = @provin
      AND partido = @partido
      AND baja_fecha IS NOT NULL
)
BEGIN
    -- recuperar registro dado de baja
    UPDATE dbo.AUMENTOS_ZONA_DETALLE
    SET baja_fecha = NULL,
        modi_fecha = GETDATE()
    WHERE cod_zona = @cod_zona
      AND vigen_desde = @vigen_desde
      AND provin = @provin
      AND partido = @partido
END
ELSE IF NOT EXISTS (
    SELECT 1
    FROM dbo.AUMENTOS_ZONA_DETALLE
    WHERE cod_zona = @cod_zona
      AND vigen_desde = @vigen_desde
      AND provin = @provin
      AND partido = @partido
)
BEGIN
    INSERT dbo.AUMENTOS_ZONA_DETALLE
    (
        cod_zona,
        vigen_desde,
        provin,
        partido,
        alta_fecha,
        modi_fecha,
        baja_fecha
    )
    VALUES
    (
        @cod_zona,
        @vigen_desde,
        @provin,
        @partido,
        GETDATE(),
        GETDATE(),
        NULL
    )
END
```

El error conceptual es este: **no alcanza con validar si existe activo** (`baja_fecha IS NULL`). Tenés que validar si existe por PK completa, porque para Sybase el registro dado de baja también ocupa la clave.

Si tu función/proceso de “recuperar” corre después del `INSERT`, llega tarde: el `INSERT` ya falló antes por clave duplicada.
