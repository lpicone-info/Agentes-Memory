### [08/09/2026 09:05:09] Agente

Sí: `Provider='SQLNCLI11'` indica que la conexión va a usar el proveedor OLE DB **SQL Server Native Client 11.0**. No es usuario ni contraseña; es el **driver/librería cliente** con la que la aplicación intenta hablar con SQL Server.

Lo que te está pasando suele deberse a esto:

- En algunas PCs ese proveedor está instalado y es compatible.
- En otras no está, está dañado, o no coincide con la arquitectura de la app (`32/64 bits`).
- También puede variar por versión de Windows, parches de SQL Native Client o requisitos de cifrado/TLS.

Por eso, **el problema no suele ser el usuario de Afilmed**, sino el **entorno del cliente**. El mensaje “999 - Inicio de sesión incorrecto” muchas veces es genérico y tapa el error real de conexión.

Tené en cuenta especialmente esto:
- `SQLNCLI11` está **deprecado**.
- Si la app es 32 bits, el proveedor debe existir en 32 bits.
- No todos los equipos tienen exactamente el mismo stack de conectividad.
- Si sin `Provider='SQLNCLI11'` funciona, probablemente la app esté cayendo en el proveedor por defecto y ese camino sí sea compatible.

Mi lectura técnica es: **es un problema de configuración/compatibilidad del cliente**, no del login en sí.  
Lo correcto ahora sería validar en las máquinas que fallan si está instalado SQLNCLI11, si coincide la bitness de la aplicación, y si existe diferencia entre usuarios o solo entre equipos.
