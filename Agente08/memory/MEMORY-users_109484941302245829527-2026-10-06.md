### WS/transacciones identificados

| Transacción | Uso odontológico |
|---|---|
| **02A** | Registrar prestaciones realizadas. Es la principal para informar la prestación y luego importarla/liquidarla en un expediente odontológico. |
| **02C** | Solicitar autorización previa para una prestación odontológica. Devuelve autorización, rechazo o pendiente. No registra por sí sola la realización. |
| **02D** | Registrar una prestación realizada en forma diferida, dentro del plazo documentado de hasta 15 días. |
| **04A** | Anular una transacción, incluyendo realizaciones informadas mediante 02A. |
| **API Consumo del afiliado** | Consulta el historial de prestaciones e incluye movimientos de tipo **Odontología**, además de sector, pieza y cara cuando corresponda. |

### Datos odontológicos soportados

El manual del módulo indica que las transacciones pueden transportar:

- `<PiezaDental>`
- `<CaraDental>`
- `<TipoTrabajo>`

También documenta el uso de sectores mediante `PiezaDental` cuando la prestación aplica a sector.

Los valores de `TipoTrabajo` son:

- `00`: preexistencia
- `01`: trabajo realizado, que puede importarse y liquidarse
- `02`: trabajo a realizar, que no se importa como prestación liquidable

### Endpoint documentado

Para las transacciones 02A, 02C y 02D se documenta un servicio SOAP:

```text
http://<server_ip:port>/autoremWebAplication/TransactionServ
```

Operación:

```xml

```

El tipo de operación se informa dentro del XML mediante:

```xml
<TipoTransaccion>02A</TipoTransaccion>
```
