## Clasificación

**Error de concurrencia/transacción**, no de cierre abrupto.

## Qué ocurre al forzar el cierre

La ventana trabaja con `SQLCA.AutoCommit = FALSE`. Por lo tanto:

- Si cerrás Afilmed antes del `COMMIT`, SQL Server detecta la desconexión y ejecuta **rollback** de la transacción pendiente.
- Si el `COMMIT` ya ocurrió, deberían quedar confirmados tanto los ítems como el nuevo `EXPEDIENTES.item_nro`.
- Al volver a ingresar, la importación debería comenzar desde un estado consistente.

En condiciones normales no debería quedar:

```text
EXPE_ORDEN_ITEMS insertado
+
EXPEDIENTES.item_nro sin actualizar
```

## Cuándo podría producirse

Solamente bajo una condición anormal adicional:

1. La importación inserta parcialmente información.
2. Afilmed no ejecuta rollback.
3. Antes de finalizar la conexión, otra operación sobre la misma `SQLCA` ejecuta un `COMMIT`.
4. Ese commit confirma accidentalmente los cambios parciales.
5. Luego se reintenta la importación.

Al matar completamente el proceso, el punto 3 normalmente no sucede porque la desconexión provoca rollback.

## En una sola PC

Podés intentar el escenario de concurrencia usando **dos instancias simultáneas de Afilmed en la misma PC**, siempre que cada instancia tenga una conexión SQL independiente:

- Instancia A importa la transacción `165698`.
- Instancia B importa la transacción `165702`.
- Ambas trabajan sobre el expediente `1-3072`.
- Ambas confirman al mismo tiempo.

Lo relevante no es utilizar dos computadoras, sino disponer de **dos sesiones SQL simultáneas**. Ejecutar una importación, matar Afilmed y luego reabrirlo genera dos sesiones consecutivas, no concurrentes, y normalmente no reproduce el error.
