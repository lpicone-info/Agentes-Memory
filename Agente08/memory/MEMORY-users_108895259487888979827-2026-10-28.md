## Cruce manual posible

Un usuario puede aproximarse al resultado utilizando estas consultas:

### 1. Identificar la configuración esperada

**Configuración → Planes → Planes adicionales por plan principal**

Permite conocer, para cada plan principal:

- Plan adicional requerido.
- Tarifa correspondiente.

### 2. Obtener los afiliados activos del plan principal

**Afiliados → Consultas → Detallada de padrón**

Configurar:

- Fecha de consulta.
- Plan principal.
- Estado **Activos**.
- Incluir contrato, integrante, apellido, nombre y plan.
- Exportar el resultado.

### 3. Obtener quienes poseen el adicional

**Afiliados → Consultas → Afiliados por planes adicionales**

Usar la misma fecha de corte y seleccionar el plan adicional correspondiente. La salida incluye:

- Contrato e integrante.
- Plan adicional.
- Tarifa.
- Vigencia.

### 4. Comparar por contrato e integrante

Comparar ambos listados mediante:

`Entidad + Contrato + Integrante`

Interpretación:

- No aparece en el listado del adicional: **SIN PLAN ADICIONAL**.
- Aparece con el plan, pero con otra tarifa: **PLAN ACTIVO CON OTRA TARIFA**.
- Aparece con plan y tarifa esperados: **Correcto**.

La consulta **Novedades por planes adicionales** solamente sirve para investigar altas o bajas ocurridas en un período; no detecta a quien nunca recibió el adicional.

## Limitación práctica

Este procedimiento debe repetirse por cada combinación de plan principal, adicional y tarifa. Por lo tanto, es posible como control manual, pero resulta poco práctico para un volumen grande.

El script [Consulta_Afil_Sin_Planes_Adic.sql](</mnt/Agentes/jpinto/S5345/Consulta_Afil_Sin_Planes_Adic.sql>) realiza automáticamente ese cruce. Al **28/10/2026**, devuelve:

- **1.538 relaciones inconsistentes**.
- **1.519 afiliados únicos**.
- 19 afiliados aparecen dos veces porque les falta más de una relación.

## Corrección desde Afilmed

La regularización puede realizarse desde:

**Afiliados → Solicitudes → Solicitudes**

Usando el motivo **“Cambios de plan, tarifa”** y el botón de **Planes adicionales** para incorporar la combinación faltante.

TRUNK permite mantener el mismo plan y tarifa principal cuando se registró una modificación en los adicionales; sin esa modificación, rechaza una solicitud que conserve exactamente el mismo plan y tarifa.
