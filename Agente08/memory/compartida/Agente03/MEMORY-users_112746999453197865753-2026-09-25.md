### Si el mismo CUIL existe en varios contratos

Con la consulta actual:

```sql
WHERE prepaga = @prepaga
  AND cuil = @cur_cuil
  AND paren = @cur_paren
```

si existen varios contratos con ese CUIL y parentesco, `@filas > 1`:

- se rechaza con código `1016`;
- se registra el error;
- no se genera una solicitud ambigua.

Eso es seguro, pero existe un caso adicional: si el CUIL aparece en varios contratos, pero sólo uno coincide con el parentesco buscado, la consulta puede devolver una sola fila aunque no coincida con el `contra + inte` informado por la novedad. En ese caso podría generar una solicitud para un contrato incorrecto.

Por eso, técnicamente, la búsqueda más segura sería:

```sql
prepaga + contra + inte + cuil
```

como primera opción. Si no encuentra una única fila, recién entonces utilizar:

```sql
prepaga + cuil + paren
```

y aceptar el resultado sólo si devuelve una única fila vigente.
