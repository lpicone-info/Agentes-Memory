### [21/09/2026 17:29:13] Agente

Cristian, al cargar el número de contrato, el campo **Sueldo Bruto** de la solapa **Deriv. Aportes OS** no se calcula en PowerBuilder.

El flujo es:

1. `wp_solici.srw` obtiene las derivaciones vigentes del contrato mediante:

```powerscript
ds_afi_aportes.Retrieve(
    dw_soli.object.prepaga[1],
    idw_titu.object.contra[1],
    dw_soli.object.fecha[1],
    li_moti
)
```

2. Ese DataWindow utiliza `d_afi_aportes_soli`, que consulta la tabla:

```text
AFI_DERIV_APORTES
```

3. El sueldo se toma de:

```sql
ada.sueldo
```

4. Luego PowerBuilder copia los resultados a la solapa del titular:

```powerscript
idw_aportes.of_append(ds_afi_aportes)
```

La consulta está en `backend/procedures/afs_afi_aportes_soli.sql`, aproximadamente en la línea 38:

```sql
sueldo =
    CASE
        WHEN dbo.fn_get_parametros_general('Afilmed','General','Sueldo') = 'S'
        THEN 0.01
        ELSE ada.sueldo
    END
```

Por eso, cuando el parámetro `Afilmed / General / Sueldo` está en `S`:

- En base puede existir un sueldo real en `AFI_DERIV_APORTES.sueldo`.
- En pantalla el campo **Sueldo Bruto** recibe `0.01`.
- Ese `0.01` es solamente el valor técnico de ocultamiento visual.

Además, cuando se carga un contrato, `wf_verificar_aportes_anteriores` no carga el sueldo: solamente ejecuta `afu_baja_deriv_aportes_antiguos`. La carga del sueldo proviene de `AFI_DERIV_APORTES` mediante `d_afi_aportes_soli`.

Para una solicitud ya existente, la solapa puede recuperar el dato desde `SOLI_DERIV_APORTES`, pero también aplica ocultamiento en `d_soli_deriv_aportes_titu.srd`:

```sql
CASE
    WHEN dbo.afn_soli_deriv_aportes_sueldo(SOLI_DERIV_APORTES.soli) = 'S'
    THEN 0.01
    ELSE SOLI_DERIV_APORTES.sueldo
END
```
