### [21/09/2026 17:28:24] Agente

Hugo, la respuesta correcta es: **es más eficiente para persistencia y escalabilidad, pero no necesariamente más rápido para enviar cada mail**.

Hay que distinguir:

- **Bullzip** genera el PDF localmente. No adjunta el archivo al mail.
- **Blob actual**: el PDF se lee desde disco y se guarda completo en `MAIL_ATTACH_BINARY.email_attach_binary`.
- **API propuesta**: el PDF se sube una vez a la API y en `MAIL_ATTACH_BINARY` se guarda solo `id_archivo_imagen`. Luego Infomailer descarga el archivo desde la API para adjuntarlo.

**Ventajas de la API:**
- Evita almacenar PDFs pesados en la base de datos.
- Reduce escrituras y lecturas BLOB.
- Disminuye el crecimiento de `MAIL_ATTACH_BINARY`.
- Permite reutilizar el archivo y desacoplarlo del proceso de envío.
- Es mejor para lotes grandes o muchos comprobantes.

**Consideración importante:** con el código actual, Infomailer descarga el PDF desde la API a un archivo temporal antes de enviarlo. Por eso agrega una comunicación de red y puede tener algo más de latencia que leer directamente el BLOB.

La arquitectura más conveniente sería:

`Bullzip genera PDF → API almacena PDF → MAIL_ATTACH_BINARY guarda solo la referencia → Infomailer descarga desde API → envío SMTP`

Por lo tanto, mi confirmación es:

**API = más eficiente en almacenamiento, base de datos y procesamiento masivo.**  
**BLOB = potencialmente más rápido en un envío individual, pero más costoso y menos escalable.**

Los objetos que dejamos preparados implementan esta estrategia sin reemplazar Bullzip como generador del PDF.
