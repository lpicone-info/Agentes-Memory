## Hallazgos tecnicos del dia

### Error en `Ospecon_Conta` al generar asientos
- En `wp_conta_asientos_expe.srw`, la llamada a `pri_conta_asientos` usa `@mensaje = :ls_mensaje_aviso OUTPUT`.
- El procedure instalado en BD tiene `@mensaje varchar(8000) OUTPUT`.
- Se reprodujo que SQL Server da error si un parametro `OUTPUT` se invoca como constante/literal, por ejemplo `@mensaje = '' OUTPUT`.
- Hipotesis comunicada: posible desalineacion entre EXE/PBD y version real de BD, o runtime PB/SNC enviando el bind como literal vacio.
- No se ejecuto el SP porque genera/borra asientos contables.

### Error SET options en `Ospecon_Conta`
- En `w_login.srw`, al conectar por `SNC`, la app ejecuta `SET ANSI_WARNINGS OFF` y `SET CONCAT_NULL_YIELDS_NULL OFF`.
- El error reportado exigia `CONCAT_NULL_YIELDS_NULL` y `ANSI_WARNINGS` correctos.
- Hipotesis comunicada: `pri_conta_asientos` o algun objeto consultado toca vista indexada, indice sobre columna calculada, indice filtrado, query notification o similar; SQL Server exige opciones SET ON.
- Correccion sugerida acotada antes de ejecutar `pri_conta_asientos`: prender `ANSI_WARNINGS` y `CONCAT_NULL_YIELDS_NULL`, idealmente el set completo: `ANSI_WARNINGS ON`, `CONCAT_NULL_YIELDS_NULL ON`, `ANSI_NULLS ON`, `QUOTED_IDENTIFIER ON`, `ANSI_PADDING ON`, `ARITHABORT ON`, `NUMERIC_ROUNDABORT OFF`.

### Dialogo seleccion de archivos PB y acceso a RED
- PowerBuilder `GetFileOpenName` / `GetFileSaveName` no tiene parametro confiable para ocultar el nodo moderno `Red` del panel izquierdo; lo administra Windows.
- `OFN_NOLONGNAMES` no aplica; solo tenia objetivo historico de nombres cortos 8.3.
- `OFN_NONETWORKBUTTON` solo afecta boton Network en dialogos clasicos, no oculta nodo `Red` del panel moderno Explorer.
- Respuesta recomendada al cliente: ocultarlo visualmente debe resolverse por politica/configuracion de Windows o selector propio PB; desde PB se puede reforzar bloqueo de uso validando rutas UNC (`\\servidor\...`) y unidades mapeadas con `GetDriveTypeW`, rechazando `DRIVE_REMOTE`.

### Autorizaciones internaciones/cirugias, transicion de circuitos y botones
- Usuario rechazo idea de llamar/recargar `ue_getauto` dentro de `ue_grabar` porque ejecuta demasiada logica adicional.
- En prestaciones, `w_clase_auto.srw` para tipo `P` luego de grabar restaura y fuerza `itemchanged` del numero de autorizacion, refrescando protecciones.
- Internaciones/cirugias usan override propio en `w_clase_auto_internacion.srw`; manejan `dw_inter`, `esta_inter`, salas, carencias y estado cabecera.
- `wf_proteger_auto` esta sobrecargada en `w_clase_auto_internacion.srw`; llama a `super::wf_proteger_auto(...)` y luego protege `dw_inter`.
- En internaciones/cirugias `wf_proteger_auto` se dispara principalmente desde el `itemchanged` del campo `auto` cuando `ue_gettipo()` es `C`, `I` o `X`.
- Si la ventana de transicion de circuitos cambia estado/sector sin disparar `itemchanged` de `auto`, no vuelve a ejecutar proteccion y no bloquea botones segun sector.
- Correccion recomendada: no llamar `ue_getauto`; postear un evento acotado despues de transicion, por ejemplo `ue_proteger_post_transicion`, que llame solo `wf_proteger_auto(dw_auto.object.sucur[1], dw_auto.object.auto[1], 'S', 'I')` en `w_clase_auto_internacion`, cubriendo internaciones, cirugias y tipo `X`.
- Funcion de apagado general de botones en autorizaciones: `wf_setbotonesoff()` en `w_clase_auto.srw`.
- Sector de usuario se carga en login desde `zz_usuari.sector` a global `gi_usuari_sector` en `w_login.srw`.
- Solucion final validada por Cristian para RM30027 en `wp_auto_cirugias.ue_grabar`: antes de disparar manualmente `itemchanged` de `sucur` y `auto`, ejecutar `dw_auto.SetItem(1, 'sucur', li_sucur)` y `dw_auto.SetItem(1, 'auto', ll_auto)`. Motivo: el `itemchanged` heredado de `w_clase_auto` usa `THIS.GetItemNumber(...)`; si solo se pasa `data` al evento manual, el buffer del DataWindow puede seguir nulo despues de `ue_restaurar`.
