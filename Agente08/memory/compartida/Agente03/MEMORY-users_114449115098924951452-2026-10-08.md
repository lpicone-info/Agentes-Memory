## Opciones posibles

### Opción 1 — Ruta absoluta configurable

Agregar a `logos`:

```text
logo_path
logo_creden_path
```

`Utiles` permitiría seleccionar un `.png` y guardar la ruta:

```text
\\servidor\logos\cliente_a\logo.png
```

El proceso de impresión:

1. Lee la ruta.
2. Verifica `FileExists`.
3. Usa el archivo externo.
4. Si no existe, usa el BLOB actual.
5. Si tampoco existe, muestra un logo predeterminado.

**Ventajas**

- Implementación sencilla.
- Los clientes administran directamente sus archivos.
- No requiere incrustar imágenes en `ilus.pbl`.
- Permite migración gradual.

**Riesgos**

- Una ruta local puede no existir en otro puesto.
- El proceso de impresión, generación PDF o envío automático debe ejecutarse con acceso a esa ruta.
- Las rutas UNC requieren permisos y disponibilidad de red.

No recomendaría guardar rutas locales como `C:\...` si la impresión puede ejecutarse en servidores o procesos automáticos.

---

### Opción 2 — Copia administrada a una carpeta estándar

El cliente selecciona el archivo desde `Utiles`, pero el sistema lo copia a una ubicación estándar:

```text
<directorio de datos>\logos\<prepaga>.png
```

En la base se guarda solamente:

```text
logo_file_name = 'prepaga_123.png'
```

El sistema resuelve la ruta en tiempo de ejecución.

**Ventajas**

- Evita rutas absolutas diferentes por puesto.
- El cliente no necesita administrar manualmente la estructura interna.
- Permite validar y normalizar el archivo al momento de guardarlo.
- Es más estable para impresión y PDF.

**Riesgos**

- Hay que definir una carpeta accesible desde todos los equipos que imprimen.
- Se debe contemplar respaldo y permisos.
- Si existen varios servidores de impresión, la carpeta debe ser compartida o sincronizada.

Esta es más segura que guardar directamente una ruta escrita por el usuario.

## Recomendación

Implementaría una combinación de las opciones **2 y 3**:

```text
Utiles selecciona imagen
        ↓
Valida formato, tamaño y dimensiones
        ↓
Copia a carpeta compartida de logos
        ↓
Guarda sólo el nombre o ruta relativa
        ↓
Impresión busca archivo externo
        ↓
Si falla, utiliza el BLOB actual
```

La estructura mínima podría ser:

```sql
logo_path varchar(500) null
logo_creden_path varchar(500) null
```

No eliminaría inicialmente:

```text
logos.logo
logos.logo_creden
```

porque funcionan como respaldo y permiten una migración sin riesgo.

## Adaptación del tamaño

No conviene limitar solamente el tamaño en KB. Un PNG de pocos KB puede tener dimensiones enormes.

La validación debería contemplar:

- Extensión permitida.
- Tamaño máximo del archivo.
- Ancho máximo en píxeles.
- Alto máximo en píxeles.
- Relación de aspecto.
- Imagen válida y no corrupta.
- Transparencia permitida.
- Resolución adecuada para impresión.

### Alternativa A — Rechazo

El sistema acepta solamente imágenes que entren en el rectángulo del logo.

Ejemplo:

```text
Ancho máximo: 800 px
Alto máximo: 300 px
Tamaño máximo: 2 MB
```

Es simple, pero obliga al cliente a editar previamente la imagen.

### Alternativa B — Redimensionamiento automático

Al guardar el logo, `Utiles` genera una copia normalizada:

```text
logo_original.png
logo_normalizado.png
```

La copia normalizada:

- Mantiene la proporción.
- Se reduce si excede el área.
- No se amplía si es demasiado pequeña.
- Se centra sobre un lienzo transparente.
- Se guarda en el tamaño esperado por el comprobante.

Esta es la mejor experiencia para los clientes.

### Alternativa C — Escalado en el DataWindow

El archivo se asigna al bitmap y se deja que el DataWindow lo muestre dentro de su área.

Es la opción de menor esfuerzo, pero requiere verificar en PowerBuilder:

- cómo se escala el bitmap;
- si conserva o distorsiona la proporción;
- si funciona igual con impresión física, PDF nativo y Bullzip;
- si el comportamiento es igual en todos los `d_factura%`.

Por eso no la usaría como única garantía.

## Cambio técnico en los DataWindows

Actualmente `d_logo_factu` utiliza:

```text
tableblob ... name=blob_1
```

Para usar archivos externos habría que reemplazarlo por un objeto bitmap con `filename`, o crear un nuevo DataWindow común, por ejemplo:

```text
d_logo_factu_ext
```

Luego, desde el proceso común de impresión, cargar dinámicamente el archivo externo antes del `Retrieve`.

El punto que debe probarse en un prototipo es la asignación dinámica de la propiedad `filename` del bitmap dentro de un DataWindow anidado. En ventanas PowerBuilder ya existe el patrón de asignar dinámicamente `PictureName`, pero no encontré todavía un ejemplo equivalente consolidado para un bitmap de DataWindow.

## Consideración importante sobre `.pic`

Recomiendo priorizar:

```text
.PNG
.JPG
.JPEG
```

El formato `.pic` debe validarse específicamente con la versión de PowerBuilder y con los motores de impresión utilizados. No lo habilitaría como formato general hasta confirmar que funciona correctamente en:

- vista previa;
- impresión;
- PDF nativo;
- envío por mail;
- ejecución desatendida.

## Solución final recomendada

```text
Utiles
  ├─ Selección del PNG/JPG
  ├─ Validación de formato y dimensiones
  ├─ Redimensionamiento automático
  └─ Copia a carpeta compartida

Base de datos
  ├─ logo_path
  ├─ logo_creden_path
  └─ BLOB existente como fallback

Impresión
  ├─ Busca archivo externo
  ├─ Carga bitmap del DataWindow
  ├─ Genera comprobante/PDF
  └─ Si falla, usa BLOB o logo predeterminado
```

Con este diseño los clientes pueden administrar sus logos sin modificar `ilus.pbl`, se evita cargar el BLOB en cada comprobante y se mantiene compatibilidad con los clientes que aún no hayan migrado.
