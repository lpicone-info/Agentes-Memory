**Cómo impacta funcionalmente el Período**

El período cargado no se usa como “hasta” ni como rango. Se usa como **mes exacto**, representado por el día 1 del mes.

Según parametrización general de `Afilmed / Aportes Exportar`, el SP puede trabajar de dos formas:

- Si el parámetro **“En la exportacion de aportes de la OS”** vale `A`, se considera el **período propio del aporte**. En ese caso filtra registros con condiciones del tipo:
  - `APR.periodo = @prm_perio`
  - `aad.periodo = @prm_perio`
  - `aaj.periodo = @prm_perio`
  - `aad.periodo = @prm_perio`

- Si ese parámetro vale `C`, se considera el **período de la cabecera/lote del archivo importado**. En ese caso primero busca lotes de `afi_aportes_pre_lote` y `afi_aportes_real_lote` cuyo `control_archivo` o `periodo` correspondan al año/mes ingresado, y después toma los aportes contenidos en esos lotes. En esta modalidad puede exportar aportes cuyo `periodo` de detalle sea el del registro original, pero el lote fue seleccionado por el período de cabecera.

Además, el período se usa para validar vigencias al momento del mes exportado:

- afiliados: se consideran activos si no están dados de baja o si su baja es posterior/al menos vigente al período, según el tramo del SP.
- derivación de aportes (`afi_deriv_aportes`): se toma la vigente a ese período, con `vigen_desde <= @prm_perio`, `vigen_hasta > @prm_perio` y baja posterior al período.
- prestador externo (`afi_prestador_externo`): también se evalúa vigente para ese período, con `vigen_desde <= @prm_perio`, `vigen_hasta > @prm_perio` y sin baja.

La lógica relevante para `afi_aportes_pre.origrect` está en `afs_afi_aportes_export.sql`, bloque `@var_ddjj_tran = 'D'` y `@var_ddjj_tran_periodo = 'C'`.

Condición base para que un registro `afi_aportes_pre` sea candidato:

- pertenece a un lote preseleccionado en `#tmp_lotes` como tipo `PRE`
- `APRE.baja_fecha IS NULL`
- coincide con afiliado por `prepaga`, `contra`, `cuil`
- el afiliado no está dado de baja antes del período buscado
- no existe ya en la temporal otro registro para el mismo `cuit`, `cuil` y `periodo`
- pasa la evaluación de `origrect`

La evaluación de `origrect` se resume así:

```sql
CASE
  WHEN APRE.origrect > 0
       AND (
            existe otro APRE2 del mismo prepaga/contra/cuil/período,
            en lotes preseleccionados,
            con origrect menor
            OR
            no existe otro APRE2 del mismo prepaga/contra/cuil/período,
            en lotes preseleccionados,
            con origrect mayor
       )
       AND no existe otro APRE2 del mismo prepaga/contra/cuil,
           con período menor al período de pantalla,
           y origrect menor
    THEN exporta

  WHEN APRE.origrect = 0
    THEN exporta

  ELSE no exporta
END
```

Punto importante: en las comparaciones de `origrect`, el código compara por `prepaga`, `contra`, `cuil` y `periodo`, pero **no compara `cuit`**. Para la validación anti-duplicado en la temporal sí usa `cuit`, `cuil` y `periodo`.

**Simulación de casos**

Caso 1: un solo registro para mismo `cuil`, `cuit`, `periodo`, con `origrect = 0`.

Resultado: **se exporta**.

Motivo: entra por la rama directa `WHEN APRE.origrect = 0 THEN 1`. No necesita que existan otros registros rectificativos.

Caso 2: un solo registro para mismo `cuil`, `cuit`, `periodo`, con `origrect > 0`, por ejemplo `origrect = 1`.

Resultado: **se exporta solo si no existe un registro anterior al período de pantalla con `origrect` menor para ese mismo `prepaga/contra/cuil`**.

Motivo: como no hay otro registro mayor dentro de los lotes preseleccionados para el mismo período, cumple la condición “no existe mayor”. Pero además debe pasar el segundo control: que no haya un aporte de período menor a `@prm_perio` con `origrect` menor.

Caso 3: dos registros en lotes preseleccionados para mismo `cuil`, `cuit`, `periodo`: `origrect = 0` y `origrect = 1`.

Resultado esperado por la condición: **ambos son exportables por `origrect`**.

Motivo: el `origrect = 0` entra siempre. El `origrect = 1` ve que existe uno menor (`0`) para el mismo período dentro de los lotes preseleccionados, por lo tanto también pasa la primera parte. Después puede ser excluido solo si encuentra un registro de período anterior al de pantalla con `origrect` menor.

En la salida agrupada, si ambos llegan a `temp_afi_export` con mismo `periodo/cuit/cuil`, la grilla de exportación suma el `valor`.

Caso 4: dos registros en lotes preseleccionados para mismo `cuil`, `cuit`, `periodo`: `origrect = 1` y `origrect = 2`.

Resultado: **se exportan ambos, salvo exclusión por registros de períodos anteriores**.

Motivo: `origrect = 1` pasa porque no existe uno mayor? En realidad sí existe `2`, entonces esa parte no le alcanza; pero si existe uno menor no pasaría. Para `1`, no hay menor y sí hay mayor, por lo tanto **no pasa**. Para `2`, sí existe uno menor (`1`), entonces pasa.  
Corrección funcional fina: con la dupla `1` y `2`, exporta **solo `2`**, salvo que la existencia de períodos anteriores con menor `origrect` lo excluya.

Caso 5: tres registros en lotes preseleccionados para mismo `cuil`, `cuit`, `periodo`: `origrect = 1`, `2`, `3`.

Resultado: **exportan `2` y `3`; no exporta `1`**.

Motivo: `1` tiene un mayor y no tiene menor, entonces no pasa. `2` y `3` tienen al menos un menor, por lo que pasan la primera parte. Después ambos pueden caer por el control de períodos anteriores si existiera un registro anterior con `origrect` menor.

Caso 6: registros `origrect = 0`, `1`, `2`.

Resultado por `origrect`: **exportan `0`, `1` y `2`**, salvo que `1` o `2` sean excluidos por registros de períodos anteriores.

Motivo: `0` entra siempre; `1` y `2` encuentran un menor dentro del mismo período/lotes preseleccionados.

Conclusión funcional: con parámetro `C`, el sistema selecciona DDJJ por **lote de cabecera del mes de pantalla**, no necesariamente por el período propio del aporte. Dentro de esos lotes, `origrect = 0` siempre queda exportable; para `origrect > 0`, el sistema intenta resolver rectificativas comparando valores de `origrect`, pero la lógica no se limita estrictamente a “exportar solo el mayor”: si hay `0`, pueden pasar también las rectificativas mayores, y si hay una secuencia `1,2,3`, pasan `2` y `3`. Luego la grilla final agrupa por `periodo/cuit/cuil` y suma valores.
