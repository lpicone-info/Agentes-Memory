### [30/10/2026 14:34:29] Agente

Facundo, la captura confirma la causa: el mensaje se genera **antes de ejecutar la búsqueda**, durante la validación del campo integrante.

## Causa técnica

En el evento `ItemChanged` de `dw_filtro`, al modificar `contra` o `inte`, la ventana recupera los valores almacenados en el DataWindow:

```powerscript
ls_contra = THIS.object.contra[1]
ls_inte   = THIS.object.inte[1]
```

Cuando se termina de escribir `00`, el evento todavía conserva en el buffer el valor anterior del integrante —vacío— y no utiliza el nuevo valor disponible en `data`.

Además, esta condición es incorrecta:

```powerscript
IF ls_inte <> '' OR NOT IsNull(ls_inte) THEN
```

Para una cadena vacía no nula, la condición resulta verdadera. Por eso llama al validador con:

```text
Entidad:   2
Contrato:  344939911
Integrante: vacío
```

El validador devuelve `Afiliado inexistente`. Después de cerrar el mensaje, el código limpia contrato, integrante y nombre.

Referencia: [wp_auto_pedidos.srw](/home/desarrollo-ia-07/.openclaw/workspace/svn/mpariso-V25.08.001/exe/Source%20Infomedical/wp_auto_pedidos.srw:1039).

## Evidencia de que el afiliado existe

```text
Entidad:    2
Contrato:   344939911
Integrante: 00
Afiliado:   PARETTI, EMILIO
Alta:       01/06/2025
Baja:       NULL
```

Ejecutando directamente `prs_auto_pedidos` con esos datos, devuelve correctamente:

```text

```

## Conclusión

El caso de búsqueda por contrato e integrante de R29455 **no funciona en esta ventana** por un defecto en el evento `ItemChanged`. No es un problema de datos ni del procedimiento `prs_auto_pedidos`.

La corrección debe hacer que, al validar el integrante:

- se utilice el nuevo valor `data`, o se acepte previamente en el DataWindow;
- no se invoque el validador con integrante vacío;
- se reemplace la condición lógica incorrecta que usa `OR`.

No modifiqué código ni datos.
