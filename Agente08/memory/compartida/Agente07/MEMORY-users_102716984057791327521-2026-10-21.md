```sql
contra = solicitud.contra

baja_fecha IS NULL
```

## Qué representa realmente “Cuota”

Técnicamente, no se recupera exclusivamente un concepto `CUO`. Se suman **todas las filas activas de PREFacturas** para el contrato y período:

```sql
SUM(P.impor)
```

Por lo tanto, el dato representa el **total neto de la prefactura**, pudiendo incluir:

- Cuota.
- Familiares.
- Adicionales.
- Descuentos.
- Aportes estimados.
- Bonificaciones.
- Otros conceptos positivos o negativos.

El plan se determina y muestra por separado; no interviene directamente en el cálculo de la columna Cuota.

## Riesgos observados

1. **Más de una prefactura activa en el mismo período**

   El SP calcula `MAX(prefac)`, pero no usa ese número para limitar la suma. Si existen dos prefacturas activas para el mismo contrato y período, suma los ítems de ambas.

2. **Nombre potencialmente confuso**

   La columna se llama `cuota`, pero contiene el total de `PREFacturas.impor`, no solamente el concepto de cuota.

3. **Ausencia de prefacturación**

   Si no existe una prefactura vigente que cumpla el criterio temporal, la cuota queda en `NULL`.

4. **Comparación directa de fechas**

   `factu_perio` se compara directamente con `apli_fecha`. El funcionamiento esperado presupone que la fecha de aplicación se maneja como período o con una fecha compatible con el inicio del mes.

