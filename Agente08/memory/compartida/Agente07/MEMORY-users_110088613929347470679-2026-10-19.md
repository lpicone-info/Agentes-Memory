## Condiciones generales para consumir un tope

Antes de acumular consumos, el sistema determina:

1. Que la cobertura pertenezca a un registro vigente de `TOPES`.
2. Que el grupo sea de tipo:
   ```text
   GRUPOS.tipo = 'T'
   ```
3. Que `TOPES` y `GRUPOS` no estén dados de baja para la fecha evaluada.
4. Si el tope se controla:
   - por prestación exacta;
   - o por todas las prestaciones integrantes del grupo.
5. Si el consumo es:
   - individual: solamente el integrante;
   - grupal: todos los integrantes del contrato.
6. El período que corresponde controlar:
   - calendario;
   - aniversario/vigencia del contrato;
   - desde la última prestación consumida.
7. Si el afiliado está eximido por situación terapéutica.

## Qué operaciones se consideran consumidas

### 1. Autorizaciones

Una prestación consume cuando:

```text

```

No se exige:

```text

```

|---|---:|---:|
| `A` | `A` | Sí |
| `R` | `A` | **Sí** |
| `P` | `A` | **Sí** |
| Cualquiera | `R` | No |
| Cualquiera | `P` | No |

La autorización que se está validando se excluye del histórico para no sumarla dos veces.

## 2. Liquidaciones — Expedientes de órdenes

Una orden histórica consume cuando:

```text
EXPEDIENTES.liqui_fecha IS NOT NULL
EXPE_ORDEN_ITEMS.ok = 'S'
    o existe un error validado que no debitó totalmente la prestación
EXPE_ORDENES.rea_fecha dentro del período
EXPE_ORDENES.prepaga/contra coinciden
EXPE_ORDENES.auto IS NULL
EXPE_ORDENES.baja_fecha IS NULL
EXPE_ORDEN_ITEMS.baja_fecha IS NULL
EXPE_ERRORES.baja_fecha IS NULL
prestación o grupo coincide
```

`EXPE_ORDENES.auto IS NULL` evita volver a contar como expediente una prestación que ya fue contabilizada desde una autorización.

### Débitos

- Ítem válido `ok = 'S'`: consume.
- Error validado sin débito total: continúa consumiendo.
- Débito total de la prestación: no consume.
- Débito parcial: mantiene el consumo correspondiente según los valores registrados en `EXPE_ERRORES`.

### Expediente todavía no liquidado

Normalmente, un expediente histórico requiere:

```text
liqui_fecha IS NOT NULL
```

Pero mientras se controla un expediente en carga, el procedimiento incorpora también **los demás ítems del mismo expediente todavía no liquidado**, excluyendo el ítem/orden que se está evaluando.

Por lo tanto:

```text
Expediente no liquidado ajeno al actual → no consume
Otros ítems del mismo expediente en carga → pueden intervenir en el cálculo
Expediente liquidado → consume históricamente
```
