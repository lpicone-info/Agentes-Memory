Facundo, para aplicar el filtro **Clase** de R30017, el proceso debe partir de `PEDIDOS` y localizar la clase vigente del contrato en `AFI_CLASE`.

## Tablas y campos

### `PEDIDOS`

```text
PEDIDOS.prepaga
PEDIDOS.contra
PEDIDOS.inte
```

`prepaga` y `contra` identifican el contrato. `inte` no interviene en la búsqueda de la clase.

### `AFI_CLASE`

```text
AFI_CLASE.prepaga
AFI_CLASE.contra
AFI_CLASE.clase_afi
AFI_CLASE.vigen_desde
AFI_CLASE.baja_fecha
AFI_CLASE.alta_fecha
```

Valores de `clase_afi`:

```text
D = Directos
E = Empresas
```

La opción `T = Todos` pertenece al filtro y no es una clase almacenada.

## Relación

```text
PEDIDOS.prepaga = AFI_CLASE.prepaga
PEDIDOS.contra  = AFI_CLASE.contra
```

No debe relacionarse por integrante ni necesita utilizarse `AFILIADOS` para obtener la clase.

## Proceso de búsqueda

1. Tomar `PEDIDOS.prepaga` y `PEDIDOS.contra`.
2. Buscar en `AFI_CLASE` los registros del contrato.
3. Considerar únicamente registros:
   - con `vigen_desde` menor o igual a la fecha de ejecución;
   - con `baja_fecha IS NULL`.
4. Si hay más de uno, seleccionar el de mayor `vigen_desde`.
5. Comparar `AFI_CLASE.clase_afi` con el filtro seleccionado.
6. Si se selecciona **Todos**, no restringir los pedidos por clase.

La “fecha de búsqueda” debe ser la fecha de ejecución del proceso:

```sql
SET @var_hoy = GETDATE()
```

No corresponde utilizar la fecha del pedido ni las fechas Desde/Hasta del filtro.

## Implementación recomendada

```sql
OUTER APPLY
(
    SELECT TOP 1
           AC.clase_afi,
           AC.cuenta,
           AC.subcta
    FROM AFI_CLASE AC
    WHERE AC.prepaga = P.prepaga
      AND AC.contra = P.contra
      AND AC.vigen_desde <= @var_hoy
      AND AC.baja_fecha IS NULL
    ORDER BY AC.vigen_desde DESC,
             AC.alta_fecha DESC
) CLASE
```

Se recomienda `OUTER APPLY` porque:

- obtiene un único registro histórico;
- evita duplicar pedidos;
- permite mantener pedidos sin clase cuando se selecciona **Todos**.

## Condición del filtro

Parámetro:

```sql
@prm_clase_afi CHAR(1) = 'T'
```

Condición:

```sql
AND
(
    @prm_clase_afi = 'T'
    OR CLASE.clase_afi = @prm_clase_afi
)
```

Resultado esperado:

```text
Todos    (T): no restringe por AFI_CLASE.clase_afi
Directos (D): AFI_CLASE.clase_afi = 'D'
Empresas (E): AFI_CLASE.clase_afi = 'E'
```

Si el contrato no tiene una clase vigente:

- con **Todos**, el pedido permanece en el resultado;
- con **Directos** o **Empresas**, el pedido queda excluido.
