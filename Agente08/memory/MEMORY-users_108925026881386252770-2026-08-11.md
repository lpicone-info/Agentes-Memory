Ro, la diferencia es esta:

La **base** tiene datos, tablas, parámetros, SP, configuración y estructura. El **EXE/PBD** tiene la lógica del sistema que lee esa base y decide qué validar, qué mostrar, qué grabar y cómo ejecutar cada proceso.

Entonces puede pasar esto:

```text
Base nuestra Prod: correcta
Base cliente Prod: correcta o similar
Pero EXE/PBD cliente: distinto o viejo
Resultado: el cliente ve un error que nosotros no reproducimos
```

En PowerBuilder esto es muy importante porque muchas reglas no están solo en la base. Pueden estar compiladas dentro de una `PBD`, por ejemplo en eventos de ventanas, funciones, DataWindows o validaciones previas a ejecutar un SP.

El caso de Igualdad fue justamente eso: la base no explicaba el problema. Al comparar los ejecutables/paquetes, se vio diferencia en las `PBD`, especialmente `liqui06.pbd`. La versión que funcionaba tenía lógica relacionada con el campo `Lugar`, y el paquete del cliente no estaba alineado. Por eso en nuestra prueba no fallaba y en el cliente sí.

Para diagnosticar bien estos casos hay que validar siempre dos capas:

```text
1. Base: parámetros, tablas, datos, SP, estructura.
2. Binarios: EXE y PBD que realmente está usando el cliente.
```

Si la base está igual pero el comportamiento cambia, hay que pedir el paquete del cliente y compararlo contra la versión que funciona. En sistemas PowerBuilder, una diferencia de `PBD` puede cambiar completamente el comportamiento aunque la base sea la misma.
