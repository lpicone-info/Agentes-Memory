### Dónde impacta en Presmed

   - Se toma el prestador efectivo de la transacción remota.
   - Se actualiza `pago_copa` tanto en la cabecera como en los ítems.
   - Si el prestador no tiene configuración, se conserva el criterio general de WebPos o el calculado originalmente.

### Precedencia

La lógica aplicada es:

1. Se calcula el copago y su forma de pago según plan, cobertura, prestación, grupo o convenio.
2. Se consulta si el prestador tiene una configuración vigente.
3. Si existe, **el criterio del prestador tiene prioridad**.
4. Si no existe o fue dado de baja, se mantiene el criterio original.

### Qué no modifica

Esta configuración **no cambia el importe del copago**. Solo determina si ese importe:

- se paga directamente al prestador; o
- se debita en la cuenta del afiliado.
