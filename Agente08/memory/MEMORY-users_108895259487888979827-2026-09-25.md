## Determinación para topes

Para topes se utiliza `prs_histo_auto_remotas`, cuyo orden de preferencia es:

1. Situaciones con `gene_topes = 'N'` y `paga_copago = 'N'`.
2. Si no encontró ninguna, situaciones con `gene_topes = 'N'`.
3. Si tampoco encontró, situaciones con `paga_copago = 'N'`.

Dentro de cada situación toma su historia de mayor `fecha`, pero cuando hay varias situaciones dentro del mismo nivel:

- no usa `TOP 1`;
- no usa `ORDER BY`;
- no compara prioridades;
- no elige explícitamente el mayor `histo`.

Por lo tanto, **no existe una prioridad determinística entre situaciones equivalentes**. La historia finalmente asignada depende del plan de ejecución y del orden en que SQL Server entregue las filas.

## Conclusión

WebPos **no establece una única “situación terapéutica más prioritaria”**:

- Para copagos prioriza el mayor `histo`.
- Para topes prioriza combinaciones de `gene_topes` y `paga_copago`, pero no desempata cuando hay varias situaciones equivalentes.
- Las prestaciones exceptuadas no se consolidan entre todas las situaciones vigentes.
- Copagos y topes pueden quedar determinados por historias diferentes.

Si la regla funcional esperada es que una prestación quede exceptuada cuando aparece en **cualquiera** de las situaciones terapéuticas vigentes del afiliado, la implementación actual no garantiza ese comportamiento. La corrección debería evaluar la prestación contra el conjunto completo de situaciones vigentes o definir una prioridad funcional explícita y determinística.

DECLARE @prepaga SMALLINT
DECLARE @solo_default_existente_al_asignar_plan CHAR(1)

-- Fecha para evaluar la vigencia
SELECT @fecha_corte =
       CONVERT(DATETIME, CONVERT(CHAR(8), GETDATE(), 112), 112)

-- NULL consulta todas las entidades
SELECT @prepaga = NULL

/*
N: compara contra toda la configuración actualmente vigente
S: considera únicamente adicionales que ya estaban configurados
   cuando se asignó el plan principal al contrato
*/
SELECT @solo_default_existente_al_asignar_plan = 'N'

SELECT COUNT(*) OVER() AS total_detectado,
       a.prepaga AS entidad,
       pr.exten_deno AS entidad_deno,
       a.contra AS contrato,
       a.inte AS integrante,
       a.ape AS apellido,
       a.nombre,
       ap.plan_codi AS plan_principal,
       pp.deno AS plan_principal_deno,
       ap.vigen_desde AS vigencia_plan_principal,
       pad.plan_adic AS plan_adicional_faltante,
       pa.deno AS plan_adicional_deno,
       pad.tari AS tarifa_esperada,
       pad.alta_fecha AS alta_configuracion_default
FROM afiliados a

INNER JOIN afi_planes ap
        ON ap.prepaga = a.prepaga
       AND ap.contra = a.contra
       AND ap.vigen_desde <= @fecha_corte
       AND (ap.baja_fecha IS NULL
            OR ap.baja_fecha > @fecha_corte)
       AND ap.vigen_desde = (
             SELECT MAX(ap2.vigen_desde)
             FROM afi_planes ap2
             WHERE ap2.prepaga = ap.prepaga
               AND ap2.contra = ap.contra
               AND ap2.vigen_desde <= @fecha_corte
               AND (ap2.baja_fecha IS NULL
                    OR ap2.baja_fecha > @fecha_corte)
       )

INNER JOIN plan_adic_defaults pad
        ON pad.prepaga = ap.prepaga
       AND pad.plan_codi = ap.plan_codi
       AND pad.alta_fecha <= @fecha_corte
       AND (pad.baja_fecha IS NULL
            OR pad.baja_fecha > @fecha_corte)

INNER JOIN prepagas pr
        ON pr.prepaga = a.prepaga

LEFT JOIN planes pp
       ON pp.prepaga = ap.prepaga
      AND pp.plan_codi = ap.plan_codi

LEFT JOIN planes pa
       ON pa.prepaga = pad.prepaga
      AND pa.plan_codi = pad.plan_adic

WHERE (@prepaga IS NULL OR a.prepaga = @prepaga)

  -- Afiliado activo a la fecha de corte
  AND a.alta_fecha <= @fecha_corte
  AND (a.baja_fecha IS NULL

  -- Permite excluir configuraciones creadas después

ORDER BY a.prepaga,

         a.inte,

DECLARE @prepaga SMALLINT

SELECT @plan_principal = NULL

SELECT pad.prepaga AS entidad,
       pad.plan_codi AS plan_principal,
       pp.deno AS plan_principal_deno,
       pad.plan_adic AS plan_adicional,
       pa.deno AS plan_adicional_deno,
       pad.tari AS tarifa_adicional,
       pad.alta_fecha,
       pad.baja_fecha
FROM plan_adic_defaults pad

LEFT JOIN planes pp
       ON pp.prepaga = pad.prepaga
      AND pp.plan_codi = pad.plan_codi

LEFT JOIN planes pa
       ON pa.prepaga = pad.prepaga
      AND pa.plan_codi = pad.plan_adic

WHERE pad.prepaga = @prepaga

       OR pad.plan_codi = @plan_principal)
