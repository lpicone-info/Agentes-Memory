## Descripción simple para documentar

### Procesamiento de rechazados de una presentación SSS

La opción **Procesar Rechazados** permite importar el archivo de registros rechazados que devuelve la Superintendencia después de presentar un padrón.

El botón solamente se habilita cuando se selecciona el **último lote exportado** de la entidad.

Al procesarlo, el sistema:

1. Solicita seleccionar el archivo TXT de rechazados.
2. Lee todas sus líneas según el formato configurado para este tipo de archivo.
3. Busca cada registro dentro del último lote presentado.
4. Para identificarlo compara:
   - lote;
   - período informado;
   - código de entidad;
   - CUIL titular;
   - CUIT;
   - tipo de movimiento.
5. Guarda el código de rechazo informado por la SSS.

### Tratamiento según el movimiento

| Movimiento rechazado | Acción realizada |
|---|---|
| **Alta (A)** | Guarda el código de error y marca como dado de baja el registro de la presentación. Esto no da de baja al afiliado: solamente invalida ese registro dentro del padrón presentado. |
| **Baja (B)** | Mantiene el registro y solamente guarda el código de error. |
| **Modificación (M)** | Mantiene el registro y solamente guarda el código de error. |

Una **Alta rechazada** deja de considerarse parte válida del padrón presentado. Si el afiliado continúa activo, puede volver a generarse como Alta en una presentación posterior.

Cuando termina el procesamiento, la pantalla vuelve a consultar el lote para mostrar su estado actualizado y deshabilita el botón.

## Observaciones técnicas importantes

1. **La validación de entidad no funciona correctamente.**  
   El procedimiento compara el código de entidad consigo mismo:

   `u.cod_enti <> u.cod_enti`

   Esa condición nunca puede cumplirse. Por lo tanto, el mensaje *“El archivo no corresponde a la entidad”* nunca se genera mediante esa validación.

2. **No se utiliza el CUIL del familiar para identificar el registro.**  
   Aunque el archivo contiene `cuil_fam`, la actualización compara solamente el CUIL titular, CUIT y movimiento. Si existen varios integrantes asociados al mismo titular, CUIT y movimiento, el proceso no permite distinguirlos de manera individual y podría aplicar el rechazo a más de un registro.
