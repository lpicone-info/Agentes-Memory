## ¿Está bien insertar las dos?

No se debe decidir sólo técnicamente. Hay tres posibilidades funcionales:

### 1. Representan una única prestación lógica

Entonces debe insertarse **una sola fila**, pero hay que definir cuál prevalece:

- ¿La que tiene `auto` informado?
- ¿La que tiene `egreso IS NULL`, es decir, la vigente?
- ¿La que tiene mayor fecha?
- ¿La de internación o la ambulatoria?
- ¿La que tiene mayor cantidad/días?

No conviene usar `TOP 1` sin criterio porque podría descartar información incorrectamente.

### 2. Ambas representan actividad acumulable

Entonces no hay que descartar una, sino consolidarlas:

```text
canti       = SUM(canti)
dias        = SUM(dias)
dias_ingre  = criterio funcional
egreso      = criterio funcional
auto        = criterio funcional
ambu_inter  = criterio funcional
```

Esto sólo es correcto si los reportes ANSSAL esperan cantidades y días acumulados.

### 3. Son dos eventos independientes

Entonces la clave primaria actual es [SECRETO REDACTADO]

```text
item_tipo
auto
ambu_inter
```

Eso implicaría modificar:

- la clave primaria de `in_sum_reg_anssal`;
- `in_sum_reg_anssal_censos`;
- los procedimientos `ins_anssal_form060/070/080/090`;
- consultas y reportes consumidores;
- procesos de borrado y regeneración.

Es la alternativa de mayor impacto y no la recomendaría sin confirmar que los formularios deben mostrar ambas filas separadamente.

## Recomendación

La alternativa más segura es:

1. Confirmar funcionalmente que ambas filas corresponden a la misma línea lógica.
2. Definir una prioridad determinista, por ejemplo:
   - conservar el registro vigente (`egreso IS NULL`);
   - si ambos están vigentes, priorizar el que tenga `auto` informado;
   - si persiste el empate, usar un criterio estable.
3. Aplicar esa selección antes del `INSERT`, mediante `ROW_NUMBER()`.
4. Agregar una detección de duplicados previa para que el proceso informe el caso en vez de fallar silenciosamente.

Ejemplo conceptual:

```sql
ROW_NUMBER() OVER (
    PARTITION BY perio, ofi, expe, item, orden,
                 prepaga, contra, inte, nomen,
                 prestac, inter_sala
    ORDER BY
        CASE WHEN egreso IS NULL THEN 0 ELSE 1 END,
        CASE WHEN auto IS NOT NULL THEN 0 ELSE 1 END
)
```

Y luego insertar únicamente `rn = 1`, **pero sólo después de que el área funcional confirme esa prioridad**.

La definición funcional que falta es:

> Cuando existen varias filas para la misma clave ANSSAL, ¿deben consolidarse, debe prevalecer una de ellas, o deben conservarse ambas ampliando la clave?

Hasta resolver eso, no es correcto elegir arbitrariamente una fila ni modificar la clave primaria.
