assistant: Marcelo, sí: en PowerBuilder se puede cubrir, pero con una salvedad importante.

**Para conexión nativa PB contra SQL Server**, la forma más controlada es ejecutar los `SET` inmediatamente después del `CONNECT USING SQLCA`, sobre la misma conexión:

```powerscript
CONNECT USING SQLCA;

IF SQLCA.SQLCode = 0 THEN
   EXECUTE IMMEDIATE "SET ANSI_NULLS ON" USING SQLCA;
   EXECUTE IMMEDIATE "SET ANSI_WARNINGS ON" USING SQLCA;
   EXECUTE IMMEDIATE "SET QUOTED_IDENTIFIER ON" USING SQLCA;
   EXECUTE IMMEDIATE "SET CONCAT_NULL_YIELDS_NULL ON" USING SQLCA;
   EXECUTE IMMEDIATE "SET ARITHABORT ON" USING SQLCA;
   EXECUTE IMMEDIATE "SET ANSI_PADDING ON" USING SQLCA;
   EXECUTE IMMEDIATE "SET NUMERIC_ROUNDABORT OFF" USING SQLCA;
END IF
```

Para índices filtrados, XML, indexed views o índices sobre columnas computadas, yo no dejaría solo esos cuatro. SQL Server exige el set completo: `ANSI_NULLS ON`, `ANSI_PADDING ON`, `ANSI_WARNINGS ON`, `ARITHABORT ON`, `CONCAT_NULL_YIELDS_NULL ON`, `QUOTED_IDENTIFIER ON` y `NUMERIC_ROUNDABORT OFF`. Microsoft documenta además que en OLE DB/ODBC normalmente varios vienen en `ON`, pero `ARITHABORT` puede quedar en `OFF`, y recomienda activarlo cuando se usan indexed views o columnas computadas indexadas.

Sobre ODBC: sí, ahí hay keywords como `AnsiNPW`, `QuotedId` y en drivers nuevos `ConcatNullYieldsNull`. Appeon documenta que PowerBuilder permite `ConnectString` / `ConnectOption` para ODBC. En nativo `SNC` / `MSOLEDBSQL`, PowerBuilder permite `ProviderString`, pero no tomaría eso como solución universal para todos estos `SET`; ejecutarlos explícitamente post-connect es más auditable.

Punto crítico: si el problema está **dentro de un SP**, `SET QUOTED_IDENTIFIER` y `SET ANSI_NULLS` se capturan al momento de `CREATE/ALTER PROCEDURE`. En ese caso no alcanza con setear la conexión PB: hay que revisar que el script del SP tenga arriba:

```sql
SET ANSI_NULLS ON
SET QUOTED_IDENTIFIER ON
GO
ALTER PROCEDURE ...
```

Conclusión: para PB nativo, pondría una rutina estándar post-conexión que fuerce los 7 settings y validaría SPs afectados para asegurar que fueron creados/alterados con `ANSI_NULLS` y `QUOTED_IDENTIFIER` en `ON`.

Fuentes: Appeon PowerBuilder DBParm/ProviderString y Microsoft SQL Server SET options para indexed views, filtered indexes y XML.
