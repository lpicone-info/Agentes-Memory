- Attempted approach using local BLOB column `logo_memoria` in `d_cred_prn_smc_opt` plus `tableblob` and `SetItem(ll_fila, "logo_memoria", ib_logo_smc)` caused runtime SQL error on `lds_creden_impre.Retrieve()`: DataWindow `ds_clase`, DataObject `d_cred_prn_smc_opt`, code 156, SQLState 42000, Microsoft SQL Native Client, incorrect syntax near keyword `WHERE`. Likely because `tableblob` without a real table/keyclause makes PowerBuilder generate invalid internal SQL.
- Investigation of existing system patterns found no working pattern where a BLOB is loaded with `SetItem()` into a DataWindow and rendered directly as an image. Existing PB code uses `tableblob` tied to real tables/keyclauses for display (`d_logo_smc.srd`, `d_logo_creden.srd`, `d_logo.srd`, `d_logo_ente.srd`), `SELECTBLOB` to read BLOBs, `UPDATEBLOB` to persist them, and file writing (`FileOpen`/`FileWrite`/`BlobMid`) for BLOB-to-file workflows.
- Conclusion for 30205 as of late 2026-09-15: direct in-memory `Blob -> DataWindow visual` appears unsupported/unproven in this codebase. Realistic alternatives are: keep `tableblob` against a real table/keyclause, generate a temporary image file from the BLOB once per lot and use a bitmap `filename`, or stage the logo once in a real auxiliary/cache table keyed by a controlled lote/session and let `tableblob` read from it. No shared filesystem folder of credential/prepaga logos was found; current system stores functional logos mainly in DB columns `logos.logo`, `logos.logo_creden`, and `entes.logo`.
