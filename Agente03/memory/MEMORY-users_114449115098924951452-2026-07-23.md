- Resultado: Se concluyo que el mensaje era posible porque el codigo ejecutaba `EXECUTE valida_importa`; si `SQLCA.SqlCode = -1`, cerraba `valida_importa`, pero luego igualmente intentaba `FETCH valida_importa`. Se indico que el SP masivo no tenia cursores T-SQL declarados, por lo que el origen probable estaba en el cursor de PowerBuilder usado para leer el resultset. Se listaron causas posibles dentro del procesamiento DDJJ: tablas temporales globales, parseo del archivo, formato DDJJ incompatible, errores de insert/update o error en el SP final de derivacion de aportes.
