### [14/09/2026 15:23:27] Agente

Marcelo, **no recomiendo `RAND(GETDATE())`**:

- `RAND` no garantiza unicidad.
- Puede repetir valores.
- En un mismo `UPDATE` puede generar el mismo valor para varias filas.
- No es reproducible ni estable entre ejecuciones.

Para un índice único, usar el identificador real de la fila, preferentemente la PK:

```sql
[email] = 'anonimo+' + CONVERT(varchar(20), id_afiliado) + '@no-real.local'
```

Para teléfonos:

```sql
[telefono] = '11' + RIGHT('00000000' + CONVERT(varchar(20), id_afiliado), 8)
```

Si no existe una PK simple, la alternativa segura es generar previamente una tabla temporal con:

```sql
ROW_NUMBER() OVER (ORDER BY clave_unica)
```

y luego actualizar por esa clave. No conviene calcular el `ROW_NUMBER()` dentro de cada lote, porque al procesar lotes sucesivos los índices pueden repetirse.

**Recomendación:** usar la PK o clave única de cada tabla como sufijo. Es determinístico, no requiere aleatoriedad y evita duplicaciones salvo que la longitud de la columna impida conservar todo el valor.
