## 2. ¿Por qué sucede?

**Clasificación: Error del sistema — regresión introducida por una versión.**

En el TK 6272 se observa:

- En la pestaña **Consulta**, la columna **Presta.** está presente, pero vacía.
- En la pestaña **Errores**, los códigos sí aparecen, por ejemplo `0104`, `040108` y `1019`.

La Consulta obtiene la información mediante:

```text
prs_expe_odon_cons
```

Antes de la versión 24.09.001, el procedimiento devolvía directamente:

```sql
b.prestac
```

Con R25738 se reemplazó por:

```sql
dbo.afn_prestac_homologado(E.prestad, b.orden, b.prestac)
```

El problema es que el segundo parámetro de la función debe ser el **nomenclador**, pero se está enviando el número de **orden**:

```text
Incorrecto: b.orden
Correcto:   b.nomen
```

Como la función intenta buscar la prestación utilizando un nomenclador incorrecto, no encuentra coincidencia y devuelve `NULL`. Por eso la columna queda vacía.

## Antigüedad del comportamiento

- Desde al menos **2009**, la pantalla tenía la columna destinada a la prestación y mostraba el valor mediante `mid(prestac,2)`.
- Hasta la versión anterior a **24.09.001**, el procedimiento recuperaba `b.prestac` correctamente.
- La regresión se incorporó con **R25738**, incluida en **24.09.001** y entregada el **15/10/2024**.
- El código actual de trunk todavía conserva el parámetro incorrecto.

Por lo tanto, **no funcionó siempre así**: el código dejó de mostrarse como consecuencia del cambio realizado para R25738.

## Solución propuesta

Corregir `prs_expe_odon_cons`:

```sql
dbo.afn_prestac_homologado(E.prestad, b.nomen, b.prestac)
```

No corresponde modificar parámetros, reglas ni homologaciones para resolverlo. La configuración de homologaciones no puede compensar que el procedimiento envíe el número de orden en lugar del nomenclador.

**Conclusión:** R30446 está correctamente clasificado como defecto y requiere una corrección del stored procedure.
