### [15/10/2026 10:45:42] Agente

Javier, `XACT_ABORT` es una configuración de SQL Server que determina qué ocurre con una transacción cuando una sentencia genera un error en tiempo de ejecución.

### Activado

```sql
SET XACT_ABORT ON
```

Ante un error, SQL Server **cancela y revierte toda la transacción**.

Ejemplo: si un procedimiento inserta una sucursal y después falla la geolocalización, se deshace también la inserción.

### Desactivado

```sql
SET XACT_ABORT OFF
```

Según el tipo de error, SQL Server puede cancelar solamente la sentencia que falló y permitir que la transacción continúe. Esto puede dejar cambios parciales pendientes.

### Relación con el error de la sucursal

`XACT_ABORT` podría explicar por qué el alta completa se revierte después del error de geolocalización, pero **no origina el error**. La causa inicial continúa siendo la falla dentro del procedimiento; `XACT_ABORT` solamente determina si se deshace toda la operación o una parte.

### [15/10/2026 10:49:21] Agente

Javier, `XACT_STATE()` es una función de SQL Server que informa el estado actual de una transacción.

Puede devolver:

| Resultado | Significado |
|---:|---|
| `1` | Existe una transacción activa y se puede ejecutar `COMMIT` o `ROLLBACK`. |
| `0` | No existe una transacción activa. |
| `-1` | Existe una transacción con error; no puede confirmarse y solamente admite `ROLLBACK`. |

Ejemplo típico:

```sql
BEGIN TRY
    BEGIN TRANSACTION

    -- Operaciones

    COMMIT
END TRY
BEGIN CATCH
    IF XACT_STATE() <> 0
        ROLLBACK

    THROW
END CATCH
```

En el caso de la sucursal, si la geolocalización produce un error y `XACT_STATE()` devuelve `-1`, el alta no puede confirmarse: debe revertirse completamente. `XACT_STATE()` **no provoca el error**; solo permite saber en qué condición quedó la transacción.

### [15/10/2026 11:20:55] Agente

Javier, `UPDLOCK` y `HOLDLOCK` son **indicadores de bloqueo** de SQL Server utilizados para evitar que otras transacciones modifiquen datos mientras una operación está en curso.

```sql
SELECT ...
FROM tabla WITH (UPDLOCK, HOLDLOCK)
WHERE ...
```

### `UPDLOCK`

Solicita bloqueos de actualización sobre las filas leídas.

- Reserva los registros para una posible modificación posterior.
- Evita que otra transacción también intente modificarlos simultáneamente.
- Permite normalmente que otras sesiones los lean, dependiendo de su nivel de aislamiento.

### `HOLDLOCK`

Mantiene los bloqueos hasta que finaliza la transacción mediante `COMMIT` o `ROLLBACK`.

Equivale, para esa tabla, al aislamiento `SERIALIZABLE`. También puede bloquear el rango donde todavía no existe un registro, evitando inserciones concurrentes.

### Usados juntos

```sql
BEGIN TRANSACTION

SELECT @numero = valor
FROM parametros WITH (UPDLOCK, HOLDLOCK)

UPDATE parametros
SET valor = @numero + 1

COMMIT
```

Garantizan que entre la lectura y la actualización otra transacción no pueda tomar el mismo valor.

### Riesgos

- Esperas y bloqueos prolongados.
- Posibles interbloqueos (`deadlocks`).
- Menor concurrencia si la transacción tarda demasiado.

En resumen:

- `UPDLOCK`: **reserva para actualizar**.
- `HOLDLOCK`: **mantiene la reserva hasta terminar la transacción**.
