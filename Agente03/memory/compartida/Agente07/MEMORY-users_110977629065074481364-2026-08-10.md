Maru, en la rama `25.08.001`, el botón **“Marcar En Revisión”** se habilita únicamente según el estado interno de la autorización seleccionada.

La regla está en `ue_marca_fila` de [wp_consulta_autorizaciones_por_sector.srw](</home/desarrollo-ia-07/.openclaw/workspace/svn/mpariso-V25.08.001/exe/Source Infomedical/wp_consulta_autorizaciones_por_sector.srw:177>):

```powerscript
is_auto_esta = dw_lista.object.esta[il_row]
is_en_revision = dw_lista.object.en_revision[il_row]

IF is_auto_esta = 'P' THEN
    cb_marca.enabled = TRUE
ELSE
    cb_marca.enabled = FALSE
END IF
```

Entonces:

- Se habilita si la autorización seleccionada tiene `esta = 'P'`.
- Se deshabilita si la autorización tiene cualquier otro estado, por ejemplo aceptada, rechazada, cerrada según estado distinto de `P`.
- El estado `P` corresponde a **Pendiente**, según `auto_estados`.

El texto del botón no define la habilitación, solo define la acción disponible:

```powerscript
IF is_en_revision = 'N' THEN
    cb_marca.text = '&Marcar En Revisión'
ELSE
    cb_marca.text = '&Desmarcar En Revisión'
END IF
```

O sea:

- Si `en_revision = 'N'`, el botón muestra **Marcar En Revisión**.
- Si `en_revision = 'S'`, el botón muestra **Desmarcar En Revisión**.
- En ambos casos solo queda habilitado si `esta = 'P'`.

Los valores vienen del DataWindow `d_lista_autorizaciones_x_sector`, que ejecuta `prs_consulta_autorizaciones_x_sector`. Ahí `esta` sale de `au.esta`, y `en_revision` se normaliza así: si `au.en_revision = 'S'` devuelve `S`, si no devuelve `N`: [prs_consulta_autorizaciones_x_sector.sql](</home/desarrollo-ia-07/.openclaw/workspace/svn/mpariso-V25.08.001/backend/procedures/prs_consulta_autorizaciones_x_sector.sql:86>).
