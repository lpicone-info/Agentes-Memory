### [23/10/2026 15:35:59] Agente

Walter. En las transacciones remotas, el tag `<Credencial>` puede contener principalmente:

```xml
<Credencial>
    <NumeroCredencial>...</NumeroCredencial>
    <Track>...</Track>
    <VersionCredencial>...</VersionCredencial>
    <Vencimiento>...</Vencimiento>
    <ModoIngreso>...</ModoIngreso>
    <PlanCredencial>...</PlanCredencial>
    <CondicionIVA>...</CondicionIVA>
    <NroInternoPaciente>...</NroInternoPaciente>
    <CodigoSeguridad>...</CodigoSeguridad>
</Credencial>
```

### Identificadores que puede recibir el servicio

1. **Número de credencial**
   ```xml
   <NumeroCredencial>123456789</NumeroCredencial>
   ```
   Es el identificador principal. El validador lo exige para la mayoría de los consumidores del servicio.  
   Fuente: [Credencial.java](/home/luispicone/.openclaw/workspace/svn/wguise-V25.08.001/ws_auto_remotas/src/java/com/autorem/entities/Credencial.java:27)

2. **Documento del afiliado**

   No va dentro de `<Credencial>`. Se informa dentro de `<Beneficiario>`:

   ```xml
   <Beneficiario>
       <TipoDocBeneficiario>DNI</TipoDocBeneficiario>
       <NroDocBeneficiario>12345678</NroDocBeneficiario>
   </Beneficiario>
   ```

   El código carga el afiliado mediante tipo y número de documento cuando el número es mayor que cero.  
   Fuente: [AutorizacionesDAO.java](/home/luispicone/.openclaw/workspace/svn/wguise-V25.08.001/ws_auto_remotas/src/java/com/autorem/daos/AutorizacionesDAO.java:126)

3. **Entidad + contrato + integrante**

   Tampoco van dentro de `<Credencial>`. Se informan como datos del beneficiario:

   ```xml
   <Beneficiario>
       <Entidad>...</Entidad>
       <Contra>...</Contra>
       <Inte>...</Inte>
   </Beneficiario>
   ```

   Cuando no llega la credencial, el DAO puede buscar la credencial a partir de `prepaga`, `contra` e `inte`.  
   Fuente: [AutorizacionesDAO.java](/home/luispicone/.openclaw/workspace/svn/wguise-V25.08.001/ws_auto_remotas/src/java/com/autorem/daos/AutorizacionesDAO.java:204)

### Importante

- `Track`, `VersionCredencial`, `PlanCredencial`, `CodigoSeguridad`, etc. son datos complementarios; no aparecen implementados como identificadores alternativos a la credencial.
- El documento se utiliza desde `Beneficiario`, no desde `Credencial`.
- Para el software `WebPostInfomedical`, el validador permite credencial **o** entidad/contrato/integrante. Para otros consumidores exige número de credencial.  
  Fuente: [TransaccionValidator.java](/home/luispicone/.openclaw/workspace/svn/wguise-V25.08.001/ws_auto_remotas/src/java/validadores/TransaccionValidator.java:42)
- En el caso específico del servicio de farmacia `RegistrarConsumoFarmacia`, no se utiliza ese tag: recibe `grupo_familiar` y `afiliado` como parámetros propios.

Para la integración con Mis Validaciones, el mapeo correcto sería:

- `afiliado_credencial`: número de credencial, si está disponible.
- `afiliado_documento`: documento del afiliado.
- `contra`/`inte`: sirven para resolver al afiliado internamente, pero no deben enviarse como `afiliado_credencial` salvo que el proveedor lo defina expresamente.
