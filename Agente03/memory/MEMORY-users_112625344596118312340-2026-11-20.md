### [20/11/2026 15:00:56] Agente

Cristian, la diferencia aparece principalmente **el día 1 de cada mes**:

| Fecha hasta | Días 2 al último | Día 1 |
|---|---|---|
| Fecha actual | Incluye el mes actual | **Excluye el mes actual** |
| Primer día + 1 | Incluye el mes actual | **Incluye el mes actual** |

La causa es que:

- `GenerateMonthlyCalendar` recibe parámetros tipo `date`, por lo que descarta la hora.
- `GenerateCalendar` trata `@dateTo` como límite **exclusivo**: `[date] < @dateTo`.
- Si hoy fuera `01/11/2026` y se enviara la fecha actual, el calendario terminaría antes de incluir `01/11/2026`.
- Enviando `02/11/2026`, queda incluido `01/11/2026`.

**Impacto de usar fecha actual:**

- El día 1 reaparecería el defecto: Afilmed y Afilmed Web no mostrarían aportes del mes recién iniciado.
- Desde el día 2 en adelante, ambas alternativas devolverían los mismos períodos mensuales.
- La fecha desde no cambia.
- Las consultas con fechas explícitas tampoco cambian.
- Usar fecha actual genera además algunos días intermedios que luego se descartan; primer día + 1 es más acotado.

Evidencia: [GenerateCalendar.sql](/home/luispicone/.openclaw/workspace/svn/cratto-R29455…ndar.sql:38), [GenerateMonthlyCalendar.sql](/home/luispicone/.openclaw/workspace/svn/cratto-R29455/backend/function/GenerateMonthlyCalendar.sql:18) y [afs_list_afi_transf_ddjj.sql](/home/luispicone/.openclaw/workspace/svn/cratto-R29455/backend/procedures/afs_list_afi_transf_ddjj.sql:108).

Por lo tanto, **primer día + 1 es técnicamente la opción correcta** para garantizar el mes actual durante todo el mes. Esta evidencia permite resolver J1 sin modificar el SP; sólo debe documentarse esta justificación.
