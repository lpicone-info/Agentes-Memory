El rol **Auditor médico no interviene directamente** en la habilitación de esos botones. La ventana utiliza el **sector configurado en `ZZ_USUARI` para el usuario conectado**, no sus roles.

El botón **Aud. Med. Ing.** queda deshabilitado cuando el sector del usuario tiene:


### 2. Imprimir certificados

Este botón necesita que se cumplan **las dos condiciones** siguientes:

1. El sector del usuario tiene:

```text
SECTORES.imprime_certificados = 'S'
```

2. La solicitud tiene al menos una de estas situaciones:

- Alguna preexistencia cargada.
- Algún integrante con auditoría médica cuyo estado tenga `impacta = FALSE`.

Si no existen preexistencias y todos los estados de auditoría impactan —o todavía no hay registros de auditoría—, **Imprimir certificados queda deshabilitado**, aunque el usuario tenga rol de auditor médico y la solicitud pertenezca al sector.

Evidencia: [wp_alta_parcial.srw:3811](/home/luispicone/.openclaw/workspace/svn/gpulka-Coomeva-trunk/exe_afilmed/src/wp_alta_parcial.srw:3811).

## Cuándo pueden quedar ambos deshabilitados

Los casos concretos son:

1. El sector asociado al usuario tiene:
   - `carga_preexistencias <> 'S'`
   - `imprime_certificados <> 'S'`

2. El sector tiene permiso para imprimir, pero:
   - `carga_preexistencias <> 'S'`
   - No hay preexistencias.
   - No existe ningún integrante con estado de auditoría que no impacte.

3. El usuario posee el rol Auditor médico, pero en `ZZ_USUARI` está asociado a otro sector cuyas capacidades no están configuradas.

4. Como caso marginal, si falla la inicialización de algún estado de integrante, la rutina de impresión retorna antes de habilitar el botón y este puede conservar su estado inicial deshabilitado.
