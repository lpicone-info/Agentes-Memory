### [04/09/2026 12:10:35] Agente

Sebastián, el punto clave es este: **PowerBuilder 2022 que estás usando es 32 bits**, entonces necesita un provider OLE DB **x86** visible desde el mundo 32 bits de Windows.

Lo que pasó en la prueba:

```text
MSOLEDBSQL 19 x86 -> no instala en Windows Server 2025
MSOLEDBSQL 18 x86 -> no instala en Windows Server 2025
MSOLEDBSQL 18.7.5 x86 -> no instala en Windows Server 2025
SQL Native Client 11 x86 -> instala, PB22 lo ve y conecta
```

No es que SQL Server 2022 “prefiera” Native Client 11. Es que en tu combinación real:

```text
Windows Server 2025 + PB22 32 bits + SQL Server 2022
```

los drivers modernos `MSOLEDBSQL 18/19` en x86 fallan por compatibilidad/soporte del instalador con el sistema operativo. En cambio `SQLNCLI11` deja registrado el provider 32 bits:

```text
SQLNCLI11
C:\Windows\SysWOW64\sqlncli11.dll
```

y por eso PowerBuilder lo puede usar con:

```text
DBMS = SNC SQL Native Client(OLE DB)
Provider = SQLNCLI11
```

Conclusión para Redmine `30282`: **no estamos eligiendo SQLNCLI11 porque sea lo más moderno**, sino porque es el único provider x86 que quedó operativo y visible para PB22 en Windows Server 2025. El riesgo a documentar es que `SQL Native Client 11` es legacy/deprecado, pero funcional para esta prueba de compatibilidad.
