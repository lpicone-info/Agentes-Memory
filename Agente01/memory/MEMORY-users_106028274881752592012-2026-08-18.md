Código propuesto:

```sql
	DECLARE @var_lock_resource	VARCHAR(100),
					@var_lock_result		INTEGER

	DECLARE csrLockReversion INSENSITIVE CURSOR FOR
		SELECT DISTINCT
						ente					= REV.ente,
						compro_tipo		= REV.compro_tipo,
						compro_nro		= REV.compro_nro
		FROM		#REV_COMPRO_A_REVERSAR AS REV
		WHERE		REV.recha IS NULL
		ORDER BY REV.ente,
						 REV.compro_tipo,
						 REV.compro_nro
		FOR READ ONLY

	OPEN csrLockReversion

	FETCH csrLockReversion INTO	@csr_ente,
																@csr_compro_tipo,
																@csr_compro_nro

	WHILE @@fetch_status = 0
	BEGIN

		SET @var_lock_resource = 'AFI_COMPRO_REVERSO|' +
														 CONVERT(VARCHAR(3), @csr_ente) + '|' +
														 @csr_compro_tipo + '|' +
														 @csr_compro_nro

		EXECUTE @var_lock_result = sp_getapplock
			@Resource		= @var_lock_resource,
			@LockMode		= 'Exclusive',
			@LockOwner	= 'Transaction',
			@LockTimeout	= 0

		IF @var_lock_result < 0
		BEGIN
			UPDATE	#REV_COMPRO_A_REVERSAR
			SET			recha = 'El comprobante se encuentra siendo reversado por otro usuario del sistema.'
			WHERE		ente				= @csr_ente
			AND			compro_tipo	= @csr_compro_tipo
			AND			compro_nro	= @csr_compro_nro
			AND			recha IS NULL
		END

		FETCH csrLockReversion INTO	@csr_ente,
																	@csr_compro_tipo,
																	@csr_compro_nro

	END

	CLOSE csrLockReversion
	DEALLOCATE csrLockReversion


	UPDATE	REV
	SET			recha = 'El comprobante ya tiene una reversion activa.'
	FROM		#REV_COMPRO_A_REVERSAR AS REV
	WHERE		REV.recha IS NULL
	AND			EXISTS	(
									SELECT	1
									FROM		COMPRO_REVERSO_DET WITH (index(ndx_compro_reverso_det1))
									WHERE		ente				= REV.ente
									AND			compro_tipo	= REV.compro_tipo
									AND			compro_nro	= REV.compro_nro
									AND			baja_fecha IS NULL
								)
```

Criterio técnico: `sp_getapplock` con `LockTimeout = 0` no espera, por lo tanto evita lockeos largos. Si otro usuario ya está procesando el mismo DA/DS/DE, el segundo proceso queda rechazado por el circuito existente de errores y no llega a generar otro CA.

No propondría de entrada un índice único filtrado sobre `COMPRO_REVERSO_DET`, porque es más invasivo y puede chocar con datos históricos o reglas funcionales no revisadas. Esta alternativa limita el cambio al flujo de reversión y no afecta facturación ni reversos automáticos salvo que usen el mismo procedimiento, que justamente es el punto a proteger.
