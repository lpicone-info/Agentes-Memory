## Por qué `id_proceso` aparece como columna

El procedimiento no hace:

```sql
RETURN @id_proceso
```

ni usa un parámetro:

```sql
@id_proceso OUTPUT
```

Lo incorpora como columna dentro del resumen:

```sql
@prm_id_proceso AS id_proceso
```

Esto permite que la respuesta tenga un contrato uniforme junto con el resto de los datos.

Además, un `RETURN` de SQL Server está pensado principalmente para un código entero de ejecución, no para devolver una estructura completa.

## Entonces, ¿es un error?

No necesariamente. Es una decisión de contrato:

```text
Entrada:  un id_proceso
Salida 1: resumen de la solicitud
Salida 2: detalle de integrantes
```

Pero sí puede ser un problema si AFE espera:

```text
una única fila plana
```

o:

```text
un único objeto con resumen y detalle anidado
```

Actualmente el consumidor debe leer dos result sets consecutivos. Si solo lee el primero, obtiene el resumen; si solo espera un valor escalar, la interfaz no coincide con este procedimiento.

También es importante que el procedimiento procesa **un solo `id_proceso` por ejecución**. No devuelve “el resto de las solicitudes” en una misma llamada. Para eso habría que diseñar otro procedimiento que reciba una colección o un criterio de lote y devuelva una única estructura consolidada.
