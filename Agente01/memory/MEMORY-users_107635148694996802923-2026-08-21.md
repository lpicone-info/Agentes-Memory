### [21/08/2026 13:56:56] Agente

Savina, ese `inte="01"` no debería ir en el XML genérico actualizado para traslado a contrato existente.

Para `<anexos>`, la obligatoriedad es:

- `<anexos>`: no es obligatorio como bloque. Sólo se informa si la APP necesita enviar anexos explícitos.
- `<anexo>`: obligatorio sólo si se informa el bloque `<anexos>`.
- `plan_anexo`: obligatorio cuando existe `<anexo>`.
- `tari_anexo`: obligatorio cuando existe `<anexo>`.
- `plan_anexo_sup`: opcional, sólo si corresponde.
- `tari_anexo_sup`: opcional, sólo si corresponde.
- `anter_prepa`, `anter_contra`, `anter_inte`: deben usarse para vincular el anexo con el integrante origen cuando el anexo pertenece a un integrante puntual.
- `inte`: no debe pedirse como dato de entrada para el traslado existente, porque el proceso calcula internamente el integrante técnico destino.

El SP tiene compatibilidad para leer `inte`, pero la definición funcional actual dice que no debe venir desde la APP. El vínculo correcto es por origen.

El tag debería quedar así:

```xml
<anexos>
    <anexo
        anter_prepa="1"
        anter_contra="CONTRATO_ORIGEN"
        anter_inte="01"
        plan_anexo="PLAN_ANEXO"
        tari_anexo="TARIFA_ANEXO"
        plan_anexo_sup=""
        tari_anexo_sup=""
    />
</anexos>
```

Motivo: `anter_prepa + anter_contra + anter_inte` identifica el integrante origen elegido por el usuario. Con eso el backend calcula el `inte` técnico interno para relacionar anexos, contactos e integrantes.
