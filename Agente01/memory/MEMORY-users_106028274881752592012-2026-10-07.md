### 3. ¿Se puede saber si hubo mantenimiento frecuente?

No directamente desde `sys.stats`: SQL Server solo guarda la última fecha, no un historial completo.

Para buscar indicios de mantenimiento automático o programado:

```sql
SELECT
    j.name AS job_name,
    h.run_date,
    h.run_time,
    h.run_duration,
    h.message
FROM msdb.dbo.sysjobhistory AS h
INNER JOIN msdb.dbo.sysjobs AS j
    ON j.job_id = h.job_id
WHERE h.step_id > 0
AND
(
       j.name LIKE '%stat%'
    OR j.name LIKE '%index%'
    OR j.name LIKE '%manten%'
    OR h.message LIKE '%UPDATE STATISTICS%'
    OR h.message LIKE '%rebuild%'
    OR h.message LIKE '%reorganize%'
)
ORDER BY h.run_date DESC, h.run_time DESC;
```

También conviene revisar los jobs activos:

```sql
SELECT
    j.name,
    j.enabled,
    js.next_run_date,
    js.next_run_time
FROM msdb.dbo.sysjobs AS j
LEFT JOIN msdb.dbo.sysjobschedules AS js
    ON js.job_id = j.job_id
WHERE j.name LIKE '%stat%'
   OR j.name LIKE '%index%'
   OR j.name LIKE '%manten%';
```

### Limitación importante

`last_updated` también puede cambiar por:

- `UPDATE STATISTICS`;
- actualización automática de estadísticas;
- `ALTER INDEX ... REBUILD`;
- algunas operaciones de mantenimiento del índice.

Por lo tanto, sirve para saber **cuándo se actualizaron**, pero no necesariamente **qué proceso lo hizo**. Para identificar al ejecutor se necesitaría historial de SQL Agent, Extended Events, auditoría o un trace que todavía conserve el evento.
