- La unión actual de [afi_procesa_comisiones_valores_complementarios.sql](/home/luispicone/.openclaw/workspace/svn/gpulka-Coomeva-trunk/backend/procedures/afi_procesa_comisiones_valores_complementarios.sql:108) por `C.cuenta + C.subcta + C.contra` devuelve 0 filas para junio 2026.

**Diagnóstico**
Para facturación empresa/colectivo, el `contra` no identifica el comprobante. La clave funcional del comprobante agrupador es `cuenta + subcta` con `factu_destino = 'E'`, y en la cabecera el registro correspondiente viene marcado como `aux_tipo = 'S'`.

La solución no debería ser:

```sql
C.contra = CMC.contra OR (C.contra IS NULL AND CMC.contra IS NULL)
```

Eso mezcla semánticas distintas y puede ser peor para el plan de ejecución.

**Mejor solución**
Separar la lógica por tipo funcional:

```sql
-- Contratos / afiliado
C.factu_destino = 'A'
AND CMC.aux_tipo = 'C'
AND C.prepaga = CMC.prepaga
AND C.contra = CMC.contra

-- Subcuentas / empresa
C.factu_destino = 'E'
AND CMC.aux_tipo = 'S'
AND C.cuenta = CMC.cuenta
AND C.subcta = CMC.subcta
```

Además, para que el reproceso histórico no dependa de `GETDATE()`, conviene calcular contra `CMC.fecha_hasta` y filtrar comprobantes vencidos a esa fecha:

```sql
AND C.fecha_vto <= CMC.fecha_hasta
```
