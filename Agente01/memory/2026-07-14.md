
## 2026-07-14 - Cambio titularidad automatico / QA InstallQA_89

Contexto durable:
- Usuario: Sebastian (segun conversacion), trabajando sobre flujo legacy PowerBuilder/MS SQL de solicitudes automaticas.
- Caso analizado: solicitud de cambio de titularidad `4677082`, XML externo `id_soli_externa="293649100"`, `soli_moti="7"`, `prepaga="1"`, `contra="1073909"`, `fecha_aplicacion="2026-07-01"`, `inte_nuevo_titular="02"`, `baja_titular="S"`, `baja_moti="1"`, `genera_resp_pagador="S"`.
- Sintomas reportados: no daba de baja al titular anterior, motivo de baja quedaba vacio en pantalla, nuevo parentesco no quedaba ingresado, y se generaba una segunda solicitud de cambio de datos generales de beneficiarios que daba error/afectaba a todos.

Diagnostico encontrado:
- En `SOLI_AUTO_CONTRATO` el XML habia entrado correctamente para `id_proceso = 108`, asociado a `soli = 4677082`; estaban presentes `inte_nuevo_titular = 02`, `baja_titular = S`, `baja_moti = 1`.
- En `GMSTXT_INTEGRANTES`, el titular anterior `inte 01` quedaba con `anula = S`.
- Al pasar a `GMSDEF_INTEGRANTES`, el campo `anula` se perdia y quedaba `NULL`.
- `gms_genera_solicitudes` solo aplicaba `baja_moti`/fecha de baja cuando `GI.anula = 'S'`; por eso no copiaba motivo 1 ni fecha a `SOLI_AFILIADOS` y la pantalla mostraba motivo vacio.
- `SOLI_AUTO_PARENTESCOS` recibia los nodos XML de parentesco, pero con `paren_actual = paren_nuevo` (`H -> H`) para integrantes 02 y 03, por lo que no habia cambio real.
- El proceso igualmente generaba solicitud secundaria de cambio de datos porque recorria todos los registros de `SOLI_AUTO_PARENTESCOS` sin filtrar cambios reales.
- Para la solicitud secundaria generada, no se estaba grabando correctamente `SOLI_PARENTESCOS`, por eso el nuevo parentesco aparecia vacio en la pantalla que lo consulta.

Cambios realizados y commiteados:
- Commit SVN: `r37328`
- Mensaje: `Fix cambio titularidad automatico`
- Archivos impactados:
  - `backend/procedures/gmstxt_pasar_a_def.sql`
  - `backend/procedures/gms_genera_solicitudes.sql`
  - `backend/procedures/afi_genera_soli_auto_cambio_datos_parentescos.sql`
- Fixes:
  - `gmstxt_pasar_a_def.sql`: persistir `TBL.anula` al insertar/pasar datos a `GMSDEF_INTEGRANTES`.
  - `gms_genera_solicitudes.sql`: evitar cargar/procesar `SOLI_PARENTESCOS` para parentescos sin cambio real (`paren_actual = paren_nuevo`), para no pisar datos del cambio de titularidad.
  - `afi_genera_soli_auto_cambio_datos_parentescos.sql`: generar solicitud secundaria solo cuando exista cambio real de parentesco y, cuando se genera, grabar tambien `SOLI_PARENTESCOS` para que el nuevo parentesco no quede vacio.
