Savina, continuando con la EF, las validaciones para ingresar una **Venta Nueva** relacionada con facturación/deudas en Coomeva son las siguientes.

## 1. Novedad seleccionada

El campo **Novedad** es obligatorio y permite:

- **1 – Venta Nueva**
- **2 – Reactivación**
- **3 – Operación Retorno**

Además, el sistema calcula una **Novedad Sistema**, que no es editable. La obtiene mediante la integración **Saldos_Castigados**, identificada como **33/A00547**, junto con las reglas de permanencia y retiro.

## 2. Validación de deuda o mora

La EF no valida solamente si existe una deuda actual. Consulta los saldos castigados de contratos de la **misma línea de negocio**, considerando los últimos **24 meses**.

La consulta se realiza según los indicadores configurados:

### Mora del contratante

Si `Mora Contratante = SI`, se consulta la deuda del:

- Contratante
- Responsable pagador
- Empleado, según corresponda al tipo de contrato

### Mora del beneficiario

Si `Mora beneficiario = SI`, se consulta la deuda individual de cada beneficiario incluido en la solicitud.

La validación depende de:

- Existencia de deuda.
- Persona que posee la deuda.
- Línea de negocio.
- Período de los últimos 24 meses.
- Novedad seleccionada por el usuario.
- Novedad calculada por el sistema.
- Reglas de permanencia y retiro configuradas.

## 3. Cómo se determina si corresponde Venta Nueva

El sistema revisa la situación anterior del beneficiario:

| Situación encontrada | Novedad Sistema |
|---|---|
| Beneficiario activo en la misma línea de negocio | Traslado |
| Beneficiario inactivo dentro del período permitido de reactivación | Reactivación |
| Beneficiario inactivo dentro del período permitido de operación retorno | Operación Retorno |
| Beneficiario retirado fuera de los períodos anteriores | Venta Nueva |

Por lo tanto, seleccionar **Venta Nueva** no garantiza que el sistema la considere automáticamente como Venta Nueva. La novedad ingresada debe coincidir con la novedad calculada.

## 4. Validaciones específicas al seleccionar Venta Nueva

### Beneficiario activo

Si el usuario selecciona **Venta Nueva**, pero el beneficiario está activo en la misma línea de negocio:

- Se muestra un mensaje informativo.
- El usuario puede continuar confirmando la operación.

En cambio, si selecciona **Reactivación** u **Operación Retorno** y el beneficiario está activo:

- Se muestra un mensaje bloqueante.
- No puede continuar con esa novedad.

### Renuncia de antigüedad

Si el beneficiario califica originalmente para Reactivación u Operación Retorno, pero se marca **Renuncia de Antigüedad**, la novedad calculada cambia a:

```text
Venta Nueva
```

## 5. Combinaciones entre deuda y novedad

La EF contempla estas situaciones:

| Situación | Resultado funcional |
|---|---|
| Existe deuda y la novedad es Reactivación | Se informa el resultado de Saldos Castigados y la solicitud queda en estado incompleto según la regla |
| Existe deuda y la novedad es Operación Retorno | Se informa el resultado de Saldos Castigados y la solicitud queda en estado incompleto según la regla |
| Existe deuda, todos los beneficiarios calculan Venta Nueva y la novedad seleccionada es Venta Nueva | Puede aceptarse y continuar por el circuito normal |
| No existe deuda y la novedad ingresada coincide con la calculada | La solicitud puede aceptarse |
| La novedad ingresada no coincide con la calculada | Mensaje bloqueante y solicitud incompleta |
| Beneficiario activo y se selecciona Venta Nueva | Mensaje informativo; puede continuar |
| Beneficiario activo y se selecciona Reactivación/Operación Retorno | Bloqueo |

### Punto importante

La deuda **no bloquea automáticamente toda Venta Nueva**. El bloqueo depende de la combinación entre:

- Deuda detectada.
- Tipo de persona con deuda.
- Novedad seleccionada.
- Novedad calculada.
- Resultado de la integración de Saldos Castigados.

## 6. Relación con facturación

La EF vincula esta validación con el proceso de incorporación del beneficiario y la situación contractual anterior. La deuda considerada es la informada por **Saldos_Castigados**, no una validación aislada de la factura del mes actual.

Para que una Venta Nueva pueda continuar, debe cumplirse principalmente:

1. La persona debe estar correctamente identificada.
2. Debe existir la información necesaria para determinar su situación anterior.
3. Debe ejecutarse la consulta de deuda cuando corresponda.
4. La novedad seleccionada debe coincidir con la calculada.
5. Si existe deuda, debe cumplirse la regla aplicable a esa combinación.
6. No debe producirse una inconsistencia de permanencia, retiro o antigüedad.
