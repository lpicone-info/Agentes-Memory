## Cambio necesario para soportarlo

La solución no sería simplemente cambiar el mensaje de error. Habría que diferenciar errores bloqueantes y no bloqueantes durante el circuito:

1. Marcar los errores provenientes de ajustes como `Warning` o `No bloqueantes`.
2. Propagar esa clasificación desde:
   ```text
   #FAC_PREPROCESOS_ERR
   ```
   hacia:
   ```text
   #FAC_PREFACTURAS_ERR
   ```
3. Cambiar la eliminación de `#FAC_PREFACTURAS` para que solo elimine el contrato cuando exista al menos un error bloqueante.
4. Mantener excluido el movimiento de ajuste que no pudo calcularse.
5. Conservar las líneas válidas de cuota.
6. Mostrar el ajuste fallido en **Inconvenientes de Prefacturación**, indicando que no se facturó.
7. Revisar los contadores de errores para que un warning no impida habilitar la prefacturación/facturación.

Un punto importante: `#FAC_PREFACTURAS_ERR` actualmente no tiene un campo de severidad ni conserva `etapa_calculo`. Por lo tanto, no conviene inferir el warning únicamente por el concepto; habría que agregar una clasificación explícita o propagar `etapa_calculo` desde `#FAC_PREPROCESOS_ERR`.

En resumen: **hay una base reutilizable para implementar el comportamiento, pero hoy los errores de ajustes son bloqueantes a nivel contrato y no existe un warning equivalente en la etapa de prefacturación.**
