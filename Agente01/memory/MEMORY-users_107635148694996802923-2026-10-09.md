En el proceso nocturno de **Primera Cuota**, la secuencia entre `SL` y `RC` es esta:

1. **`SL` representa la deuda** de primera cuota.
2. **`RC` representa el pago/recaudo** recibido.
3. El `RC` puede llegar antes o después de generarse/facturarse la deuda.

### Si la solicitud tiene `SL`

El `SL` debe existir previamente en:

```text
COMPRO_PRIMERA_CUOTA
```

El proceso nocturno no crea ese `SL`; lo utiliza para determinar qué solicitud y períodos debe facturar.

Si el pago ya fue importado, se encuentra inicialmente como recaudo sin identificar. Al impactar la solicitud:

1. Busca el `RC` por el código único del `SL`.
2. Anula técnicamente el recibo sin identificar.
3. Genera un nuevo recibo asociado al contrato.
4. Registra su identificación.
5. Posteriormente, el proceso nocturno genera la deuda de primera cuota y permite aplicar ese pago.

Esta lógica está en [afu_chequea_pago_primera_cuota.sql](/home/luispicone/.openclaw/workspace/svn/svarela-Coomeva-trunk/backend/procedures/afu_chequea_pago_primera_cuota.sql:94).

### Si la solicitud tiene directamente un `RC`

La solicitud guarda:

```text
recibo_compro_tipo  = RC
recibo_compro_nro   = número del recaudo
```

Al impactarla, Afilmed busca ese recibo en `RECIBOS_SIN_IDENTIFICAR`, lo asocia al contrato y luego el proceso nocturno incluye la solicitud para generar la deuda correspondiente.

### Proceso nocturno

El SuperBatch ejecuta diariamente el proceso `PRICUO`:

```text
Crear PREFACTURAS_CAB tipo PC
→ Verificar solicitudes
→ Prefacturar
→ Facturar
→ Aplicar/compensar el recaudo existente
```

La selección exige:

```sql

```

Para solicitudes con `SL`, además exige que exista el registro en `COMPRO_PRIMERA_CUOTA`.

Referencia: [afi_verif_contra_prefac_primera_cuota.sql](/home/luispicone/.openclaw/workspace/svn/svarela-Coomeva-trunk/backend/procedures/afi_verif_contra_prefac_primera_cuota.sql:56).
