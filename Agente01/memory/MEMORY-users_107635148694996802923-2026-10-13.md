Savina, la diferencia principal es que el `SL` se genera **antes del impacto**, mientras que el proceso nocturno genera la deuda contable correspondiente. El nocturno **no genera el SL faltante**.

## Qué son `SL` y `RC`

- **`SL`**: comprobante de Primera Cuota calculado desde la valorización de la solicitud.
- **`RC`**: recaudo real ya recibido.
- El `SL` representa cuánto debe pagar.
- El `RC` representa el dinero efectivamente recibido.

La obligación funcional no es necesariamente generar un `SL`: cuando corresponde Primera Cuota, la solicitud debe tener **un `SL` o un `RC` válido**.

## Inclusión y Venta Nueva manual

| Característica | Venta Nueva | Inclusión |
|---|---|---|
| Motivo | `1` | `2` |
| Contrato al generar el SL | Está siendo creado | Ya existe |
| Valorización | Grupo inicial | Nuevos integrantes |
| Parámetros de emisión | `SOLI_TITULARES` | Contrato vigente o datos modificados |
| Primera Cuota obligatoria | Según subcuenta y tarifa | Según subcuenta, tarifa y modalidad prepaga |
| Múltiples solicitudes | Una Venta Nueva por contrato | Puede agrupar inclusiones del mismo contrato |

En ambos casos la secuencia manual es:

```text
Grabar solicitud
→ valorizar
→ generar SL o seleccionar RC
→ guardar comprobante en SOLICITUDES
→ impactar solicitud
→ buscar/aplicar recaudo
→ proceso nocturno PC
→ generar deuda real
→ aplicar saldo o pago disponible
```

La ventana bloquea el impacto si corresponde Primera Cuota y no existe comprobante:

Savina, **no es una regla “si y solo si”**.

### Comportamiento normal

- Si existe un `RC` y se selecciona en la solicitud, **no es necesario generar un `SL`**.
- La solicitud queda con:

```text
recibo_compro_tipo = RC
```

- Al impactar, el `RC` se relaciona con el contrato real.
- Luego el proceso nocturno `PC` genera la deuda y aplica el recaudo.

### Pero puede reemplazarse el RC por un SL

Si la solicitud ya tiene un `RC` y el usuario presiona **Generar Comp.**, la ventana advierte:

```text
Está a punto de generar un comprobante nuevo.
Este reemplazará al actual.
```

Si continúa:

1. Se genera el `SL`.
2. El `SL` reemplaza al `RC` en la solicitud.
3. El recaudo deberá relacionarse después mediante el código único del `SL`.

Por lo tanto:

| Situación al impactar | Resultado |
|---|---|
| Se seleccionó un `RC` | Se impacta con `RC`, sin generar `SL` |
| Se generó un `SL` | Se impacta con `SL` |
| Había `RC`, pero se generó después un `SL` | El `SL` reemplaza al `RC` |
