# Cambio de responsable pagador

Los tres atributos se informan únicamente en el tag principal `<solicitud>`:

```xml
<solicitud
    finalizar_resp_pagador="S"
    baja_resp_pagador="N"
    moti_ret_resp_pag="1">
```

No deben colocarse dentro de `<responsable_pagador>`.

Si `finalizar_resp_pagador` o `baja_resp_pagador` no se informan, el sistema los interpreta como `"N"`.

## Significado de cada atributo

### `finalizar_resp_pagador`

Indica que el responsable pagador vigente debe finalizar normalmente.

```xml
finalizar_resp_pagador="S"
```

El sistema:

- Identifica al responsable vigente.
- Calcula automáticamente su fin de vigencia como:
  ```text
  fecha_aplicacion - 1 día
  ```
- Exige informar `moti_ret_resp_pag`.
- Permite agregar otro responsable pagador en la misma solicitud.

No debe informarse `vigen_hasta_resp_pagador`, porque el sistema la calcula.

### `baja_resp_pagador`

Indica una **baja técnica** del responsable vigente:

```xml
baja_resp_pagador="S"
```

Solo se permite cuando:

```text
vigencia inicial del responsable = fecha de aplicación
```

Se utiliza para anular un responsable que comenzó a regir en esa misma fecha.

Con la revisión `38298`, la baja técnica **sí permite agregar un nuevo responsable pagador en la misma solicitud**.

### `moti_ret_resp_pag`

Es el motivo de retiro del responsable.

Solo corresponde cuando:

```xml
finalizar_resp_pagador="S"
```

Debe ser:

- Numérico.
- Mayor que cero.
- Un código vigente de la tabla de motivos.

Cuando `finalizar_resp_pagador="N"`, no debe informarse:

```xml
<!-- No incluir moti_ret_resp_pag -->
```

Aunque se realice una baja técnica, el motivo no corresponde, salvo que también se indique `finalizar_resp_pagador="S"`.

# Matriz de casos

| Operación | Finalizar | Baja | Motivo | ¿Nuevo RP? |
|---|---:|---:|---|---|
| Actualizar datos del RP actual | N | N | No informar | Debe ser la misma persona |
| Agregar RP cuando no existe uno vigente | N | N | No informar | Sí |
| Finalizar y reemplazar | S | N | Obligatorio | Sí, persona distinta |
| Finalizar sin reemplazar | S | N | Obligatorio | Permitido si queda un titular adulto |
| Baja técnica sin reemplazar | N | S | No informar | Permitido si queda un titular adulto |
| Baja técnica y reemplazo | N | S | No informar | Sí, persona distinta |
| Finalizar y dar baja técnica | S | S | Obligatorio | Opcional; si se informa, debe ser distinto |

## Actualizar al mismo responsable

Para modificar datos de la persona que ya es responsable:

```xml
<solicitud
    finalizar_resp_pagador="N"
    baja_resp_pagador="N">

    <responsable_pagador
        docu_tipo="CC"
        docu_nro="..." />
</solicitud>
```

La persona informada debe ser la misma que está vigente.

Si se informa otra persona mientras ambos indicadores están en `"N"`, el XML será rechazado porque falta indicar cómo debe terminar el responsable anterior.

## Reemplazo normal

```xml
<solicitud
    finalizar_resp_pagador="S"
    baja_resp_pagador="N"
    moti_ret_resp_pag="1">

    <responsable_pagador
        docu_tipo="CC"
        docu_nro="..." />
</solicitud>
```

Resultado:

1. Finaliza el responsable anterior.
2. Se registra el motivo.
3. Se agrega el nuevo responsable desde la fecha de aplicación.

El nuevo responsable debe ser una persona distinta.

## Baja técnica con reemplazo

```xml
<solicitud
    finalizar_resp_pagador="N"
    baja_resp_pagador="S">

    <responsable_pagador
        docu_tipo="CC"
        docu_nro="..." />
</solicitud>
```

Resultado:

1. Se anula técnicamente el responsable anterior.
2. No se informa motivo de retiro.
3. Se agrega el nuevo responsable en la misma solicitud.

Esta operación solo es válida cuando el responsable anterior comenzó su vigencia en la fecha de aplicación.

## Finalización y baja simultáneas

La combinación ahora está permitida:

```xml
<solicitud
    finalizar_resp_pagador="S"
    baja_resp_pagador="S"
    moti_ret_resp_pag="1">
```

El responsable anterior queda:

- Marcado con baja técnica.
- Con vigencia hasta el día anterior a la aplicación.
- Con motivo de retiro.

También exige que su vigencia inicial coincida con la fecha de aplicación.

## Reglas para agregar un nuevo responsable

Cuando se incluye `<responsable_pagador>`:

- Solo puede informarse uno.
- `docu_tipo` y `docu_nro` son obligatorios.
- Debe ser mayor de edad.
- Si se finaliza o da de baja al anterior, debe ser otra persona.
- Si no existe en Registro Único, deben informarse sus datos personales.
- Debe existir o informarse domicilio, teléfono y correo.
- No deben informarse `item`, `vigen_desde` ni `vigen_hasta`; se calculan internamente.

Si se finaliza o da de baja al responsable sin agregar otro, el contrato debe conservar un titular mayor de edad. De lo contrario, el nuevo responsable es obligatorio.
