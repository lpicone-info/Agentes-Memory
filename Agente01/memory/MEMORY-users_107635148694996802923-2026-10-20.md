## Cuándo exige Primera Cuota

La ventana bloquea el impacto cuando se cumplen simultáneamente estas condiciones:

- solicitud de Venta Nueva, motivo `1`;
- existe al menos un beneficiario que no sea bebé gestante;
- la subcuenta exige Primera Cuota;
- la tarifa no es tipo `Q` ni `F`;
- no se registró comprobante de Primera Cuota.

# 7. Diferencias entre Venta Nueva e Inclusión

| Tema | Venta Nueva | Inclusión |
|---|---|---|
| Motivo | `1` | `2` |
| Contrato al generar SL | Todavía se está formando | Ya existe |
| Valorización | Grupo inicial de beneficiarios | Nuevos integrantes |
| Datos de emisión | Datos de la solicitud y `SOLI_TITULARES` | Contrato, subcuenta y titular vigentes |
| Modalidad | Se determina desde la nueva solicitud | Se exige expresamente contrato prepago, `emi_modo = 0` |
| Recaudo antes del impacto | No puede asociarse a un contrato inexistente | El contrato ya existe, pero debe asociarse correctamente con la inclusión |
| Proceso nocturno | Procesa la Venta Nueva individualmente | Puede agrupar varias inclusiones del mismo contrato |
| Riesgo específico | Impactar sin identificar correctamente el pago inicial | Duplicar SL o reprocesar un RC ya identificado por otra inclusión |

La obligación en Inclusiones se controla cuando:

- motivo `2`;
- hay beneficiarios que no son bebé gestante;
- el contrato es prepago;
- la subcuenta exige Primera Cuota;
- la tarifa no es `Q/F`;
- no existe comprobante.

# 8. Situación de las solicitudes automáticas V104

La lógica manual necesaria existe en la rama, pero el circuito específico de generación automática:

```text

afu_genera_soli_auto_app
afs_soli_auto_obligatorios
afi_insertar_soli_auto
```

no invoca automáticamente:

```text

```

Tampoco completa por sí mismo los campos:

```text

recibo_compro_letra
recibo_compro_punto
recibo_compro_nro
fecha_recibo
valor_recibo
```

Por lo tanto, indicar que la solicitud automática requiere Primera Cuota **no equivale** a:

- generar el SL;
- buscar un RC pendiente;
- reservarlo;
- asociarlo con la solicitud;
- garantizar el mismo bloqueo que aplica la ventana manual.

## Brecha funcional resumida

```text
Ventana manual
→ valoriza
→ genera SL o selecciona RC
→ impide impactar sin comprobante
→ identifica el RC al impactar
→ habilita el proceso nocturno PC

Solicitud automática V104
→ genera la solicitud
→ no reproduce integralmente el circuito anterior
```

Para igualar el comportamiento manual, la automatización tendría que ser idempotente:

```text
Determinar si corresponde Primera Cuota
→ valorizar
→ reutilizar SL vigente o generar uno
→ localizar y reservar RC si existe
→ guardar comprobante en SOLICITUDES
→ impedir duplicación de SL/RC
→ impactar
→ identificar y aplicar mediante afu_chequea_pago_primera_cuota
→ dejar la solicitud disponible para el proceso nocturno PC
```
