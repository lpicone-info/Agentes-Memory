Savina, revisado en código: la obligatoriedad por `pago_forma` no está completa en `afi_insertar_soli_auto_traslado_nuevo`; ahí solo lee y guarda los atributos del tag `<facturacion>`. La validación fuerte aparece después en `gmsdef_val_pago_formas`.

**Regla por código**

- Si no viene `pago_forma`, el proceso lo defaulta a `E`.
- Para cuenta colectiva, `afi_insertar_soli_auto_traslado_nuevo` fuerza `pago_forma = 'E'` y limpia `banco`, `banco_suc`, `tipo_cta`, `cta`, `tarje`, `titular`, `venci_fecha`.
- Para individual/no colectiva, los datos del XML pasan a GMS y luego se validan.

**Matriz de obligatoriedad**

`pago_forma = E`
```xml
<facturacion pago_forma="E" vto_grupo="2" emi_modo="1" />
```
No exige banco, sucursal, tipo cuenta, cuenta, tarjeta ni titular.

`pago_forma = T` tarjeta
```xml
<facturacion
    pago_forma="T"
    vto_grupo="2"
    emi_modo="1"
    cta="4111111111111111"
    tarje="1"
    titular="NOMBRE TITULAR" />
```
Obligatorio:
- `tarje`
- `cta` numérica
- `titular`
- si la tarjeta es débito: `tipo_cta` debe ser `CA` o `CC`
- `venci_fecha` no es obligatoria, pero si viene debe estar entre `1950-01-01` y `2050-12-31`

`pago_forma = N` CBU/débito bancario
```xml
<facturacion
    pago_forma="N"
    vto_grupo="2"
    emi_modo="1"
    banco="001"
    banco_suc="001"
    tipo_cta="CA"
    cta="1234567890" />
```
Obligatorio:
- `banco`
- `banco_suc`
- `tipo_cta` en `CA` o `CC`
- `cta` numérica

Para otras formas donde `PAGO_FORMAS.tipo_cobro = 'B'`, el código aplica la misma lógica bancaria: `banco`, `banco_suc`, `tipo_cta CA/CC` y `cta` numérica.
