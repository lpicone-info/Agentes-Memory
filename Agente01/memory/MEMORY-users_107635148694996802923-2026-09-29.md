Savina, tenés razón. Mostré una variante válida de SQL Server, pero distinta del formato estándar usado en las pruebas de solicitudes automáticas.

Ambas formas producen una variable de tipo `XML`:

```sql
DECLARE @xml XML

SET @xml = N'<solicitud>...</solicitud>'
```

Aquí SQL Server realiza una **conversión implícita** de texto a XML.

El formato utilizado en las pruebas realiza la conversión explícitamente:

```sql
DECLARE @var_data_xml XML

SET @var_data_xml = CAST(N'
<solicitud>
    ...
</solicitud>
' AS XML)
```

### Formato correcto para mantener el estándar de las pruebas AFE

```sql
DECLARE @var_data_xml XML
DECLARE @retorno INT

SET @var_data_xml = CAST(N'
<solicitud
    id_soli_externa="303459901"
    soli_moti="1">
    ...
</solicitud>
' AS XML)

EXEC @retorno = dbo.afi_insertar_soli_auto
    @var_data_xml = @var_data_xml

SELECT @retorno AS retorno
```

No existe una diferencia funcional en el procedimiento: recibe XML en ambos casos. Pero corresponde usar `@var_data_xml` y `CAST(... AS XML)` porque:

- coincide con los scripts de prueba existentes;
- deja explícita la conversión;
- permite detectar inmediatamente un XML mal formado;
- facilita comparar las pruebas entre los distintos motivos de solicitud.

Por lo tanto, el XML anterior debe envolverse con `CAST(N'...' AS XML)` siguiendo este formato.
