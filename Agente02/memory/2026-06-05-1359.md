user: Como funciona el multipart-form-data?
assistant: `multipart/form-data` es una forma de enviar un `POST` donde el body se divide en partes. Cada parte tiene un nombre de campo y su propio contenido.

En este caso sería como enviar un formulario con un campo llamado `msj`:

```text
POST /ws_auto_remotas/api/tx HTTP/1.1
Content-Type: multipart/form-data; boundary=----ABC123

------ABC123
Content-Disposition: form-data; name="msj"

<Mensaje>
  ...
</Mensaje>
------ABC123--
```

La clave es el `boundary`: es un separador que permite distinguir dónde empieza y termina cada campo del formulario. El cliente HTTP lo genera normalmente solo. Por eso con `curl` no hace falta escribirlo:

```bash
curl -X POST \
  "http://host:puerto/ws_auto_remotas/api/tx" \
  -F "msj=<Mensaje>...</Mensaje>"
```

El servlet recibe eso y puede leer:

```java
Part parte = request.getPart("msj");
String xml = leerContenido(parte);
```

o, según implementación/contenedor, también puede estar disponible como:

```java
String xml = request.getParameter("msj");
```

Para este caso, `msj` sería una parte de texto que contiene el XML completo. No es JSON, no es SOAP, y no va en la URL. La respuesta del endpoint sería el XML resultante directo en el body.
