### `canti`

Aunque inicialmente puede ser `""`, el schema exige que tenga valor:

```ts
if (item.canti === undefined) {

```

Por eso, al llegar a `onSubmit`, puede convertirse directamente:


### Importes opcionales

No podemos hacer directamente:

```ts
copaValor: Number(item.copaValor)
```

porque, si está vacío:

```ts
Number("") === 0
```

Se enviaría un copago de cero en vez de omitirlo.

Por eso se utiliza:

```ts
...(item.copaValor !== undefined &&
  item.copaValor !== "" && {
    copaValor: Number(item.copaValor)
  })
```

La propiedad solamente se incorpora cuando existe un valor.

Lo mismo aplica para los combos:

```ts
...(item.pagoCopa && {
  pagoCopa: item.pagoCopa
})
```

Si el combo está vacío, no se agrega `pagoCopa` al payload.

## Motivo de fondo

```text
canti
└── obligatorio → siempre se envía

copaValor, pagoCopa, excedente, pagoExce, presuValor
└── opcionales → solamente se envían cuando están informados
```

Pero el objeto tendría la propiedad con valor `undefined`. La expansión condicional construye un payload más limpio: la propiedad directamente no existe cuando el campo está vacío.
