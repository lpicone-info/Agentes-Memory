### [27/08/2026 12:15:37] Agente

Leandro, el circuito es este:

`aru_reset_pass` lo llama WebPOS desde el link de recuperación de contraseña.

Flujo:

1. En `index.php` está el botón de reset.
2. Ese botón ejecuta `reset_pass()` en `webpos/js/login_user.js`.
3. `reset_pass()` llama a `webpos/controlador/envio_reset_pass.php`.
4. `envio_reset_pass.php` llama a `Usuario::sendResetPass()`.
5. `sendResetPass()` ejecuta:

```sql
EXEC aru_reset_pass_envio @prm_usuari = ?, @prm_url = ?
```

6. Ese SP/envío manda un link a `reset_pass.php?u=...`.
7. Cuando el usuario abre ese link, `webpos/reset_pass.php` llama a `Usuario::resetPass()`.
8. `Usuario::resetPass()` ejecuta:

```sql
EXEC aru_reset_pass @prm_usuari = ?
```

Ese `aru_reset_pass` resetea la clave tomando el valor viejo de `ZZ_USUARI.pwd`, marca `cambia_pass = 'S'`, limpia `ZZ_INTENTOS` y deja `pwd = NULL`.

`aru_cambio_pass` lo llama WebPOS cuando el usuario ya está logueado y cambia la clave desde `cambia_pass.php`.

Flujo:

1. `cambia_pass.php`
2. JS `webpos/js/login_user.js`
3. `webpos/controlador/cambia_pass_proceso.php`
4. `Usuario::updatePassword($newPass)`
5. Ejecuta:

```sql
EXEC aru_cambio_pass @prm_usuario = ?, @prm_pass = ?, @prm_new_pass = ?
```

Ese SP valida la password actual contra `pwd_encript`, actualiza `pwd_encript`, pone `cambia_pass = 'N'` y limpia `ZZ_INTENTOS`.

Entonces sí hay forma de desbloquear, pero no desde el login normal cuando ya está bloqueado. Las vías actuales son:

```sql
EXEC dbo.aru_cant_errores @prm_usuario = '<usuario>'
```

o resetear contraseña por el circuito de recuperación, porque `aru_reset_pass` también limpia los intentos.
