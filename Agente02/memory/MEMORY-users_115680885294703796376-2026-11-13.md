Que es el query store?

---

### [13/11/2026 13:57:49] Agente

Leandro, **Query Store** es una funcionalidad de SQL Server que guarda un historial del comportamiento de las consultas de una base de datos.

Registra principalmente:

- Texto de las consultas.
- Planes de ejecución utilizados.
- Duración.
- CPU consumida.
- Lecturas lógicas y físicas.
- Cantidad de ejecuciones.
- Reservas de memoria.
- Esperas asociadas.
- Cambios de plan a lo largo del tiempo.

No guarda los resultados devueltos por las consultas ni los datos consultados.

## Para qué sirve

### Detectar regresiones

Permite identificar una consulta que antes:

- tardaba 100 ms;
- utilizaba determinado índice;
- consumía poca CPU;

y que después de cambiar la compatibilidad:

- tarda varios segundos;
- utiliza otro plan;
- realiza un scan completo;
- reserva demasiada memoria.

### Comparar compatibilidades

En este caso se puede:

1. Capturar el funcionamiento con compatibilidad 100.
2. Cambiar a 150 o 170.
3. Ejecutar la misma carga funcional.
4. Comparar planes y métricas anteriores contra las nuevas.

El cambio de compatibilidad invalida los planes de caché, pero **el historial de Query Store permanece**, permitiendo la comparación.

### Forzar un plan anterior

Si una consulta empeora, Query Store permite forzar temporalmente el plan que funcionaba correctamente, sin modificar el procedimiento:

```text
Consulta
 ├── Plan anterior: rápido
 └── Plan nuevo: lento
          ↓
     Forzar plan anterior
```

Esto funciona como mecanismo de estabilización mientras se analiza la causa real.

## Alcance

Query Store se configura **por base de datos**, no para todo el servidor. Tiene almacenamiento limitado y políticas de limpieza configurables.

En resumen, es una “caja negra” del rendimiento SQL: conserva qué consultas se ejecutaron, qué planes utilizaron y cómo rindieron antes y después de un cambio.
