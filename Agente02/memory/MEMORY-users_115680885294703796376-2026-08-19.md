Sí, Leandro. En este caso `APPLY` queda mejor y probablemente más eficiente.

Pero usaría `CROSS APPLY`, no `OUTER APPLY`, porque en esos bloques necesitás que exista una derivación candidata. `OUTER APPLY` sirve si querés conservar el registro padre aunque no encuentre derivación, y acá no haría falta.

La lógica actual hace 3 subconsultas correlacionadas:

```sql
PDA_T.obra_soc = (SELECT MAX(obra_soc) ...)
AND PDA_T.cuit = (SELECT MAX(cuit) ...)
AND PDA_T.vigen_aporte = (SELECT MAX(vigen_aporte) ...)
```

Eso obliga a resolver varias búsquedas para terminar eligiendo un único registro. Se puede reemplazar por algo así:

```sql
CROSS APPLY (
	SELECT TOP 1
					PDA_A.obra_soc,
					PDA_A.cuit,
					PDA_A.vigen_aporte,
					PDA_A.empresa,
					PDA_A.sueldo,
					PDA_A.vigen_hasta,
					PDA_A.sistema_deriv
	FROM PRECARGA_DERIV_APORTES PDA_A

	AND		PDA_A.item = PSA_T.item
	AND		PDA_A.baja_fecha IS NULL

	AND		(PDA_A.vigen_hasta IS NULL OR PDA_A.vigen_hasta > PS.apli_fecha)
	ORDER BY PDA_A.obra_soc DESC,
					 PDA_A.cuit DESC,
					 PDA_A.vigen_aporte DESC
) PDA_T
```
