### Precaución importante con ODBC 18

ODBC 18 es más estricto con cifrado y certificados TLS. Al migrar pueden aparecer errores de conexión si el SQL Server:

- no tiene un certificado válido;
- usa un certificado autofirmado;
- no tiene configurada correctamente la cadena de confianza;
- requiere una configuración explícita de `Encrypt`.

Por eso no conviene cambiar PHP, SQLSRV y ODBC simultáneamente sin pruebas comparativas.

1. PHP 8.4/8.5 + SQLSRV 5.13.x + ODBC 17.
2. Validar consultas, procedimientos almacenados, fechas, números, UTF-8, transacciones y adjuntos.
3. Luego probar ODBC 18 en un entorno separado.
4. Revisar explícitamente `Encrypt` y la validación del certificado.
5. No usar `TrustServerCertificate=true` como solución permanente en producción.

- **ODBC 17 no debe cambiarse obligatoriamente para soportar PHP 8.4/8.5.**
