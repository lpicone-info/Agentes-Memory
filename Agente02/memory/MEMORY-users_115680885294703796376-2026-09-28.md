El problema no estaba directamente en la llamada a la API de defaults, sino en la referencia de `cabecera`.

## Antes

`useAutorizacionCargaStore` devolvía un objeto nuevo en cada render:

```tsx
return {
  defaults,
  cabecera: {
    sucur,
    auto2,
    fecha,
    ordenFecha,
    valiFecha,
    prepaga,
    contra,
    inte,
    histo,
    icd
  }
};
```

Aunque los valores no cambiaran, `cabecera` tenía una referencia diferente.

En `AutorizacionCarga`, `cabecera` es dependencia de `initialValues`:

```tsx
const initialValues = useMemo(
  () => ({
    // ...
  }),
  [
    cabecera,
    defaults.diasAutoOrden,
    sucurUsuario,
    defaults.prepaga
  ]
);
```

Y posteriormente:

```tsx
useEffect(() => {
  reset(initialValues);
}, [initialValues, reset]);
```

Esto producía el ciclo:

```text
render
→ nuevo objeto cabecera
→ nuevo initialValues
→ reset(initialValues)
→ nuevo render
→ nuevo objeto cabecera
→ ...
```

## Corrección

Ahora `cabecera` se memoiza dentro de `useAutorizacionCargaStore`:

```tsx
const cabecera = useMemo(
  () => ({
    sucur,
    auto2,
    fecha,
    ordenFecha,
    valiFecha,
    prepaga,
    contra,
    inte,
    histo,
    icd
  }),
  [
    sucur,
    auto2,
    fecha,
    ordenFecha,
    valiFecha,
    prepaga,
    contra,
    inte,
    histo,
    icd
  ]
);
```

Y se devuelve la referencia memoizada:

```tsx
return {
  defaults,
  cabecera
};
```

De esta manera, `cabecera` solo cambia de referencia cuando cambia realmente alguno de sus campos.

## Resultado

Cuando llegan los defaults desde la API:

```text
defaults cambia
→ se recalcula initialValues
→ reset(initialValues) se ejecuta una vez
→ el formulario queda inicializado
```

Los renders posteriores mantienen la misma referencia de `cabecera`, por lo que `initialValues` tampoco cambia y el efecto no vuelve a ejecutar `reset()` indefinidamente.

El `reset()` continúa siendo necesario; la corrección consistió en estabilizar sus dependencias.

Hay tres alternativas.

## 1. Volver a `register` — recomendada

`FormSelect` representa un `<select>` HTML nativo. No necesita ser controlado mediante `useController`.

```tsx
const { register } = useFormContext<TFieldValues>();
const { errors, touchedFields } = useFormState({
  name
});

const registration = register(name);
const error = get(errors, name) as
  | { message?: string }
  | undefined;

const isTouched = Boolean(get(touchedFields, name));
const message = error?.message;
```

Y el select:

```tsx
<Form.Select
  {...rest}
  {...registration}
  onBlur={(event) => {
    registration.onBlur(event);
    handleBlur?.(event);
  }}
  onChange={(event) => {
    registration.onChange(event);
    handleChange?.(event);
  }}
  isValid={isTouched && !message}
  isInvalid={!!message}
>
  {children}
</Form.Select>
```

Ventajas:

- elimina la advertencia;
- mantiene el select no controlado;
- evita renders por cada cambio de valor;
- `setValue()` sigue funcionando con campos registrados;
- coincide con la implementación anterior que superaba el lint.

Esta sería mi elección para `FormSelect`.

## 2. Usar el componente `Controller`

Si por algún motivo se necesita mantenerlo controlado, puede reemplazarse `useController` por `Controller`:

```tsx
const { control } = useFormContext<TFieldValues>();

return (
  <Controller
    name={name}
    control={control}
    render={({ field, fieldState }) => (
      <Form.Select
        {...rest}
        name={field.name}
        ref={field.ref}
        value={field.value ?? ""}
        onBlur={(event) => {
          field.onBlur();
          handleBlur?.(event);
        }}
        onChange={(event) => {
          field.onChange(event);
          handleChange?.(event);
        }}
        isValid={fieldState.isTouched && !fieldState.error}
        isInvalid={!!fieldState.error}
      >
        {children}
      </Form.Select>
    )}
  />
);
```

Esto evita que ESLint interprete el valor devuelto directamente por un hook como un ref leído durante el render.

Es válido, pero para un `<select>` nativo agrega una capa controlada innecesaria.

## 3. Desactivar la regla localmente

Se puede deshabilitar solo para el archivo:

```tsx
/* eslint-disable react-hooks/refs */
```

O mediante un override en `eslint.config.js`:

```tsx
{
  files: ["src/ui/FormSelect.tsx"],
  rules: {
    "react-hooks/refs": "off"
  }
}
```

Esto oculta el falso positivo, pero también elimina una validación útil para futuros refs reales dentro del componente.

Mantener el select controlado, pero usar el componente `Controller` para evitar el falso positivo de ESLint:

```tsx
import {
  Controller,
  useFormContext
} from "react-hook-form";
```

```tsx
const { control } = useFormContext<TFieldValues>();
```

```tsx
<Controller
  name={name}
  control={control}
  render={({ field, fieldState }) => {
    const message = fieldState.error?.message;

    return (
      <Form.Group
        className={className}
        controlId={name}
        {...params}
      >
        {label && (
          <Form.Label className={classNameLabel}>
            {label}
          </Form.Label>
        )}

        <Form.Select
          {...rest}
          name={field.name}
          ref={field.ref}
          value={field.value ?? ""}
          onBlur={(event) => {
            field.onBlur();
            handleBlur?.(event);
          }}
          onChange={(event) => {
            field.onChange(event);
            handleChange?.(event);
          }}
          isValid={fieldState.isTouched && !message}
          isInvalid={!!message}
        >
          {children}
        </Form.Select>

        <Form.Control.Feedback type="invalid">
          {message}
        </Form.Control.Feedback>
      </Form.Group>
    );
  }}
/>
```

Así se conservan ambas necesidades:

- el valor cargado con `setValue()` queda seleccionado cuando llegan las opciones;
- el campo continúa controlado por RHF;
- se evita acceder directamente durante el render al objeto devuelto por `useController`;
- no es necesario desactivar globalmente `react-hooks/refs`.

Por lo tanto, considerando la carga asincrónica de los combos, **mantendría el comportamiento controlado y reemplazaría `useController` por `Controller`**.
