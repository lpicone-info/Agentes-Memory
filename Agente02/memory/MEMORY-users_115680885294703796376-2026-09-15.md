Existe alguna manera de ejecutar un caso de prueba parecido a como hicimos con playwright pero para la aplicación legacy afilmed o presmed realizada en powerbuilder?

---

### [15/09/2026 11:48:25] Agente

Sí, existe, pero no con Playwright directamente.

Para PowerBuilder desktop hay que usar automatización de UI Windows. Las opciones razonables son:

1. **WinAppDriver / Appium Windows**
   Permite automatizar una aplicación Windows como si fuera Selenium/Playwright: abrir la app, buscar controles, escribir campos, hacer click, validar textos y tomar screenshots.
   Es la opción más parecida conceptualmente a Playwright.

2. **pywinauto**
   Muy útil si la app expone controles Windows estándar o accesibles. Se puede scriptar en Python:
   - abrir `afilmed.exe` o `presmed.exe`
   - loguear
   - navegar ventanas
   - completar campos
   - validar valores
   - capturar pantalla

3. **AutoIt / AutoHotkey**
   Más simple y práctico para legacy duro, pero menos robusto. Sirve cuando los controles no son fáciles de identificar y hay que trabajar por coordenadas, títulos de ventana o navegación con teclado.

4. **Prueba híbrida**
   Para PowerBuilder suele ser la más efectiva:
   - automatizar UI solo para el flujo visible
   - validar efectos en base de datos con SQL
   - guardar screenshots
   - dejar un `resultado.json` o reporte similar al de Playwright

La limitación principal es que PowerBuilder no siempre expone bien los controles internos, especialmente DataWindows. Si los controles son accesibles, se puede hacer bastante robusto. Si no, hay que apoyarse más en teclado, coordenadas, screenshots y validación por base.

Mi recomendación para `afilmed` o `presmed`: probar primero con `pywinauto` sobre una pantalla concreta. Si puede detectar ventanas, botones, edits y DataWindows con nombres/control IDs, armamos una prueba bastante parecida a la de Playwright, con screenshots y resultado trazable.

---

### [15/09/2026 11:51:20] Agente

Puede tener cualquiera de los dos, pero para automatizar una prueba tipo “usuario real”, el punto de partida principal es el **EXE**.

- **Con el EXE:** se prueba la aplicación compilada, como la usa el usuario. Es lo más parecido a Playwright: abrir `afilmed.exe`/`presmed.exe`, loguear, navegar, cargar datos, validar pantalla y sacar screenshots.

- **Con el código fuente:** sirve para entender nombres de ventanas, flujo, DataWindows, SQL invocado y controles esperados. Ayuda muchísimo para diseñar la prueba, pero no reemplaza la ejecución real.

Lo ideal para legacy PowerBuilder es híbrido:

1. Ejecutar el **EXE** para la prueba end-to-end.
2. Usar el **código fuente** para saber qué ventana abrir, qué campos tocar y qué validar.
3. Usar la **base de datos** para confirmar resultados cuando la UI no sea fácil de inspeccionar.

Si queremos una prueba automática real, arrancaría desde el EXE.
