assistant: Sí, **puede afectar performance**, pero probablemente de forma menor salvo que el volumen sea alto.

Como lo definiste:

```sql
LEFT JOIN PRESTADORES AS PR_EFE
ON PR_EFE.prestad = AU.efe_prestad

LEFT JOIN PRESTADORES AS PR_SANA
ON PR_SANA.prestad = AU.efe_sana
```

SQL Server intenta resolver **ambos joins** por cada autorización, aunque después el `CASE` use primero `PR_EFE`.

En cambio, con:

```sql
LEFT JOIN PRESTADORES AS PR_SANA
ON PR_SANA.prestad = AU.efe_sana
AND AU.efe_prestad IS NULL
```

le das una condición adicional para evitar buscar `PR_SANA` cuando ya existe `efe_prestad`.

## Diferencia práctica

- **Resultado funcional:** igual.
- **Performance:** la versión con `AND AU.efe_prestad IS NULL` puede ser mejor.
- **Impacto real:** depende de:
  - cantidad de autorizaciones devueltas
  - índice sobre `PRESTADORES.prestad`
  - porcentaje de registros con `efe_prestad` informado

Si `PRESTADORES.prestad` está indexado y el SP devuelve pocas filas, la diferencia probablemente sea chica.  
Si devuelve muchas autorizaciones, conviene agregar la condición.
