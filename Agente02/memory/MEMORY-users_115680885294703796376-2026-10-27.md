## Script recomendado para obtener la lista real en el cliente

La lista del repositorio es estática. Para contemplar procedimientos o tablas instalados específicamente en el cliente, conviene ejecutar primero este relevamiento en la base del cliente:

```sql
SET NOCOUNT ON

CREATE TABLE #objetos
(
    object_id INT NOT NULL PRIMARY KEY
)

INSERT INTO #objetos
SELECT o.object_id
FROM sys.objects o
INNER JOIN sys.schemas s
    ON s.schema_id = o.schema_id
WHERE s.name = 'dbo'
AND o.name IN
(
    'pri_auto_remotas_webpos',
    'pri_auto_prestac_items_remotas',
    'prs_valida_of_auto_remotas'
)
AND o.type = 'P'

WHILE 1 = 1
BEGIN
    INSERT INTO #objetos
    SELECT DISTINCT d.referenced_id
    FROM sys.sql_expression_dependencies d
    INNER JOIN #objetos o
        ON o.object_id = d.referencing_id
    INNER JOIN sys.objects r
        ON r.object_id = d.referenced_id
    WHERE d.referenced_id IS NOT NULL
    AND r.is_ms_shipped = 0
    AND r.type IN ('P', 'V', 'IF', 'TF', 'FN', 'FS', 'FT')
    AND NOT EXISTS
    (
        SELECT 1
        FROM #objetos x
        WHERE x.object_id = d.referenced_id
    )

    IF @@ROWCOUNT = 0
        BREAK
END

SELECT DISTINCT
    s.name AS esquema,
    t.name AS tabla
FROM #objetos o
INNER JOIN sys.sql_expression_dependencies d
    ON d.referencing_id = o.object_id
INNER JOIN sys.tables t
    ON t.object_id = d.referenced_id
INNER JOIN sys.schemas s
    ON s.schema_id = t.schema_id
ORDER BY s.name, t.name
```

Ese `SELECT` es la lista efectiva de tablas reconocidas por SQL Server en la instalación concreta.

## Generación de las sentencias

Para generar las tres sentencias por cada tabla detectada:

```sql
SELECT
    'ALTER INDEX ALL ON '
    + QUOTENAME(s.name) + '.' + QUOTENAME(t.name)
    + ' REBUILD' AS sentencia
FROM #objetos o
INNER JOIN sys.sql_expression_dependencies d
    ON d.referencing_id = o.object_id
INNER JOIN sys.tables t
    ON t.object_id = d.referenced_id
INNER JOIN sys.schemas s
    ON s.schema_id = t.schema_id
GROUP BY s.name, t.name

UNION ALL

SELECT
    'UPDATE STATISTICS '
    + QUOTENAME(s.name) + '.' + QUOTENAME(t.name)
    + ' WITH COLUMNS'
FROM #objetos o
INNER JOIN sys.sql_expression_dependencies d
    ON d.referencing_id = o.object_id
INNER JOIN sys.tables t
    ON t.object_id = d.referenced_id
INNER JOIN sys.schemas s
    ON s.schema_id = t.schema_id
GROUP BY s.name, t.name

UNION ALL

SELECT
    'EXEC sp_recompile '''
    + s.name + '.' + t.name
    + ''''
FROM #objetos o
INNER JOIN sys.sql_expression_dependencies d
    ON d.referencing_id = o.object_id
INNER JOIN sys.tables t
    ON t.object_id = d.referenced_id
INNER JOIN sys.schemas s
    ON s.schema_id = t.schema_id
GROUP BY s.name, t.name
ORDER BY sentencia
```

## Observaciones importantes

- `ALTER INDEX ALL ... REBUILD` ya actualiza las estadísticas de índices, pero no necesariamente todas las estadísticas de columnas.
- `UPDATE STATISTICS ... WITH COLUMNS` cubre las estadísticas de columnas.
- `sp_recompile` no actualiza estadísticas: marca procedimientos dependientes para recompilación.
- `sp_recompile` sobre las 151 tablas puede provocar muchas recompilaciones y afectar temporalmente el rendimiento.
- `temp_copagos` es una tabla de trabajo asociada a sesiones y no la incluiría en una reconstrucción masiva sin validar antes su uso.
- El procedimiento `prs_valida_of_auto_remotas` contiene llamadas a rutinas específicas de cliente que no están todas presentes en el directorio base del repositorio. Por eso, la consulta contra `sys.sql_expression_dependencies` en la base del cliente es la validación definitiva.
