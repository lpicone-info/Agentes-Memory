### [28/10/2026 16:53:13] Agente

La diferencia principal es **quién ejecuta la validación y cómo devuelve el resultado**.

## `validateField("campo")`

Es una función imperativa de Formik:

```javascript
await validateField("prepaga");
```

Formik:

1. Busca la validación del campo.
2. Si existe un `validate` propio del campo, lo ejecuta.
3. Si existe `validationSchema`, ejecuta la validación Yup correspondiente.
4. Actualiza internamente `errors`.
5. No devuelve directamente el mensaje de error.

El problema para este caso es que necesitamos validar varios campos y decidir inmediatamente si abrir o no la carga del integrante. Por ejemplo:

```javascript
for (const campo of camposCabecera) {
  await validateField(campo);
}
```

Después de esas llamadas, `errors` puede no estar actualizado todavía dentro del mismo callback, porque Formik actualiza el estado de forma asíncrona. Eso obliga a depender de otro render o de lógica adicional para saber si hubo errores.

## `schema.validateAt("campo", values)`

Es la validación directa de Yup:

```javascript
await schema.validateAt("prepaga", values);
```

- Ejecuta la regla del campo.
- Devuelve correctamente si es válida.
- Lanza una excepción con el mensaje si es inválida.
- No modifica el estado de Formik automáticamente.

Por eso permite recolectar los errores de forma determinística:

```javascript
const errores = {};

for (const campo of camposCabecera) {
  try {
    await schema.validateAt(campo, values);
  } catch (error) {
    errores[campo] = error.message;
  }
}
```

Luego se actualiza Formik explícitamente:

```javascript
setFieldError(campo, mensaje);
setFieldTouched(campo, true, false);
```

## Comparación

| Aspecto | `validateField` | `schema.validateAt` |
|---|---|---|
| Pertenece a | Formik | Yup |
| Usa el schema Yup | Sí | Sí |
| Actualiza `errors` automáticamente | Sí | No |
| Devuelve directamente el error | No | Sí, mediante excepción |
| Permite recolectar varios errores inmediatamente | Menos conveniente | Sí |
| Ejecuta validaciones `validate` propias del campo | Sí | No |
| Requiere un schema nuevo | No | No |

## Para este caso

Como las validaciones actuales de `ResumenPrecarga` están definidas en el `schema` Yup y no mediante funciones `validate` individuales, ambas alternativas aplicarían las mismas reglas.

La diferencia práctica es que:

- `validateField` es más idiomático para validar un campo y dejar que Formik administre el estado.
- `schema.validateAt` es más conveniente para validar varios campos de cabecera y decidir inmediatamente si se abre `CargaIntegrante`.

Por eso, para este botón puntual, usaría `schema.validateAt` sobre el schema existente, sin crear un schema adicional.
