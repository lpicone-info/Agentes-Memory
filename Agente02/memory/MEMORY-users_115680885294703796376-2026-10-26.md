## ¿Funciona ingresando primero el token?

Sí, con el código actual debería funcionar.

El token puede ingresarse primero porque:

- el campo permanece cargado;
- `limpiar_campos('contra')` no borra el token;
- cuando luego se busca el afiliado, `generar()` lee el valor actual de `#token`.

Por lo tanto, el orden recomendado actualmente es:

```text
1. Entidad
2. Token
3. Contrato/integrante o documento
```

Al completar la búsqueda del afiliado, la transacción automática debería enviarse con el token informado.

## Solución mínima de código

Evitar la generación automática de 01A cuando el token obligatorio todavía está vacío:

```javascript
if (
    tipoTransac == '01A' &&
    $('#nroTransacR').length == 0 &&
    $.trim($('#token').val()).length > 0
) {
    generar('N')
}
```

Esto resuelve el caso si 01A está configurada siempre como obligatoria en ese entorno.

Si 01A puede ser obligatoria o no según configuración, la solución correcta es que PHP entregue al JavaScript un indicador de `obliga_token`. La condición debería ser:

```javascript
if (
    tipoTransac == '01A' &&
    $('#nroTransacR').length == 0 &&
    (!obligaToken || $.trim($('#token').val()).length > 0)
) {
    generar('N')
}
```

La alternativa más rápida y sin riesgo funcional inmediato es usar el orden **token primero, afiliado después**.
