## Requerimiento Redmine 30103 - WS Farmacia / token afiliado
- Usuario: Cesar.
- Pedido original: analizar impacto del requerimiento 30103 sin modificar archivos.
- Requerimiento: "WS Farmacia - sumar el TOKEN a la validacion del afiliado", estado En Analisis, producto Otros Webservices, ticket InvGate 5851.
- Primer analisis corregido luego por documentacion: inicialmente se habia asociado a `RegistrarConsumoFarmacia.guardar` y `AUTO_REMOTAS`, pero la peticion SOAP aportada por Cesar corresponde a `ValidacionAfiliadosGeneral`, no al consumo de farmacia.
- Peticion SOAP relevante: operacion `ser:ValidacionAfiliadosGeneral` con namespace `http://service.autorem.com/`, parametros `cuitFarma`, `prepaga`, `numeroCategoria`, `petAdic1` a `petAdic6`.
- Evidencia local revisada: servicio `ws_generales/src/java/service/ValidacionAfiliados.java`, BO `AfiliadoBO.java`, DAO `AfiliadoDAO.java`, SP `backend/procedures/ars_csf_validacion_afiliados.sql`.
- Impacto corregido: concentrado en `ws_generales` + `ars_csf_validacion_afiliados`; no deberia tocar `RegistrarConsumoFarmacia`, `pri_auto_remotas_farma` ni `AUTO_REMOTAS.token` para esa peticion.
- Hipotesis tecnica: usar uno de los `petAdic` existentes, probablemente `petAdic1`, para transportar token sin cambiar contrato SOAP. Si se agrega tag explicito `<token>`, cambia WSDL e impacta consumidores.
- Criterios de validacion propuestos para procedure reusable: respetar parametro global `Generan token de seguridad`; revisar `tr_tran_tipos.usa_token` y `obliga_token`; si no usa token no valida; si no obligatorio y no viene token no valida; si obligatorio/no existe token error 1449; baja error 1450; vencido error 1451; contemplar exencion por prestador/farmacia si se puede mapear `cuitFarma`.
- Se propuso conceptualmente un SP `dbo.prs_valida_token_afiliado_csf` con parametros `@prm_docu_tipo`, `@prm_docu_nro`, `@prm_token`, `@prm_cuitFarma`, `@prm_tran_tipo`, `@out_error`, `@out_exento`.
- Punto pendiente confirmado como incertidumbre: validar si `prestad_exen_token.prestad` corresponde realmente a `farmacias.farma` antes de implementar exenciones.
- Explicacion dada sobre `xmlns:ser="http://service.autorem.com/"`: es namespace SOAP generado por JAX-WS desde package/clase, `ser` es solo prefijo XML; no implica existencia de dominio externo.

## Error `Cannot GET /standard/precarga/prod/index.jsp`
- Usuario reporto error de navegacion.
- Analisis dado: la URL pega a un servidor Express/Node esperando JSP, pero la app revisada de precarga es React; no hay `index.jsp` para esa ruta.
- Rutas frontend observadas: `/precarga/*`, `/precarga/carga`.
- APIs backend Node observadas: `/api/auth`, `/api/combo`, `/api/precarga`.
- Causas probables: URL vieja de despliegue Java/JSP, reverse proxy apuntando al backend Node en lugar del build frontend, falta rewrite/fallback a `index.html`, o mismatch con base publica `/standard/precarga/prod/`.
- Conclusion dada: la entrada correcta deberia resolver a `index.html` del frontend React, no a `index.jsp`; backend Node solo responderia si se configura estaticos/redireccion.
