## Campos que determinan el estado

| Campo | Interpretación |
|---|---|
| `baja_fecha` | Retirado |
| `liqui_fecha` | Liquidado |
| `super_fecha` | Supervisado / A liquidar |
| `audi_fecha` | Auditado / A supervisar |
| `cierre_admin_fecha` | Cierre administrativo / A auditar |
| `revi_fecha` | Revisado / A cierre administrativo |
| `carga_fecha` | Cargado / A revisar |
| Todas las anteriores nulas | Ingresado o en carga |

El orden es importante: debe evaluarse desde el estado más avanzado hacia el inicial.

## Consulta recomendada

```sql
DECLARE @ofi SMALLINT = 1
DECLARE @expe INT = 4531146

SELECT
    e.ofi,
    e.expe,
    e.carga_fecha,
    e.revi_fecha,
    e.cierre_admin_fecha,
    e.audi_fecha,
    e.super_fecha,
    e.liqui_fecha,
    e.baja_fecha,
    estado =
        CASE
            WHEN e.baja_fecha IS NOT NULL
                THEN 'Retirado'
            WHEN e.liqui_fecha IS NOT NULL
                THEN 'Liquidado'
            WHEN e.super_fecha IS NOT NULL
                THEN 'A liquidar'
            WHEN e.audi_fecha IS NOT NULL
                THEN 'A supervisar'
            WHEN e.cierre_admin_fecha IS NOT NULL
                THEN 'A auditar'
            WHEN e.revi_fecha IS NOT NULL
                THEN 'A cierre administrativo'
            WHEN e.carga_fecha IS NOT NULL
                THEN 'A revisar'
            WHEN e.item_nro = 0
                THEN 'Ingresado'
            ELSE 'En carga'
        END
FROM expedientes e
WHERE e.ofi = @ofi
AND e.expe = @expe
```

John, el mecanismo puede denominarse **control de concurrencia de expedientes**. En el código de Presmed se implementa como **uso de ventanas por expediente**.

No es un bloqueo SQL tradicional: es un registro de presencia que avisa qué usuarios tienen abierto el expediente.

## Tablas utilizadas

### `USO_VENTANAS_EXPE`

Registra cada usuario que abre un expediente:

| Campo | Contenido |
|---|---|
| `expe` | Número de expediente |
| `usuari` | Usuario de Presmed |
| `etapa` | Etapa o ventana donde trabaja |
| `fecha_acceso` | Fecha y hora de apertura |

La clave es:

```text
expe + usuari + etapa
```

### `USO_VENTANAS_EXPE_ETAPAS`

| `C` | Carga |

## Cómo funciona

### 1. Al abrir una ventana

La aplicación consulta:

```text
prs_uso_ventanas_expe
```

Este procedimiento busca usuarios registrados para el expediente y la etapa. Si encuentra alguno, construye un mensaje como:

```text
Usuarios en expediente:
USUARIO 2026-10-27 10:35:20 (Auditoría)
```

### 2. Registra al usuario actual

Después ejecuta:

```text
pru_uso_ventanas_expe
```

- Si ya existe el usuario para ese expediente y etapa, actualiza `fecha_acceso`.
- Si no existe, inserta el registro.

### 3. Al cerrar la ventana

Ejecuta:

```text
prd_uso_ventanas_expe
```

y elimina el registro correspondiente al usuario, expediente y etapa.

## ¿Bloquea al segundo usuario?

En las ventanas revisadas, **no lo bloquea**. Muestra la advertencia, pero después registra también al segundo usuario y permite continuar.

Por tanto, es un control de concurrencia **informativo o preventivo**, no un bloqueo exclusivo. Ambos usuarios podrían modificar el expediente, por lo que las operaciones posteriores deben controlar estados y datos nuevamente antes de guardar.

Por ejemplo, en Auditoría Médica:

```text
Consulta usuarios etapa A
→ muestra el aviso
→ registra al usuario actual
→ permite abrir la auditoría
```

## Consultar quién tiene abierto un expediente

```sql

    u.expe,
    u.usuari,
    u.fecha_acceso,
    u.etapa,

INNER JOIN uso_ventanas_expe_etapas e
    ON e.etapa = u.etapa
WHERE u.expe = @expe
ORDER BY u.fecha_acceso
```

## Consideraciones técnicas

1. **No registra `ofi`:** aunque la clave real del expediente es [SECRETO REDACTADO]

2. **Puede dejar registros residuales:** la liberación ocurre al cerrar correctamente la ventana. Si Presmed termina abruptamente, se pierde la conexión o se ejecuta `Halt`, el registro podría permanecer.

3. **No existe vencimiento automático:** el código revisado no elimina registros por antigüedad ni mantiene un heartbeat. `fecha_acceso` representa el momento del registro o su última actualización.

4. **No garantiza exclusividad:** el aviso no impide que otro usuario continúe trabajando.

```sql
AND eoi.baja_fecha IS NULL
AND eo.baja_fecha IS NULL
AND EXISTS
(

    FROM expe_errores ea
    WHERE ea.ofi = ee.ofi
    AND ea.expe = ee.expe
    AND ea.item = ee.item
    AND ea.orden = ee.orden
```
