# Paso 2 — Crear el procedimiento de consulta

prs_auto_url_analisis_ia

## Script propuesto

```sql
IF OBJECT_ID('dbo.prs_auto_url_analisis_ia') IS NOT NULL
    DROP PROCEDURE dbo.prs_auto_url_analisis_ia
GO

/*
    Procedure      : prs_auto_url_analisis_ia

    Creation Date  : <fecha>

    Programmer     : whiguera

    Description    : Recupera la URL del último análisis IA
                     relacionado con una autorización.

    Bug            : DATE        PROGRAMMER      DESCRIPTION      REFERENCE
*/

CREATE PROCEDURE dbo.prs_auto_url_analisis_ia
(
    @sucur SMALLINT,
    @auto  INT
)
AS
BEGIN

    SET NOCOUNT ON

    SELECT TOP 1
        url_presmed = IA.url_presmed
    FROM saludmp.flujo_ia_autorizaciones IA WITH (NOLOCK)

    INNER JOIN dbo.AUTORIZACIONES A WITH (NOLOCK)
        ON A.sucur = IA.sucur
        AND A.auto = IA.autorizacion

    WHERE A.sucur = @sucur
    AND A.auto = @auto
    AND A.estado_procesamiento_ia = 'F'

    ORDER BY IA.orden_recuperacion DESC

END
GO
```

## Por qué se conserva el `INNER JOIN`

Aunque sucursal y autorización existan en `flujo_ia_autorizaciones`, el `INNER JOIN` permite aplicar la condición funcional:

```sql
A.estado_procesamiento_ia = 'F'
```

Así la base vuelve a proteger el flujo aunque el procedimiento sea invocado desde otro lugar distinto del botón.

## Por qué devuelve solamente `url_presmed`

PowerBuilder solo necesita la URL para abrir el visor. La columna de orden sirve internamente para elegir el registro, pero no forma parte del contrato de salida.

El procedimiento tendrá este contrato:

```text
Parámetros de entrada:
    @sucur
    @auto

Resultado:
    Una fila con url_presmed
    o ninguna fila
```

Wilmer, ahora entiendo: pensaban crear una columna calculada con `ROW_NUMBER()` según el orden en que SQL Server recupere las filas.

Eso **no sería confiable** porque SQL Server no garantiza un orden natural de recuperación. Sin un `ORDER BY` basado en un dato físico, conceptos como “primero” y “último” no existen.

## Lo que no debemos hacer

```sql
ROW_NUMBER() OVER (ORDER BY (SELECT NULL)) AS orden_recuperacion
```

Aunque genera números, el orden puede variar entre ejecuciones por:

- Plan de ejecución.
- Índices utilizados.
- Paralelismo.
- Estadísticas.
- Cambios internos de SQL Server.

Por tanto, hoy podría devolver una URL y mañana otra.

## Uso correcto de una columna calculada

Podemos crear `orden_recuperacion` con `ROW_NUMBER()`, pero necesitamos ordenarla por una columna real de la tabla, por ejemplo:

```sql
ROW_NUMBER() OVER
(
    ORDER BY
        IA.fecha_registro,
        IA.id
) AS orden_recuperacion
```

Después se toma el último:

```sql
WITH CTE_URL AS
(
    SELECT
        IA.url_presmed,
        orden_recuperacion = ROW_NUMBER() OVER
        (
            ORDER BY
                IA.fecha_registro,
                IA.id
        )
    FROM saludmp.flujo_ia_autorizaciones IA

    INNER JOIN dbo.AUTORIZACIONES A
        ON A.auto = IA.autorizacion
        AND A.sucur = IA.sucur

    WHERE A.sucur = @sucur
    AND A.auto = @auto
    AND A.estado_procesamiento_ia = 'F'
)
SELECT TOP 1
    url_presmed
FROM CTE_URL
ORDER BY orden_recuperacion DESC
```

Pero esto exige que existan columnas como:

```text
fecha_registro
id
consecutivo
fecha_procesamiento
fecha_modificacion
```

## Solución más simple

Si existe una columna que define el orden, no necesitamos crear `ROW_NUMBER()`. Podemos hacer directamente:

```sql
SELECT TOP 1
    url_presmed = IA.url_presmed
FROM saludmp.flujo_ia_autorizaciones IA

INNER JOIN dbo.AUTORIZACIONES A
    ON A.auto = IA.autorizacion
    AND A.sucur = IA.sucur

WHERE A.sucur = @sucur
AND A.auto = @auto
AND A.estado_procesamiento_ia = 'F'

ORDER BY
    IA.fecha_registro DESC,
    IA.id DESC
```

Esta alternativa es más clara y eficiente.

## Si la tabla no tiene ninguna columna de orden

En ese caso no es posible identificar correctamente el último registro existente. Las únicas soluciones seguras serían:

1. Agregar una columna física `IDENTITY` o consecutiva.
2. Agregar una fecha de creación con precisión suficiente.
3. Solicitar a COOMEVA que informe qué campo determina el orden.
4. Hacer que el proceso que inserta los registros genere un consecutivo.

Una columna física posible sería:

```sql
orden_recuperacion BIGINT IDENTITY(1,1) NOT NULL
```

Pero tiene una consideración: al agregarla sobre registros históricos, SQL Server asignará valores a esos registros, pero eso no garantiza que representen su orden cronológico original. Serviría confiablemente para los registros nuevos.
