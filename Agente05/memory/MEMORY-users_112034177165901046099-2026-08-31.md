**Problemática**

El sistema actual no tiene cerrado el circuito para que las solicitudes de autorizaciones creadas desde App/Web sean derivadas a la IA de COOMEVA antes de ser asignadas a usuarios PRESMED.

El EF define que la IA debe poder:

- Recuperar solicitudes pendientes de procesamiento IA.
- Consultar datos de solicitud, tipo, estado, fecha, `api_id_dir` y adjuntos.
- Procesar soportes para identificar CUPS y conceptos.
- Devolver a PRESMED los CUPS, cantidades, conceptos y resultado del procesamiento.
- Recién después permitir que la solicitud entre al proceso normal de asignación masiva.

Hoy en `InstallQA` no existen todavía los campos requeridos en `SOLICITUDES_AUTO`: `procesaIA`, `fecha_procesaIA`, `resultado_procesaIA`. Tampoco existe el SP nuevo sugerido `pru_registra_solicitudes_auto_IA`.

**Solución Propuesta**

Implementar el flujo en 4 partes:

1. Modificar `SOLICITUDES_AUTO` agregando:
   - `procesaIA CHAR(1)`
   - `fecha_procesaIA DATETIME`
   - `resultado_procesaIA VARCHAR(100)`

2. Modificar `pru_wrapper_registra_solicitudes_auto` para recibir `@prm_procesaIA CHAR(1) = 'N'`, validar solo `S` o `N`, y grabarlo al crear la solicitud.

3. Modificar `pru_proceso_asignacion_masiva` para excluir solicitudes con `procesaIA = 'S'` y `fecha_procesaIA IS NULL`. Cuando `fecha_procesaIA` ya tenga valor, debe entrar al flujo normal.

4. Crear dos SP:
   - SP de recupero de solicitudes para IA: devuelve solicitudes `procesaIA = 'S'`, `fecha_procesaIA IS NULL`, estado `R`, tipo `D`, `H` o `Q`, con adjuntos obligatorios.
   - `pru_registra_solicitudes_auto_IA`: recibe solicitud, tipo opcional, listas de nomenclador, CUPS, cantidad y concepto, valida todo, inserta prestaciones/conceptos y marca la solicitud como procesada por IA.
