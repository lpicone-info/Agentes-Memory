## Por qué se repiten las solicitudes

El defecto está en este `JOIN`:

```sql
INNER JOIN PLANES AS PLA
    ON  PLA.prepaga = APLA.prepaga
    AND PLA.plan_codi = APLA.plan_codi
    AND PLA.baja_fecha IS NULL
     OR PLA.baja_fecha >= SA.fecha
```

SQL Server interpreta la condición así:

```sql
(
    PLA.prepaga = APLA.prepaga
    AND PLA.plan_codi = APLA.plan_codi
    AND PLA.baja_fecha IS NULL
)
OR PLA.baja_fecha >= SA.fecha
```

Por la precedencia de `AND` sobre `OR`, cualquier registro de `PLANES` cuya `baja_fecha` sea posterior a la fecha de la solicitud se relaciona con ella, aunque no coincidan:

- `prepaga`
- `plan_codi`

Por eso la grilla repite:

- número de solicitud;
- datos de la solicitud;
- afiliado;
- contrato e integrante;

pero muestra diferentes programas provenientes de filas de `PLANES` que no corresponden al afiliado.

## Modificación necesaria

Debe agruparse la condición de vigencia de `PLANES`:

```sql
INNER JOIN PLANES AS PLA
    ON  PLA.prepaga = APLA.prepaga
    AND PLA.plan_codi = APLA.plan_codi
    AND (
           PLA.baja_fecha IS NULL
        OR PLA.baja_fecha >= SA.fecha
    )
```

Cambio puntual:

```diff
- AND PLA.baja_fecha IS NULL OR PLA.baja_fecha >= SA.fecha
+ AND (PLA.baja_fecha IS NULL OR PLA.baja_fecha >= SA.fecha)
```

Esto obliga a que siempre coincidan `prepaga` y `plan_codi`, y luego evalúa si el programa estaba vigente.
