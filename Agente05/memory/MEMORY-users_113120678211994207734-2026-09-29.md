# Hallazgos críticos

## 1. Falta `@SoliAutoStart`

El documento exige un número inicial opcional:

```sql
@SoliAutoStart NUMERIC(...)
```

Cuando se informe, debe comenzar la numeración desde ese valor. Si llega `NULL`, puede utilizarse la secuencia o el máximo existente más uno.

El SP solamente declara:

```sql
@prm_fechadesde DATETIME,
@prm_fechahasta DATETIME,
@prm_transaccion CHAR(1) = 'S'
```

Evidencia: [líneas 15-19](/home/desarrollo-ia-05/.openclaw/workspace/media/inbound/openclaw-staged-a2f5cc9b-6cb3-47ca-9534-9aba80a30295/input-pru_genera_solicitudes_auto_histo---8a4c8de4-c77e-4b57-bed8-6983fb8a9c4c.sql:15).

Por lo tanto, no permite controlar el comienzo de la numeración histórica.

## 2. Falta completamente el DryRun

El documento exige:

```text
@DryRun = 1
```

para:

- No insertar.
- Mostrar conteos.
- Presentar la vista previa.
- Permitir validar la migración antes de confirmarla.

`@prm_transaccion = 'N'` **no equivale a DryRun**. Con ese valor, el SP continúa ejecutando todos los `INSERT`, pero sin una transacción explícita.

Esto implica que una ejecución con:

```sql
@prm_transaccion = 'N'
```

puede dejar información parcialmente insertada si falla una sentencia intermedia.


Primero se debe calcular el nivel de la autorización:

```sql

(
    SELECT nivel = MAX(ISNULL(API.nivel, 0))
    FROM AUTO_PRESTAC_ITEMS API
    WHERE API.sucur = A.sucur
    AND API.auto = A.auto
    AND API.baja_fecha IS NULL
) NIVEL_AUTO
```

Agregar en la lista del `INSERT INTO SOLICITUDES_AUTO`:

```sql
responsable_gestion
```

y en el `SELECT`:

```sql
responsable_gestion =
    CASE
        WHEN NIVEL_AUTO.nivel = 0
            THEN CONVERT(CHAR(15), A.efe_prestad)

        WHEN NIVEL_AUTO.nivel IN (1, 2)
         AND A.esta = 'N'
            THEN A.usuario_nego

        WHEN NIVEL_AUTO.nivel IN (1, 2)
            THEN COALESCE
            (
                A.usuario_superviso,
                A.usuario_autorizo,
                A.usuario
            )

        ELSE A.usuario
    END
```

## Aclaración funcional necesaria

El documento dice:

```text

si no existe usuario_superviso → asignar usuario_superviso
```

La segunda condición asignaría `NULL`, por lo que parece estar invertida.

La lógica técnicamente coherente es:

```text
si existe usuario_superviso → usuario_superviso
si no existe → usuario_autorizo
```

El `COALESCE` anterior implementa esa interpretación y agrega `A.usuario` como respaldo.
