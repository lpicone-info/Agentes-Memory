## Punto técnico importante: SQL Server

En SQL Server no se puede declarar:


```sql

```

## Riesgos principales

### Pérdida silenciosa de información

Un texto de 32.000 caracteres podría guardarse correctamente en `EXPEDIENTES`, pero luego aparecer truncado al:

- Consultar el expediente.
- Abrir la supervisión.
- Generar liquidaciones.
- Exportar información.
- Imprimir reportes.
- Enviar devoluciones.
- Consultar pendientes de débito.
- Ejecutar procesos de importación o reproceso.

### Incompatibilidad de tipos

Cambiar la columna a `VARCHAR(MAX)` obliga a revisar:

- Tablas temporales.
- Variables locales.
- Parámetros de procedimientos.
- Resultsets definidos con `CHAR(255)` o `VARCHAR(2000)`.
- DataWindows PowerBuilder.
- Reportes y objetos de impresión.
- Integraciones que esperen una cadena de longitud fija.

### Visualización

32.000 caracteres no son prácticos para una grilla o un reporte convencional. Se debería definir:

- Campo multilínea con scroll.
- Consulta completa bajo demanda.
- Exportación a archivo.
- Corte visual sin pérdida del contenido almacenado.
- Indicador de longitud del texto.

### Rendimiento y almacenamiento

`VARCHAR(MAX)` puede almacenarse fuera de la fila cuando el contenido es grande. Esto puede impactar:

- Lecturas de expedientes.
- Consultas masivas.
- Ordenamientos.
- Reportes.
- Exportaciones.
- Ancho de los resultsets.

El impacto no necesariamente será crítico para pocos registros, pero sí puede ser relevante si muchas filas contienen textos extensos.

### Auditoría

Los procedimientos registran la actividad en `EXPE_AUDITORIA`, pero no necesariamente guardan el texto anterior y el nuevo. Por ejemplo, `pru_expedientes_debi_moti` registra:

```text

```

Esto significa que, si el motivo se modifica, podría quedar trazabilidad de la acción, pero no necesariamente del contenido histórico completo.

**Ventaja:** conserva el modelo actual.
