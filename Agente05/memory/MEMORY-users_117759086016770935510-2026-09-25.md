### [25/09/2026 13:37:27] Agente

John, el nivel asociado a cada CUPS de una autorización queda registrado en `auto_prestac_items.nivel`. La consulta sería:

```sql
DECLARE @sucur INT = 1
DECLARE @auto BIGINT = 123456

SELECT
    a.sucur,
    a.auto,
    a.fecha,
    api.nomen,
    api.prestac AS cups,
    p.exten_deno AS descripcion_cups,
    api.nivel AS nivel_autorizacion,
    pan.nivel AS nivel_configurado_actual,
    api.esta AS estado_item
FROM autorizaciones a
INNER JOIN auto_prestac_items api
    ON api.sucur = a.sucur
    AND api.auto = a.auto
LEFT JOIN prestaciones p
    ON p.nomen = api.nomen
    AND p.prestac = api.prestac
    AND p.baja_fecha IS NULL
LEFT JOIN prestac_auto_niveles pan
    ON pan.nomen = api.nomen
    AND pan.prestac = api.prestac
    AND pan.baja_fecha IS NULL
WHERE a.sucur = @sucur
AND a.auto = @auto
AND a.baja_fecha IS NULL
AND api.baja_fecha IS NULL
ORDER BY api.nomen, api.prestac
```

- `nivel_autorizacion`: nivel que quedó guardado en el ítem cuando se procesó la autorización.
- `nivel_configurado_actual`: nivel vigente actualmente para ese nomenclador y CUPS.
- La autorización se identifica por la clave compuesta `sucur + auto`.

El uso de `auto_prestac_items.nivel` está evidenciado en [d_auto_lista_prestac.srd:9](/home/desarrollo-ia-05/.openclaw/workspace/svn/csiafas-Coomeva-trunk-exe_presmed-Source20Infomedical/d_auto_lista_prestac.srd:9), y la configuración vigente se obtiene de `prestac_auto_niveles` en [w_clase_auto.srw:608](/home/desarrollo-ia-05/.openclaw/workspace/svn/csiafas-Coomeva-trunk-exe_presmed-Source20Infomedical/w_clase_auto.srw:608).

### [25/09/2026 14:52:15] Agente

John, en Presmed, **auditar un expediente** hace referencia a realizar la **auditoría médica de una cuenta médica presentada por un prestador**.

El objeto principal es:

- **Cabecera:** `expedientes`
- **Ítems/CUPS:** `expe_ordenes`

Un expediente queda pendiente de auditoría cuando:

- fue cargado;
- fue revisado administrativamente;
- tiene cierre administrativo;
- todavía no tiene `audi_fecha`;
- todavía no fue supervisado ni liquidado.

Durante la auditoría se revisan los CUPS incluidos en el expediente, sus cantidades, valores, soportes y posibles débitos. Las autorizaciones pueden utilizarse como antecedente para validar esos CUPS, pero **auditar el expediente no significa auditar directamente la autorización**.

Por lo tanto, si necesitás conocer el nivel de los CUPS durante la auditoría de un expediente, el punto de partida debería ser `expe_ordenes`, vinculando después cada ítem con su autorización y con `auto_prestac_items`, cuando exista esa asociación. La bandeja pendiente de auditoría confirma este flujo en [d_expe_pend_audit.srd:20](/home/desarrollo-ia-05/.openclaw/workspace/svn/csiafas-Coomeva-trunk-exe_presmed-Source20Infomedical/d_expe_pend_audit.srd:20).
