## Consulta de diagnóstico

Esta consulta permite revisar qué proceso corresponde a cada fila histórica:

```sql
SELECT
    SAN.notificacion_id,
    SAN.soli_auto,
    SAN.mail_id,
    SAN.proceso_id,
    SAN.alta_fecha,
    proceso_historico =
        MAX
        (
            CASE
                WHEN SAA.activi LIKE '%proceso_id: 5%' THEN 5
                WHEN SAA.activi LIKE '%proceso_id: 8%' THEN 8
                WHEN SAA.activi LIKE '%proceso_id: 9%' THEN 9
                WHEN SAA.activi LIKE '%proceso_id: 13%' THEN 13
                WHEN SAA.activi LIKE '%proceso_id: 23%' THEN 23
                WHEN SAA.activi LIKE '%proceso_id: 27%' THEN 27
                WHEN SAA.activi LIKE '%proceso_id: 28%' THEN 28
                WHEN SAA.activi LIKE '%proceso_id: 29%' THEN 29
                WHEN SAA.activi LIKE '%proceso_id: 30%' THEN 30
                ELSE NULL
            END
        )
FROM dbo.SOLICITUDES_AUTO_NOTIFICACIONES SAN
LEFT JOIN dbo.SOLICITUDES_AUTO_AUDITORIA SAA
    ON SAA.soli_auto = SAN.soli_auto
    AND SAA.activi LIKE
        '%mail_id: ' + CONVERT(VARCHAR(20), SAN.mail_id) + '%'
WHERE SAN.soli_auto = <SOLICITUD>
AND SAN.baja_fecha IS NULL
GROUP BY
    SAN.notificacion_id,
    SAN.soli_auto,
    SAN.mail_id,
    SAN.proceso_id,
    SAN.alta_fecha
ORDER BY SAN.alta_fecha
```

Esta consulta no modifica datos.

La condición para considerar que ya existe una notificación final debe ser:

# Registros históricos ambiguos

Para los registros donde:

ni:

Tampoco recomiendo eliminar registros históricos.

La opción segura es:

2. Detectarlo como histórico ambiguo.
3. No generar un nuevo correo automáticamente.
4. Registrar una auditoría técnica.
