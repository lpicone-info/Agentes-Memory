Si la regla funcional solamente buscaba impedir:

la implementación actual es demasiado general.

## 2. Depende de la intercalación de la base

En `PruebasCoreINFOMEDICAL` funciona para mayúsculas y minúsculas porque la base es `CI`.

En una base con intercalación sensible a mayúsculas y minúsculas, el correo en minúsculas podría no ser detectado.

Una comparación independiente de la intercalación debería normalizar explícitamente el valor antes de compararlo.

## 3. PowerBuilder pierde el motivo específico

El procedimiento devuelve únicamente:

```text
1  = válido
-1 = inválido
```

PowerBuilder no puede distinguir entre:

- correo sin `@`;
- correo con espacios;
- dominio inválido;
- más de un `@`;
- uso de `sincorreo`.

Todos los casos terminan mostrando el mismo mensaje genérico.

## 4. Es una validación heredada limitada

El procedimiento hace controles manuales de longitud y caracteres. No implementa una validación completa de direcciones de correo.

Por ejemplo, la validación del nombre de usuario permite combinaciones que podrían ser incorrectas, como puntos consecutivos o un punto al inicio/final, dependiendo del caso.

Esto no explica el reporte actual, pero es una limitación técnica del validador compartido.
