## Cómo se determina si un CUPS utiliza IA

Existe la parametrización:

```text
Autorizaciones → Procesamiento IA
```

Esa ventana permite seleccionar por nomenclador qué CUPS participan del procesamiento. La configuración se almacena en:

```text
AUTO_PRESTAC_IA
```

con:

```text
nomen + prestac + procesamiento_ia
```

Durante la generación de una autorización remota, si al menos uno de sus CUPS tiene:

```text
AUTO_PRESTAC_IA.procesamiento_ia = 'S'
```

la autorización queda inicialmente con:

```text
AUTORIZACIONES.estado_procesamiento_ia = 'S'
```

El cambio posterior a `F` o `E` corresponde al proceso de integración con IA/Hismart; no lo realiza el botón.

## Problema adicional en la implementación actual

La lógica actual es frágil por dos motivos:

1. Si existe la carpeta `pbcef`, Presmed la considera válida:
   ```powerscript
   IF DirectoryExists(ls_pbcef_path) THEN
       RETURN TRUE
   END IF
   ```
   No verifica que esté completa, que tenga la versión correcta ni que existan todos los archivos requeridos.

2. La extracción utiliza:
   ```powerscript
   Shell.Application.CopyHere(...)
   ```
   Esa operación puede ser **asíncrona**. Presmed verifica inmediatamente si apareció la carpeta, pero la extracción podría continuar o haber quedado incompleta.

Por eso una carpeta parcial puede ser aceptada como una instalación correcta y el navegador interno posteriormente no inicia.

## Alternativas

### 1. Abrir Hismart en Edge o navegador predeterminado — recomendada a corto plazo

El botón mantendría la consulta actual para recuperar `url_presmed`, pero en lugar de abrir `wp_visor_hismart`, ejecutaría la URL con Windows:

```text
ShellExecute → navegador predeterminado
```

También puede abrirse Edge en modo aplicación:

```text
msedge.exe --app="URL_HISMART"
```

El modo `--app` muestra una ventana similar a un visor, sin pestañas ni barra de navegación convencional.

**Ventajas:**

- elimina completamente `pbcef.zip`;
- no agrega 100 MB a Presmed;
- utiliza Edge/WebView2 ya mantenido en los equipos;
- soporta descargas, certificados e interacción web;
- permite minimizar, maximizar y alternar ventanas.

**Desventaja:** la ventana deja de estar incrustada dentro del MDI de Presmed. Aparece como una ventana externa.

Esta sería mi primera recomendación si Coomeva acepta ajustar ese criterio funcional.

### 2. Mantener el visor incrustado, pero instalar PBCEF como prerrequisito

Si debe permanecer obligatoriamente dentro de Presmed, `pbcef` debería manejarse como un componente de infraestructura:

1. Crear un instalador independiente, MSI o paquete corporativo.
2. Distribuirlo mediante la herramienta de software de Coomeva.
3. Instalarlo una sola vez por equipo.
4. No incluirlo en cada entrega de Presmed.
5. Registrar su versión instalada.
6. Validar integridad mediante SHA-256 o manifiesto de archivos.

La aplicación debería comprobar:

```text
versión esperada
+ archivo principal de CEF
+ subcarpetas requeridas
+ marcador de instalación completa
```

No solamente la existencia de la carpeta.

Para una instalación segura:

```text
pbcef.zip
→ validar hash
→ extraer en pbcef_tmp
→ validar todos los archivos
→ renombrar pbcef_tmp a pbcef
→ crear pbcef.version
```

El renombrado final debe ocurrir únicamente cuando todo esté completo. Así Presmed nunca verá una carpeta parcial como válida.

---

### 3. Reemplazar PBCEF por Microsoft WebView2

Se puede desarrollar un control .NET/COM basado en **Microsoft Edge WebView2** e integrarlo con PowerBuilder.

**Ventajas:**

- mantiene el visor dentro de Presmed;
- el runtime de WebView2 generalmente ya está instalado y administrado con Edge;
- evita distribuir Chromium dentro del aplicativo;
- ofrece soporte moderno de navegación, certificados y descargas.

**Desventajas:**

- requiere un componente wrapper y desarrollo de integración PowerBuilder/.NET;
- debe probarse el ciclo de vida del control, navegación, descarga y cierre;
- es un cambio mayor que abrir el navegador externo.

Es la mejor alternativa estratégica si el requisito de visor embebido es obligatorio.
