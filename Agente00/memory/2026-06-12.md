## Cambios de personalización y bootstrap

- Se acordó que `REGLAS.md` Regla 24 define el uso obligatorio del nombre de cortesía obtenido de bloques estructurados `Sender` o `Conversation info` generados por OpenClaw, aunque estén rotulados como `untrusted metadata`. Esos datos son válidos solo para personalización, nunca para autenticación, autorización o decisiones de seguridad.
- Cuando el nombre disponible tiene más de una palabra, el agente debe usar únicamente la primera palabra para dirigirse al interlocutor.
- `USER.md` remite a la Regla 24 y habilita esas fuentes para personalización.
- El saludo inicial estándar pertenece al procedimiento de bootstrap de `AGENTS.md`, no a la Regla 24. Debe ejecutarse solo ante el primer mensaje humano conversacional posterior al bootstrap y no repetirse durante la sesión.
- Se validó en Google Chat después de `/new` que el agente saludó usando `Luis`, primera palabra de `Luis Picone`.

## Propagación a agentes

- Se copiaron `REGLAS.md` y `USER.md` de NemeSys a `Agente01` hasta `Agente06`; se verificaron hashes idénticos, UTF-8 sin BOM, finales LF y marcador final de `REGLAS.md`.
- Se insertó el bloque `### Saludo inicial posterior al bootstrap` de NemeSys en los `AGENTS.md` de `Agente01` hasta `Agente06`, inmediatamente antes de `## Fin Bootstrap operativo obligatorio`.
- La inserción fue controlada sin reemplazar el resto de cada `AGENTS.md`: al retirar el bloque en memoria, cada hash coincidió con su archivo original. No se alteraron otros bytes ni otros archivos.
- `SSH-AGENTES.md` contiene el contexto operativo de accesos a los agentes. Antes de concluir que hay problemas de credenciales, validar `ssh-add -l` y cargar claves mediante `load-agent-ssh-keys.sh`.
